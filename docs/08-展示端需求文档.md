# 07 · 展示端需求文档（面向主播 · 移动端优先）

> 定位：把现有的对外展示页（`/s/:planId`、`/st`）升级为**主播日常自己看数据**的轻量页面。
> 使用场景是主播在手机上打开链接/收藏，随时看自己的音浪、直播时长和分组。
> 本期只定需求，不写代码。视觉与降级机制沿用现有展示页实现（`apps/web/src/components/ShareView.tsx`、`styles/share.css`）。
>
> **实现状态（2026-10-06）**：展示页落在 `rust/crates/pk-server/src/st_page.html`，入口
> `/1`（男团）、`/0`（女团），`/st/m`、`/st/f` 为别名；页签为**数据 / 分组**两个——
> 「我的」页签已按运营要求下线（`/verify`、`/my`、`/my/series` 后端接口保留未挂 UI）。
> 与本文的差异：①字段显隐分两层——后台开关（`/api/admin/public/settings`）决定数据是否
> 下发，读者可在页内「显示哪些字段」面板里再挑自己要看的列（存浏览器本地，只影响自己）；
> ②每日榜包含全团在册主播，当天无采集记录的标「未开播」，可在字段面板里隐藏；
> ③**默认日期为「当天 - 1」**（数据每晚 24 点后补前一天），该日无数据时自动回退到库里
> 最新一天；月/年口径的默认周期同样以昨天为参照日。

## 1. 目标用户

| 角色 | 说明 |
| --- | --- |
| **主播（主用户）** | 在管主播，手机上看自己的每日/每月/年度音浪与时长、看自己第几组几点开赛 |
| **粉丝/观众（顺带覆盖）** | 同一个链接，看榜单和分组，不做单独设计 |

**全站登录门（2026-10-10 起）**：展示端所有接口都要登录态，没有注册入口——账号由运营在
管理端手动设置（「我的」页面账号 / 右键主播），登录 = **手机号或姓名 + 密码**（密码 4~20 位
字母或数字，一个姓名一个密码，一个手机号只绑一个姓名）。本团台账里有同名主播 → 打开个人页；
台账里没有同名主播但账号带 `is_admin=1`（**管理员观看账号**）→ 也放行，`personId=0`，
榜单/分组/族谱照常看，「我的」个人数据为空。

**内置管理员观看账号通过 `BUILTIN_MY_ACCOUNTS` 环境变量注入，默认不创建**（2026-10-10
安全修订）：不在代码/文档里内置任何明文口令；需要时由部署方通过环境变量配置
（账号=密码，`is_admin=1`，男女团链接都能登），未配置则启动不创建内置账号。
已有同名账号只补 `is_admin`，**不覆盖运营自己改过的密码**（密码被别的姓名占用时
跳过并告警）。口令属敏感信息，任何文档不得写明文。

> 待确认：环境变量注入的具体实现（读取 `BUILTIN_MY_ACCOUNTS`、默认不建）由 Rust 侧
> 改造，本节先按目标口径描述；在代码合入前，现行为仍是 `store::BUILTIN_MY_ACCOUNTS`
> 常量内置。

**男团和女团是两个独立链接**：`/st/m`（男团）、`/st/f`（女团）——链接本身即团别，页面内不提供团别切换。运营把两个链接分别发到男团群和女团群，主播只看到自己团的数据。

## 2. 核心使用场景

1. **下播看数据**：主播从自己团的链接打开页面，看今天音浪多少、播了多长时间、排第几、比昨天涨了还是跌了。
2. **月初/年初看累计**：切到「本月 / 今年」口径，看自己这段时间的总音浪和总时长、团内名次。
3. **赛前看分组**：分组方案上架后，主播打开页面看自己第几组、几点开赛、同组有谁。
4. **粉丝围观**：粉丝通过群里链接看本团榜单和分组，顺带找到自家主播的数据。

## 4. 每个页面的模块结构

### 4.1 数据榜（首页 `/st/m`、`/st/f`）

| 模块 | 需求说明 |
| --- | --- |
| 团别归属 | **链接即团别**：页面内所有榜单、名次、图表只含本团主播，不跨团混排、无团别切换控件 |

沿用现有三视图中的分组视图，本期增强：

| 模块 | 需求说明 |

### 4.3 个人数据（「我的」tab）

| 模块 | 需求说明 |
| --- | --- |
| 身份验证 | 首次进入「我的」需**输入自己的抖音号**验证身份：匹配到主播档案即进入个人页，`localStorage` 记住已验证身份（按链接团别分别记住），之后免输入；支持退出登录 / 换号（页内底部小字入口）。抖音号不存在时提示「没有找到这个抖音号，请核对后重试」；**抖音号存在但团别与当前链接不符时，提示「该抖音号不属于本团」**，两种失败都不泄露任何名单信息 |
| 数据卡 | 当前口径（日/月/年）的**音浪、直播时长**两大数字卡 + **团内**当前名次（同时显示全场名次小字） |
| 趋势图 | 近 7/30 天音浪曲线（每日口径）；月口径显示逐月累计；年口径显示逐月分布 |
| 目标对照（可选） | 若后台设了日目标，显示达成进度条；没设则整个模块隐藏 |
| 昨日/上月对照 | 日口径显示较昨日增减；月口径显示较上月同期增减 |

> 安全口径：抖音号验证接口只返回「匹配成功 / 失败」，**不返回主播名单、不返回抖音号字段本身**；展示页其余公开接口同样不下发抖音号，防止遍历撞库。

### 4.5 微信推送（「我的」页，2026-10-09 上线）

定位：**个人订阅**——每个主播在自己页面设置要追谁、要不要收日报，数据一入库由微信机器人私聊推给他。
和后台「机器人」页（管理员命令）是两套东西：这里的推送请求永远来自普通主播。

| 模块 | 需求说明 |
| --- | --- |
| 绑定（2026-10-10 改手机号） | 「我的」页出一张二维码（后台「机器人」页上传的**机器人微信名片码**）。用户扫码加机器人 → **把自己的手机号发给机器人** → 机器人按手机号把这条微信私聊会话绑到该账号，并回复「绑定成功」。手机号必须在后台「我的」页面账号里登记过（一个手机号只绑一个姓名），页面只回显**脱敏**手机号（`138****5678`）。没登记手机号的人走兜底：页面出 **6 位一次性绑定码**（30 分钟有效，码表剔除 0/O/1/I），发给机器人同样能绑。机器人里回复「解绑」可断开；页面里也有「解除绑定」 |
| 追分提醒 | 每人最多 **5 个**目标，一律比**本月累计**：① 追某个人（超过 = 追上）② 自定义本月音浪目标（前端填「万」）③ **追名次**（本月累计排进团内第 N 名，2026-10-10 新增）。数据入库后合成**一条**消息推送：「🚀 已追上 X / ⚠️ X 又差回来了 / · 距 X 还差 N」。追名次但本月没播 →「你还没进本月榜 · 本月还没开播」 |
| 每日报告 | 当天音浪榜 TOP10 + 我的名次与音浪（未开播则显示「今天还没开播」）。**同一业务日只推一次**（`last_report_date` 去重）：运营补数据重排队列时不再重复推同一份日报 |
| 延迟触发（2026-10-10） | 数据入库**不立刻推**，先排队到 **30 分钟后**（`PUSH_DELAY_MINUTES`，0 = 入库即推），由 `push::scheduler_loop`（60 秒一轮）到点统一推。理由：运营一轮导入常分好几个文件（男女团 / 一人多号），立刻推会把半成品榜单推给用户。同一 (团, 业务日) 只排一队（`push_jobs` 唯一键），重复导入只刷新不叠加；不分团导入时男女团各排一队 |
| 开关未开不推 | 两个开关（追分提醒 / 每日报告）都关着的人完全不推 —— `push_bindings_for_team` 只取至少开了一个开关的绑定 |
| 数值口径 | 推送里所有音浪一律按**万**（如 `11.4 万`）；追分对比用**本月累计**而非历史累计；追名次比的是**名次**而不是音浪 |
| 搜索 | 设置追谁时支持按名字搜，**只能搜到本团在册主播**（男团链接搜不到女团的人，服务端兜底校验），且不能追自己 |
| 失败兜底 | 微信 iLink 只有「被动回复」形态，主动推送依赖最后一次私聊留下的 `context_token`；推送失败会把原因写回绑定记录并在「我的」页提示「让对方给机器人发一条消息后再试」 |

后台侧：「机器人」页新增两块：
- 「微信推送 · 加好友二维码」卡片（上传/更换/清除，压到最长边 720 的白底 PNG）；
- 「推送队列」表格：团别 / 业务日 / 计划推送时间 / 状态（排队中·推送中·已推送·失败）+ **立即推送**
  按钮（不等到点，`POST /api/admin/push/run?team=&bizDate=`）。

要让推送真正工作，服务端必须配 `BOT_WECHAT_ADMINS`（微信渠道实例的前提）并完成扫码登录。

接口（都要「我的」登录态）：`GET /my/push`、`POST /my/push/code|settings|unbind|targets|targets/delete`、`GET /my/push/search|qr`。
数据表：`push_bindings`（绑定 + 开关）、`my_targets`（目标 + 追上状态）、`wx_sessions`（私聊上下文），见 `migrations/004_push.sql`。

### 4.6 手机号注册 + 绑定主播（2026-10-10 实现，默认**关闭**）

用户口径（2026-10-10 原文）：「添加注册功能，注册功能同时调用 [WorkBuddy 用量看板
`?tab=gateway`] 里的添加账号 oauth 实现手机号登录，然后验证码数字就是密码，手机号就是账号。
然后提醒用户进行绑定姓名，绑定之后不支持解绑。」后续澄清：绑的是**主播**，用户自己不能解绑，
**管理员可以改绑**；并且「**注册先不开**」——功能做好但默认关闭，想开时在后台一键打开。

| 模块 | 需求说明 |
| --- | --- |
| 开关（默认关） | 后台「机器人 → 公开站点设置 → 开放手机号注册」（`myRegister`）。**关**：登录门不显示「注册」页签，`/api/public/my/register*` 一律 400「注册功能暂未开放」；登录、绑定、我的页完全不受影响 |
| 入口 | 展示端登录门新增「注册」页签（与「登录」并列）。**手机号就是账号，短信验证码数字就是密码**——不需要自建短信通道 |
| 第一步：加账号池 | 页签里点「获取授权链接（国内版 / 国际版）」→ 服务端向 WorkBuddy 网关申请授权链接（`POST /accounts/login/start`）→ 用户在打开的授权页用**手机号**登录（收到短信验证码）→ 页面每 2.5 秒轮询 `/api/public/my/register/oauth/poll` 自动检测入池，成功后标「✓ 已加入账号池」。也可显式「跳过这一步（不加入账号池）」 |
| 第二步：完成注册 | 填手机号 + 刚才收到的验证码 → `POST /api/public/my/register` → 建号成功直接登录（`bound=false, needBind=true`）。手机号已存在、验证码撞上别人密码（密码 1:1 唯一键）都会给出明确文案 |
| 提醒绑定 | 注册后顶部出现「你还没有绑定主播姓名」提醒条（水印显示「未绑定主播」），「我的」页此时**只有一张绑定卡**：搜主播（全台账，注册账号还没有团别）→ 选中确认 → `POST /api/public/my/bind`。绑定成功后账号名改写成主播姓名、换发 token；主播在另一个团时自动切到该团网址 |
| 不可解绑 | 绑定接口只接受 `bound=0` 的账号，已绑定的再调一律拒（「该账号已绑定主播，不能自行更改」）。**改绑只有管理员能做**：后台「我的页面账号」里点「改绑」选新主播（`POST /api/admin/my-accounts/{name}/bind`） |
| 安全 | 面板密码只存在服务端环境变量（`WORKBUDDY_PANEL_PASSWORD`），浏览器只拿到 `state` 与 `authUrl`；注册接口独立限流（每 IP 每分钟 12 次），登录仍是 5 次 |

接口：`GET /api/public/my/register/config`、`POST /api/public/my/register/oauth/start|cancel`、
`GET /api/public/my/register/oauth/poll`、`POST /api/public/my/register`、
`GET /api/public/my/bind/search`、`POST /api/public/my/bind`、
`POST /api/admin/my-accounts/{name}/bind`。
数据表：`my_accounts` 增列 `bound / bound_at / source / wb_state`（`migrations/008_my_register.sql`）。
自检：`node scripts/uicheck-register.mjs [BASE] [管理员口令]`（关着时断言「页签藏起来 + 接口被拒」，
打开后跑完整注册 → 绑定 → 二次绑定被拒 → 手机号回登录，跑完自动删测试账号）。

### 4.7 访客地域门禁（2026-10-10）

展示端只对**河南 / 安徽**访客开放，判定全在后端（不做 Cloudflare 规则；数据源、投票与
fail-closed 口径见 docs/07 §3.4.3）。访客视角的行为：

| 场景 | 表现 |
| --- | --- |
| 非河南 / 安徽打开展示页 | HTML 页面本身不拦；页面加载后第一个数据接口返回 403，前端**整页替换**为「当前地区暂不支持访问」（副文案「本展示页仅对河南 / 安徽开放」），不是 404、不是白屏 |
| 登录 / 注册 / 「我的」 | 一律同样受限：`/api/public/*` 全挂同一中间件，外省在登录门里的提交也拿 403；`verify` 的外省尝试会记一条登录日志（带账号与失败），后台可见 |
| 面板数据接口 403 | **不视为登录失效**：不清 token、不弹登录门、不显示「请先登录」；401 才走登录失效流程 |
| 缓存与兜底 | 403 只由后端地区判定（含数据源全失败的 fail-closed）触发；归属结果缓存 7 天；内网 IP 默认拒绝且不发外部查询；仅当本地 `IP_GATE_DISABLED=1` 时整体不拦；门禁数据源默认 3 个（`IP_GATE_SOURCES` 可配，见 docs/07 §3.4.3） |

被拦访问与外省登录尝试可在后台「访客日志」（`/admin/visits`）查看。

### 4.4 后台对应的显示开关（设置 `/settings` → 展示设置）

所有展示数据均为**后端级开关：关闭后接口不下发该类数据**（不是前端藏），展示端对应模块整体消失：

| 开关 | 控制范围 |
| --- | --- |
| 每日数据显示 | 榜单每日 tab + 个人每日明细 |
| 每月数据显示 | 月 tab + 个人月累计 |
| 每年数据显示 | 年 tab + 个人年分布 |
| 直播时长显示 | 三个口径里的时长列与个人时长卡（关掉后只剩音浪） |
| 涨跌/对照显示 | 涨跌箭头与同比增减 |
| **男团链接显隐** | 控制男团链接 `/st/m` 整体可见性：关闭后访问该链接一律返回「暂未公布」占位（后端不下发男团数据）；后台提供复制男团链接入口 |
| **女团链接显隐** | 同上，控制 `/st/f`，两链接相互独立、互不影响 |
| **每日报告页显隐**（2026-10-10） | `dataEnabled`：关掉后「每日报告」主导航整体消失，`/daily` 接口按关闭处理 |
| **分组页显隐**（2026-10-10） | `groupEnabled`：关掉后「分组」主导航消失，`/api/public/plans` 不下发任何方案 |

## 5. 视觉风格关键词

沿用现有展示端的苹果风 token，移动端为主场景：

- **深色头部 + 浅色正文**：masthead 顶光（≤6%）+ 颗粒，正文白底发丝线列表；
- **大数字**：音浪/时长用 `.figure` 等宽负字距大字排版，一屏一眼看清；
- **发丝分隔名单行**：行 hover 点亮在移动端表现为按压态（active 背景色）；
- **胶囊赛程条**：横滑 + 右侧渐隐，组时段一眼扫完；
- **单一品牌色**：靛蓝只用在 tab 指示、我的行高亮、进度条；涨跌用语义色（涨红跌绿）；
- **系统字体栈**，零外部请求，弱网可用。

## 6. 交互要点

- 单手操作：核心操作都落在屏幕下半 2/3；tab 与日期条吸顶。
- 切口径（日/月/年）不整页刷新，列表原地过渡（150ms 淡入）。
- 日期条横滑 + 点击选择；月/年用左右箭头切换上一期/下一期。
- 「我的」身份选择一次后免打扰；换人入口藏在「我的」页底部小字。
- 分组页在比赛日自动静默刷新；榜单每分钟后台刷新不动 UI（客户端加 ±10s 随机抖动，避免所有页面整点同步请求形成服务端尖峰）。
- 长按榜单行可复制「名字 + 音浪」文本（方便主播转发群里）。

## 7. 空状态

| 位置 | 表现 |
| --- | --- |
| 无任何数据 | 「暂未公布数据」占位页 + 公会联系方式文案，不是 404 |
| 某口径被后台关闭 | 对应 tab 整体消失（只剩开启的口径）；全部关闭时只剩分组 tab |
| 所选日期无数据 | 「该日期没有采集记录」+ 跳回最新日期按钮 |
| 团链接被关闭 | 访问该团链接一律「暂未公布」占位页（不是 404），另一个团链接不受影响 |
| 未上架方案 | 「分组暂未公布」占位 |
| 名单被隐藏 | 只显示赛程时段条，不出现空洞名单区 |
| 未验证身份进「我的」 | 抖音号输入页（一次输入框 + 确认按钮，页内引导，不弹窗） |
| 抖音号未匹配 | 「没有找到这个抖音号，请核对后重试」+ 重试输入，不给任何候选名单 |
| 抖音号团别不符 | 「该抖音号不属于本团」+ 重试输入 |
| 趋势数据不足 | 「暂无足够历史数据」文案占位，不画空图 |

## 8. 加载状态

- 首屏骨架：头部 + 前三行骨架屏，弱网也不白屏。
- 切日期/口径时旧列表保持 + 降透明度，新数据到达后替换，不闪空白。
- 每分钟静默刷新不动 UI；失败不打扰用户，连续失败才在头部出现「数据可能不是最新」灰条。
- 数据库不可用：自动降级用方案快照 + `stale`「数据延迟」徽标，页面照常可看。
