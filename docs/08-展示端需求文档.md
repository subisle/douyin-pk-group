## 1. 目标用户

| 角色 | 说明 |
| --- | --- |
| **主播（主用户）** | 在管主播，手机上看自己的每日/每月/年度音浪与时长、看自己第几组几点开赛 |
| **粉丝/观众（顺带覆盖）** | 同一个链接，看榜单和分组，不做单独设计 |

**全站登录门（2026-10-10 起）**：展示端所有接口都要登录态，**没有注册入口**——账号由运营在
管理端手动设置（「我的」页面账号 / 右键主播；**2026-10-14 起这是唯一开号路径**，自助注册已彻底移除，见 4.6），
登录 = **手机号或姓名 + 密码**（密码 4~20 位
字母或数字，一个姓名一个密码，一个手机号只绑一个姓名）。本团台账里有同名主播 → 打开个人页；
台账里没有同名主播但账号带 `is_admin=1`（**管理员观看账号**）→ 也放行，`personId=0`，
榜单/分组/族谱照常看，「我的」个人数据为空。

**内置管理员观看账号通过 `BUILTIN_MY_ACCOUNTS` 环境变量注入，默认不创建**（2026-10-10
安全修订）：不在代码/文档里内置任何明文口令；需要时由部署方通过环境变量配置
（账号=密码，`is_admin=1`，男女团链接都能登），未配置则启动不创建内置账号。
已有同名账号只补 `is_admin`，**不覆盖运营自己改过的密码**（密码被别的姓名占用时
跳过并告警）。口令属敏感信息，任何文档不得写明文。

> **已实现（2026-10-11 核对）**：`store::builtin_my_accounts_from_env()` 读
> `BUILTIN_MY_ACCOUNTS="name:pass,name2:pass2"`（密码缺省 = 账号本身；未配置时一个都不建，
> 旧硬编码 `shuai/shuai` 已移除）。库里 `my_accounts.pass` 存 **argon2id PHC 哈希**
> （迁移 `010_my_pass_hash`），校验走 `auth::verify_password`（PHC 解析失败按不匹配处理，
> 兼容极老明文行）。

**男团和女团是两个独立链接**：`/st/m`（男团）、`/st/f`（女团）——链接本身即团别，页面内不提供团别切换。运营把两个链接分别发到男团群和女团群，主播只看到自己团的数据。

## 2. 核心使用场景

1. **下播看数据**：主播从自己团的链接打开页面，看今天音浪多少、播了多长时间、排第几、比昨天涨了还是跌了。
2. **月初/年初看累计**：切到「本月 / 今年」口径，看自己这段时间的总音浪和总时长、团内名次。
3. **赛前看分组**：分组方案上架后，主播打开页面看自己第几组、几点开赛、同组有谁。
4. **粉丝围观**：粉丝通过群里链接看本团榜单和分组，顺带找到自家主播的数据。

### 4.5 微信推送（「我的」页，2026-10-09 上线）

定位：**个人订阅**——每个主播在自己页面设置要追谁、要不要收日报，数据一入库由微信机器人私聊推给他。
和后台「机器人」页（管理员命令）是两套东西：这里的推送请求永远来自普通主播。

| 模块 | 需求说明 |
| --- | --- |
| 绑定（2026-10-11 改为用户自助扫码，多账号） | 「我的」页推送设置里点「获取二维码」→ 用户用微信扫描并确认。服务端按官方 `Tencent/openclaw-weixin` 协议（`POST /ilink/bot/get_bot_qrcode?bot_type=3` + `GET /ilink/bot/get_qrcode_status`）拿到该账号的 `bot_token / ilink_bot_id / ilink_user_id / baseurl`，落 `wx_push_accounts` 并为该账号单独跑一条 `getupdates` 长轮询。扫码确认后用户在微信里给机器人发任意一条消息，留下 `context_token`，推送即激活。之后推送用该账号自己的 token 发送（多账号并存）。旧手机号 + 6 位绑定码流程保留为兼容兜底 |
| 追分提醒 | 口径「**分数是分数，追人是追人**」（2026-10-15）：**追人 ≤5 条、目标分数 ≤5 条各自独立计数**（`push::MAX_TARGETS=5` 复用为**单类**上限），一律比**本月累计**：① 追某个人（超过 = 追上；支持本团搜索 + **多选批量添加**，`POST .../my/push/targets/batch`）② 自定义本月音浪目标（前端填「万」）③ **追名次**（本月累计排进团内第 N 名，2026-10-10 新增；2026-10-15 起前端不再提供新增入口，只保留可列出 / 可删除）④ **追人 + 自定义分数**（2026-10-12 新增：选人后可选填「目标分（万）」，后端存 `targetWan * 10000`，展示名写进 `target_name`；未填保持旧口径「超过他本人」）。数据入库后合成**一条**消息推送：「🚀 已追上 X / ⚠️ X 又差回来了 / · 距 X 还差 N」。追名次但本月没播 →「你还没进本月榜 · 本月还没开播」。追人目标带自定义分时，推送按该固定分算差距（如「距『张三 · 50 万』还差 30 万（你 20 万）」），不受对手实际音浪波动影响。详见 docs/14 §8 |
| 每日报告 | 当天音浪榜 TOP10 + 我的名次与音浪（未开播则显示「今天还没开播」）。**2026-10-12 起：本人有 ≥2 个抖音号时追加「我的抖音号」明细段**（每个号一行「日 / 月 / 年」，按当日音浪降序，超过 3 个号折叠为「…等 N 个号」；只有 1 个号时不加，避免重复）。取数失败退回不带明细的原文案，不影响推送本身。详见 docs/14 §4 |**同一业务日只推一次**（`last_report_date` 去重）：运营补数据重排队列时不再重复推同一份日报 |
| 延迟触发（2026-10-10） | 数据入库**不立刻推**，先排队到 **30 分钟后**（`PUSH_DELAY_MINUTES`，0 = 入库即推），由 `push::scheduler_loop`（60 秒一轮）到点统一推。理由：运营一轮导入常分好几个文件（男女团 / 一人多号），立刻推会把半成品榜单推给用户。同一 (团, 业务日) 只排一队（`push_jobs` 唯一键），重复导入只刷新不叠加；不分团导入时男女团各排一队 |
| 开关未开不推 | 两个开关（追分提醒 / 每日报告）都关着的人完全不推 —— `push_bindings_for_team` 只取至少开了一个开关的绑定 |
| 数值口径 | 推送里所有音浪一律按**万**（如 `11.4 万`）；追分对比用**本月累计**而非历史累计；追名次比的是**名次**而不是音浪 |
| 搜索 | 设置追谁时支持按名字搜，**只能搜到本团在册主播**（男团链接搜不到女团的人，服务端兜底校验），且不能追自己 |
| 失败兜底 | 微信 iLink 只有「被动回复」形态，主动推送依赖最后一次私聊留下的 `context_token`；推送失败会把原因写回绑定记录并在「我的」页提示「让对方给机器人发一条消息后再试」 |

后台侧：「机器人」页新增两块：
- 「微信推送 · 加好友二维码」卡片（上传/更换/清除，压到最长边 720 的白底 PNG）；
- 「推送队列」表格：团别 / 业务日 / 计划推送时间 / 状态（排队中·推送中·已推送·失败）+ **立即推送**
  按钮（不等到点，`POST /api/admin/push/run?team=&bizDate=`）。

要让推送真正工作，服务端必须配 `BOT_WECHAT_ADMINS`（微信渠道实例的前提）并完成扫码登录。

**「消息设置」子页（2026-10-15）**：原「我的」页列表项「推送机器人服务」改名为**「消息设置」**
（副标题：微信机器人对接与推送开关），子页 key `wechat` → `/my/wechat`；**保留 `push` 作为别名**
（`/my/push` 旧链接仍打开同一页，不 404、不落回列表）。页内三段：
① 微信对接（扫码绑定 `POST /my/push/wechat/start` + `/poll`、绑定码 `POST /my/push/code`、
解绑 `POST /my/push/unbind`、绑定状态三态 `channelConfigured` / `scanBound` / `bound`）；
② 推送开关（追分提醒 `notifyTarget` / 每日报告 `dailyReport` / 师门日报 `lineageReport`——
师门日报仅在**名下有直系徒弟**（`hasDisciples`）时显示；保存仍走 `POST /my/push/settings`，
`lineageReport` 缺省 = 不改动现值）；③ 追分设置入口（一行，跳 `/my/chase` 子页）。
管理员观看账号（`admin`）与未绑定态沿用既有置灰 / 提示口径，不得回归成可点。

接口（都要「我的」登录态）：`GET /my/push`（响应含 `counts{person,value,rank}`）、
`POST /my/push/code|settings|unbind|targets|targets/delete|targets/batch|wechat/start|wechat/poll`、
`GET /my/push/search|qr`。
数据表：`push_bindings`（绑定 + 开关）、`my_targets`（目标 + 追上状态）、`wx_sessions`（私聊上下文），见 `migrations/004_push.sql`。

### 4.7 访客地域门禁（2026-10-10）

## 5. 视觉风格关键词

沿用现有展示端的苹果风 token，移动端为主场景：

- **深色头部 + 浅色正文**：masthead 顶光（≤6%）+ 颗粒，正文白底发丝线列表；

## 6. 交互要点

- 单手操作：核心操作都落在屏幕下半 2/3；tab 与日期条吸顶。
- 切口径（日/月/年）不整页刷新，列表原地过渡（150ms 淡入）。
- 日期条横滑 + 点击选择；月/年用左右箭头切换上一期/下一期。
- 「我的」身份选择一次后免打扰；换人入口藏在「我的」页底部小字。
- 分组页在比赛日自动静默刷新；榜单每分钟后台刷新不动 UI（客户端加 ±10s 随机抖动，避免所有页面整点同步请求形成服务端尖峰）。
- 长按榜单行可复制「名字 + 音浪」文本（方便主播转发群里）。
