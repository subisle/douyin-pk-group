# 09 · 机器人口令与权限结构

> 定位：定义 QQ / 微信群机器人（`pk-server` 的 `bot/` 模块）的**角色分层、命令口径与推送开关语义**。
> 2026-10-10 起机器人从「仅管理员」改为三层：未绑定会话静默 → 已绑定主播 5 条用户命令 → 管理员全部命令。
>
> **实现状态**：命令的单一事实来源是代码注册表 `rust/crates/pk-server/src/bot/commands.rs`
> （2026-10-10 引入，分层随该改动落地；合入前线上仍是「仅管理员」）。本文与代码冲突时以代码为准，
> 并回头修订本文。**提权口令不落明文**（见代码常量 `WECHAT_ADMIN_CODE`；沿用 docs/08 的敏感信息要求）。

## 1. 角色模型与判定优先级

### 1.1 三个角色

| 角色 | 判定条件 | 可用范围 |
| --- | --- | --- |
| **未绑定访客** | 微信私聊，且 `push_bindings.conversation_id` 未命中 | 除绑定 / 解绑流程必须的回复外**完全静默**：帮助、未知命令、管理员命令、附件一律不回复，只在日志与 `bot_sessions` 留痕 |
| **普通用户** | 微信私聊，且 `push_bindings.conversation_id` 命中（已完成推送绑定的主播，见 §5） | 5 条用户命令（§3）；发管理员命令 → 拒绝并提示发「帮助」；发附件 → 提示导入是管理员功能 |
| **管理员** | ① QQ 全部会话（群聊 / 私聊，**免白名单**）② 微信白名单 `BOT_WECHAT_ADMINS` ③ `bot_sessions.is_admin`（内置提权口令 / 管理端会话列表勾选） | 用户 5 条之外的全部管理员命令（§4） |

### 1.2 渠道差异

| 渠道 / 会话 | 行为 |
| --- | --- |
| QQ（全部会话） | 一律按管理员处理，没有绑定概念 |
| 微信私聊 | 绑定 / 解绑 + 用户 5 条命令 + 提权口令 + 白名单；未绑定静默 |
| 微信群 | 不做绑定（绑定只对私聊生效）；非白名单群消息静默；白名单命中的群 = 管理员 |
| 展示端网页 | 不属于本文；绑定码与推送开关在「我的」页生成 / 保存（见 docs/08 §4.5） |

> 1.0.1：微信 iLink 传输层全链路对齐 Tencent/openclaw-weixin 协议（扫码状态机、
> 验证码、baseurl 切换、-14 暂停重试）。**命令、角色、判定顺序不变**——协议细节见 docs/07 §3.5.1。

### 1.3 单条消息判定顺序（每次入站固定执行）

1. **会话登记**：所有渠道（含非管理员）写入 `bot_sessions`，管理端会话列表据此展示、勾选管理员；
2. **限流**：10 条/分钟/会话（`BOT_RATE_LIMIT`，对所有渠道、绑定尝试与管理员都生效），超限直接回
   「消息太频繁了，稍后再试（限流 10 条/分钟）」；
3. **微信私聊绑定 / 解绑**（§5：**主路径是用户自助扫码**，本节是兼容兜底）：命中即返回，不再往下走；
4. **微信内置提权口令**：私聊整条消息精确命中口令 → `bot_sessions.is_admin=1`，回「已成为管理员」；
5. **管理员判定**：QQ 全部会话 ∥ `BOT_WECHAT_ADMINS` ∥ `bot_sessions.is_admin`；
6. **非管理员分流**：命中 `push_bindings` → 普通用户命令集；未命中 → 静默（不回复）。

## 2. 权限矩阵（命令 × 角色）

| 命令 | 未绑定微信私聊 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| `帮助`（help） | 静默 | ✅ 按角色显示 5 条 | ✅ 显示全部 |
| `每日报告`（daily） | 静默 | ✅ | ✅ |
| `个人报告`（me / my） | 静默 | ✅ | ✅ |
| `暂停接收每日推送`（暂停推送 / pause） | 静默 | ✅ | ✅ |
| `开启接收每日推送`（开启推送 / resume） | 静默 | ✅ | ✅ |
| `绑定 手机号 绑定码` / `解绑` 等绑定消息 | ✅（兼容兜底入口） | ✅（按绑定流程处理） | ✅ |
| `状态` / `分组` / `总榜` / `排行 [N]` / `查询 <主播名>` | 静默 | ❌ 拒绝并提示发「帮助」 | ✅ |
| `导出 …` / `日报 …` / `缺数据` | 静默 | ❌ 拒绝并提示发「帮助」 | ✅ |
| `导入 …` + 数据行 / 纯日期黏住 / CSV 附件 | 静默 | ❌ 拒绝；附件 → 提示导入是管理员功能 | ✅ |

> QQ 会话即管理员，不适用左侧两列；「普通用户」列只可能是微信私聊。
> 普通用户发管理员命令被拒时统一回显规范命令名（如「『状态』是管理员命令，你没有权限」）
> 并引导发「帮助」；未知命令同样只提示发「帮助」。

## 3. 普通用户 5 条命令

### 3.1 触发词与别名（命令名与代码注册表一致）

| 命令 | 触发词 | 别名 |
| --- | --- | --- |
| 每日报告 | `每日报告` | `daily` |
| 个人报告 | `个人报告` | `me`、`my` |
| 暂停接收每日推送 | `暂停接收每日推送` | `暂停推送`、`pause` |
| 开启接收每日推送 | `开启接收每日推送` | `开启推送`、`resume` |
| 帮助 | `帮助` | `help` |

### 3.2 返回内容、数据口径与边界

| 命令 | 返回内容 | 数据口径 | 失败 / 边界提示 |
| --- | --- | --- | --- |
| 每日报告 | 当天音浪榜 TOP10 + 我的名次 | 复用每日推送同一套文案与排序（`push.rs`）；手工查询不受「同一业务日只推一次」的去重限制（去重只管主动推送） | 当天无数据 → 明确提示；本人未开播 → 名次行按未开播展示；数据库不可用 → 「稍后再试」类文案 |
| 个人报告 | 我的今日名次 / 音浪、本月累计与名次、追分目标进度 | 月榜按**本月累计**；追分进度与推送同源（`my_targets`，最多 5 个目标，本月累计口径），追名次比的是名次不是音浪 | 本月还没播 → 按未开播文案（追名次场景：「你还没进本月榜 · 本月还没开播」）；没设目标 → 引导去展示端「我的」页「推送设置」添加 |
| 暂停接收每日推送 | 关闭后的确认回执 | **只关** `push_bindings.daily_report`；`notify_target`（追分提醒）不受影响 | 重复暂停 → 幂等回执（当前已是关闭）；未绑定会话不可达（静默） |
| 开启接收每日推送 | 打开后的确认回执 | **只开** `push_bindings.daily_report`；与展示端「我的」页开关写同一字段 | 重复开启 → 幂等回执；未绑定会话不可达（静默） |
| 帮助 | 按角色显示可用命令 | 普通用户：上表 5 条；管理员：全部命令（§4） | 未绑定会话静默（连帮助也不回） |

## 4. 管理员命令表（沿用现状）

| 命令 | 功能简述 |
| --- | --- |
| `状态` | 数据新鲜度、最新业务日、有效日期数、在册主播数、写库连接状态 |
| `分组` | 当前已上架分组方案（分组、时段、名单口径） |
| `总榜` | 累计音浪榜 |
| `排行 [N]` | 近 N 日音浪榜，默认 10（取值收在 1~100） |
| `查询 <主播名>` | 查某人数据（走姓名归一 / 别名匹配） |
| `导出 今日\|YYYY-MM-DD\|总榜` | 导出指定口径，回 CSV 文本 |
| `日报 [男团\|女团] [日期]` | 指定团别 / 日期的日报文案 |
| `缺数据` | 当日无数据 / 未开播清单 |
| `导入 [男团\|女团] [日期]` + 数据行 | 文本导入；只有需要按团校验时才带团别；与 HTTP 端同一套 `commit_import`（幂等 merge） |
| 纯日期黏住（如发「10.1」） | 先记下业务日期，之后发的 CSV 都按它入库；再发一个日期可改 |
| 直接发 CSV 附件 | 不分男女团，团别按主播档案逐行归属；同一天重复导、值相同不覆盖。含月度时长文件（文件名带月份） |

## 5. 绑定 / 解绑流程

### 5.1 主路径：用户自助扫码（2026-10-11 起，多账号）

每个展示端账号在「我的」页**自己扫一个 iLink 账号**，凭证（账号级 `bot_token`）落
`wx_push_accounts`，服务端为该账号**单独跑一条 `getupdates` 长轮询**，推送用该账号自己的
token 发出 —— 不依赖管理员全局机器人，账号之间互不影响。

1. 展示端「我的」页 →「推送设置」→ 点「获取二维码」；
2. 用户用微信扫码并确认 → 服务端拿到 `bot_token / ilink_bot_id / ilink_user_id / base_url` 落
   `wx_push_accounts`（迁移 `013_wx_push_accounts`）并拉起该账号的长轮询；
3. 用户在微信里给机器人发**任意一条消息**，留下 `context_token` → 推送即激活，机器人回「✅ 微信推送已绑定」；
4. 之后推送走 `push.rs::send_binding` 的扫码分支（找不到扫码凭证才回落到管理员机器人）。

完整口径与已知边界见 docs/07 §3.5.2。解绑：微信里发「解绑」，或展示端「我的」页「解除绑定」
（删掉 `wx_push_accounts` 行，下一轮轮询读不到凭证自然结束）。

### 5.2 兼容兜底：6 位绑定码（旧流程，不再推荐）

只在账号没有扫码凭证时使用（例如管理员侧手建的旧绑定）：

1. 展示端「我的」页 →「推送设置」→ 生成 **6 位绑定码**（30 分钟一次性；码表剔除易混字符 `0/O/1/I`）；
2. 私聊机器人发 `绑定 你的手机号 绑定码`（关键词 `绑定` / `bind` / `bd`；手机号 7~15 位数字；码 6 位）；
3. 也可以分两条：先发手机号（或「绑定 手机号」），**30 秒内**再发码，机器人自动黏合成一条；
4. 手机号必须在后台「我的页面账号」里登记过，且**手机号与绑定码必须配对**（防「甲的码绑乙的号」）；
   任一环节不匹配统一回「绑定没有成功：手机号和绑定码要配对使用…」，**不泄露**号码是否登记、码是否过期；
5. 绑定成功：回复**不带姓名**（防截图外传），并提示「之后每天数据入库约 30 分钟后会推送追分提醒 / 每日报告，两个开关默认关着，去「我的」页设置」；
6. 解绑：机器人里发 `解绑` / `取消绑定` / `unbind` → 断开当前会话并回确认；未绑定过的会话回
   「这条会话还没有绑定过，不用解绑。」。

### 5.3 口令与凭据存储口径（2026-10-11）

| 项 | 口径 |
|---|---|
| `my_accounts.pass` | **argon2id PHC 字符串**（迁移 `010_my_pass_hash` 起），**不存明文**；登录时 `Argon2::verify` 比对，PHC 解析失败按「不匹配」处理 |
| 管理员口令 | 环境变量 `ADMIN_PASSWORD` 为准；未配置时用代码内置兜底（打 WARN 提示），**生产应在 .env 覆盖并轮换** |
| 微信 bot 凭据 | `bot_token` 存 `wx_push_accounts`（用户扫码）与 `config.wechat_token`（管理员全局机器人），均**在库内明文存储** —— 数据库访问权即等于推送权，备份与导出要按敏感数据处理 |
| 文档纪律 | 任何文档不得写明文口令 |

## 6. 推送开关语义（daily_report vs notify_target）

| 开关 | 落库字段 | 默认 | 打开后 | 关闭后 |
| --- | --- | --- | --- | --- |
| 每日报告 | `push_bindings.daily_report` | 关 | 每个业务日收 1 条「当天 TOP10 + 我的名次」 | 机器人「暂停接收每日推送」只关这个 |
| 追分提醒 | `push_bindings.notify_target` | 关 | 追分目标追上 / 掉出时推消息（≤5 个目标，均为本月累计口径） | 只影响追分，不影响每日报告 |

两个开关**相互独立**；都关着的人完全不推 —— `push_bindings_for_team` 只取至少开了一个开关的绑定。
展示端「我的」页开关与机器人「暂停 / 开启接收每日推送」写的是同一字段，两边互相同步。

## 7. 推送触发与去重口径

- **触发**：数据入库后延迟 `PUSH_DELAY_MINUTES`（默认 30；0 = 入库即推）统一推送，等一轮导入的几个文件都到齐，避免推半成品榜单；
- **每日报告去重**：同一业务日只推一次（`push_bindings.last_report_date`），补数据重排队列时不会重复推；
- **追分提醒**：与每日报告同轮合成一条消息（「🚀 已追上 / ⚠️ 又差回来 / · 距 X 还差 N」）；
- **后台可见**：机器人页「推送队列」（团别 / 业务日 / 计划推送时间 / 状态 + 「立即推送」按钮）；
- **失败兜底**：微信 iLink 只有被动回复形态，主动推送依赖最后一次私聊留下的 `context_token`；
  推送失败会把原因写回绑定记录，并在「我的」页提示「让对方给机器人发一条消息后再试」。

## 8. 已知边界

| 边界 | 口径 |
| --- | --- |
| 限流 | 10 条/分钟/会话（`BOT_RATE_LIMIT`），**含绑定试码**（防暴力试码），超限统一文案；对所有渠道与管理员都生效 |
| 未开播 | 当日音浪 < 2（`dialect::NOT_LIVE_WAVE_THRESHOLD`）视为未开播，不进榜、不推送 |
| 隐藏主播 | `hide_in_daily_report=1` 不进对外榜单与推送（TOP10 与个人名次按隐藏后重排） |
| 微信主动推送 | 依赖 `context_token`，长期未私聊会失败（见 §7） |
| 未绑定访客 | 完全静默，连报错都不回（防止被当成查号工具） |
| 旧口径 | 2026-10-10 前的文档 / 部署说明写「机器人命令仅管理员生效」，一律以本文为准 |
