# 07 · 后端需求文档（Rust 单技术栈）

> 版本 v2 · 2026-10-02 · 取代 v1 的 Go 后端需求
> 实现：`rust/crates/pk-server`（axum + sqlx/MySQL；运行时表已单库化并入 MySQL，
> 旧 SQLite 只作搬家来源留底），前端照常走 `api.ts`

## 1. 定位

`pk-server` 是唯一后端，承担五类职责：

1. **PK 分组**：名单解析、自动分组、拖拽后体检、均衡微调（算法权威在 `pk-core`）
2. **对外展示**：方案上架、裁剪字段、实时音浪/每日榜单
3. **方案与名单**：MySQL 业务库持久化（单库化），刷新不丢
4. **数据管理**：采集、导入、主播台账（承接原 Go 服务职责，统一入口 `/api/admin/*`）
5. **机器人**：QQ / 微信 iLink 确定性命令路由

## 2. 非功能需求

| 项 | 要求 |
|---|---|
| 运行时 | 单进程 axum；启动 < 1s；常驻内存 < 160MB（RK3318 预算） |
| 只读保障 | 查询只走 `pk_reader` 池，SQL 集中在 `dialect.rs`，拒绝外部 SQL 字符串 |
| 写库隔离 | 导入/采集/管理走 `douyin_writer` 池，与读池分离 |
| 确定性 | 机器人命令路径不调用模型，纯规则；同命令同输入同输出 |
| 降级 | 数据库不可用 → 展示页用方案快照 + `stale` 标记，不白屏 |
| 缓存 | 音浪/主播结果缓存 10 分钟（`WAVE_CACHE_TTL`），支持强制刷新 |
| 并发 | 展示读者 ≥ 100 人同时在线；公开接口缓存命中 P95 < 50ms、未命中 < 300ms；读池 ≤ 10、写池 ≤ 4 连接 |
| 限流 | 公开 API 按 IP 限流；机器人按会话限流（默认 10 条/分钟）；服务端并发导出上限 10，超出排队 |
| 可测 | `pk-core` 与 `pk-server` 均有单测；`cargo clippy -D warnings` 门禁 |

### 3.4.2 展示端手机号注册（2026-10-10 起，默认关闭；2026-10-11 改为「注册即绑定」）

用户口径：**手机号 = 账号、短信验证码 = 密码、注册时填主播姓名且必须在台账里**；
注册同时调用 WorkBuddy 用量看板的「添加账号 (OAuth)」；
姓名校验通过即视为已绑定该主播（`bound=1`），用户自己不能解绑（管理员可改绑）。
后台开关 `myRegister`（默认**关**），关着时本节接口一律 400。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/public/my/register/config` | 注册能力探测：`{open, oauth, platform}`（前端据此决定露不露「注册」页签） |
| POST | `/api/public/my/register/oauth/start` | 代调网关 `POST /accounts/login/start` → `{state, authUrl, realm}`（面板密码不出服务端） |
| GET | `/api/public/my/register/oauth/poll?state=` | 代调 `GET /accounts/login/poll` → `{status, message, nickname}` |
| POST | `/api/public/my/register/oauth/cancel` | 代调 `POST /accounts/login/cancel`（关弹窗时清理面板状态） |
| GET | `/api/public/my/register/check-name?q=` | 注册页实时校验主播姓名（免 token，注册开关关着时不可用）→ `{ok, name, personId, team}` 或 `{ok:false, error}` |
| POST | `/api/public/my/register` | `{phone, code, name, team?, wbState?}` → **校验姓名在台账 → 以台账姓名建号（`bound=1`）+ 发 token**。姓名查不到 / 该主播已有账号 / 手机号已存在 → 明确文案拒绝 |
| GET | `/api/public/my/bind/search?token=&q=` | 绑定页搜主播（全台账，注册账号还没有团别） |
| POST | `/api/public/my/bind` | `{token, personId}` → 绑主播（只允许 `bound=0`），换发带 personId/团别的 token |
| POST | `/api/admin/my-accounts/{name}/bind` | 管理员改绑（用户自己改不了） |

实现要点：网关客户端在 `wbgateway.rs`（token 缓存 + 401 重登 + 中文错误文案）；
姓名校验走 `store::anchor_lookup_by_name`（全台账精确匹配 `name`，`deleted_at IS NULL`
且 `status <> 'left'`，与「绑定主播」同一口径）；注册类接口独立限流（每 IP 每分钟 12 次，
登录仍是 5 次）；表结构见 `008_my_register.sql`（`my_accounts` 增 `bound / bound_at /
source / wb_state`），老库没跑迁移时登录路径自动退回老查询。

**注册返回**：`{ok, token, name（=主播姓名）, team（按台账）, personId, bound:true, needBind:false}`。
登录名是主播姓名，`phone` 列另存手机号，因此**手机号和姓名都能登录**。

**台账护栏与限流（2026-10-11 审计修复）**：

| 场景 | 行为 |
|---|---|
| 台账里**同名两行**（都未删除、未离团） | 拒绝注册：「台账里有不止一位叫「X」的主播，为避免绑错人，请联系管理员先区分艺名」——绝不静默取 id 最小那行 |
| 主播**团别不是 male/female**（如新建师傅/徒弟的默认 `unknown`） | 拒绝注册并让人去补台账；否则会「注册当场成功、token 过期后永远登不上」且手机号已被占，用户死局 |
| 同一手机号并发注册（两个请求同时穿过查重） | 由 `uk_my_phone_uniq` 唯一索引兜底（`012_my_phone_unique.sql`：生成列 `phone_uniq = NULLIF(phone,'')` + 唯一索引；空手机号可多行）。历史数据已有重复非空 phone 时该迁移**跳过建索引**而不是失败卡部署 |
| 忘记密码重置 | 只认 `is_admin=0` 的普通账号 —— 管理员观看账号即便登记过手机号也不能被「手机号 → 后四位」接管 |
| 业务拒绝的状态码 | 注册/重置的用户错误（姓名不在台账、已注册、格式不对）→ **400**；限流 → **429**；只有库层故障才是 500 |
| 限流档位 | 登录 5/分/IP；注册与 `check-name` 共用 12/分/IP；OAuth 轮询 120/分/IP（前端 2.5s 一次 ≈ 24/分） |
| 日志 | 手机号按 `199****1234` 打码（与展示端同口径），不落全量号码 |

### 3.4.3 访客地域门禁 + 访问日志（2026-10-10）

用户口径：展示端只对**河南 / 安徽**访客开放，判定在服务端做（**不做 Cloudflare 规则**）；
本地先开发测试再部署 147 生产。归属数据源为 ihmily/ip-info-api
（<https://github.com/ihmily/ip-info-api>）收集的免费接口，共 19 个可选（pconline(GBK) / baidu /
ip9 / ip-api / ip.sb / geojs / ipwhois / db-ip / ipinfo / ipquery / ipdata.info / ip2location /
freeipapi / nc.gy / ipwtf / realip.cc / geolocation-db / ipapi.co / db-ip-demo），
**默认只并行打 3 个（可配置）后投票合并**，单次外部查询超时 3s。

| 项 | 行为 |
|---|---|
| 中间件 | `ip_gate_mw`（`ipinfo.rs`）挂在 `/api/public/*` 路由层；放行 / 拒绝都写访问日志 |
| 数据源配置 | 门禁 `IP_GATE_SOURCES`（默认 `pconline,baidu,ip9`）；后台 IP 查询 `IP_QUERY_SOURCES`（默认 `ip.sb,ip2location,ipwhois`）。逗号分隔、未知名忽略、留空回默认；19 个来源全部仍可选（每个列表除默认 3 个外还有 16 个） |
| 判定口径 | **fail-closed**：任一来源识别出河南 / 安徽即放行；都没识别出来或全部失败一律 403 `{"error":"当前地区暂不支持访问"}`（展示省份取票数最多者，并列优先河南 / 安徽） |
| 拦截范围 | 只拦 API；HTML 页面不拦（页面加载后第一个数据接口 403，前端整页提示）。登录 / 注册 / 「我的」等所有 `/api/public/*` 一律同样受限；`verify` 不记 api 条目，改由 handler 判定（同口径）并记一条登录尝试，带账号与成败、**外省被拒也记** |
| 内网 / 本地 | loopback / 私网 IP 不发外部查询，记为「内网」且**默认拒绝**；`IP_GATE_DISABLED=1` 关闭拦截（访问日志照记） |

**两张表**（迁移 `011_ip_geo`，`pk-server migrate` 幂等新增）：

| 表 | 用途 | 关键字段 |
|---|---|---|
| `ip_geo_cache` | 归属结果缓存 **7 天**（`ip` 主键，VARBINARY(16)） | `province` / `city` / `isp` / `source` / `allowed` / `looked_up_at` |
| `access_logs` | 所有访客访问 / 登录记录（**含外省被拒的**） | `kind`（api / login）/ `ip` / `province` / `city` / `isp` / `geo_source` / `team` / `path` / `account_name` / `allowed`（地区放行）/ `login_ok`（登录成败）/ `dedup_key`（去重唯一键，login 行 NULL）/ `created_at` |

- **写入口径**：`kind=api` 同 IP + 同路径 **5 分钟对齐桶去重**（非滑动窗口；同一次页面加载的连续请求不刷屏）；
  `kind=login` 每次登录尝试都记，带账号与成败；登录了带账号（token 解析），未登录只记 IP。
- **查询接口**：`GET /api/admin/visits`（管理员鉴权），参数 `limit`（默认 200 / 上限 500）、
  `q`（IP / 账号模糊）、`kind`（api / login / visit，visit 仅兼容筛选、当前无写入路径）、
  `blocked=1`（只看被拒）。响应结构：

```json
{
  "items": [ { "id": 1, "kind": "api", "ip": "1.2.3.4", "province": "河南",
    "city": "郑州", "isp": "联通", "source": "baidu,ip9", "team": "m",
    "path": "/api/public/teams/m/daily", "account": "", "allowed": true,
    "loginOk": false, "createdAt": "2026-10-10 12:00:00" } ],
  "stats": { "all": 0, "today": 0, "todayUniq": 0, "todayAllowed": 0,
    "todayBlocked": 0, "todayLogins": 0 }
}
```

对表：`today` 今日访问 / `todayUniq` 独立 IP / `todayAllowed` 放行 / `todayBlocked` 拦截 /
`todayLogins` 登录（`all` 为累计行数）。后台页面为「访客日志」（`/admin/visits`）。

- **后台 IP 查询**：`GET /api/admin/ip-lookup?ip=1.2.3.4`（管理员鉴权）——按 `IP_QUERY_SOURCES`
  实时查询，**不读也不写 `ip_geo_cache`**。非法 IP → 400 `{"error":"IP 格式不对"}`；
  内网 IP → `province=内网`、`allowed=false`、`sources=[]`。响应：

```json
{ "ip": "218.22.0.1", "province": "安徽", "city": "Hefei", "isp": "China Telecom",
  "source": "ip.sb,ipwhois,ip2location", "allowed": true,
  "sources": [ { "name": "ip.sb", "ok": true, "province": "Anhui", "city": "Hefei", "isp": "China Telecom" },
               { "name": "ipwhois", "ok": true, "province": "Anhui Sheng", "city": "Hefei", "isp": "Chinanet" } ] }
```

对应后台「访客日志」页的「IP 查询」面板。

## 4. 数据流

```text
前端（apps/douyin-web，挂 /admin）
  ├─ /api/group/*       → pk-core 算法 → MariaDB(pk_reader) 取音浪
  ├─ /api/plans         → MySQL 业务库（单库化后读写同库，分池分账号）
  ├─ /api/admin/import  → MariaDB(douyin_writer) 写入 daily_metric
  └─ /api/admin/bots    → bot/ 模块 → MariaDB(douyin_writer) 取数/写日志

采集定时器（pk-server 内 collect/）
  → DouyinLang 推 API → MariaDB(douyin_writer)
  → 漏采告警 → 微信管理员群
```
