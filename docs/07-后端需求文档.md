# 07 · 后端需求文档（Rust 单技术栈）

> 版本 v2 · 2026-10-02 · 取代 v1 的 Go 后端需求
> 实现：`rust/crates/pk-server`（axum + sqlx/MySQL；运行时表已单库化并入 MySQL，
> 旧 SQLite 只作搬家来源留底），前端照常走 `api.ts`

## 1. 定位

`pk-server` 是唯一后端，承担五类职责：

1. **PK 分组**：名单解析、自动分组、拖拽后体检、均衡微调（算法权威在 `pk-core`）
2. **对外展示**：方案上架、裁剪字段、实时音浪/每日榜单
3. **方案与名单**：MySQL 业务库持久化（单库化），刷新不丢
4. **数据管理**：采集、导入、主播台账（承接原 Go 服务职责，统一入口 `/api/admin/*`）
5. **机器人**：QQ / 微信 iLink 确定性命令路由

## 2. 非功能需求

| 项 | 要求 |
|---|---|
| 运行时 | 单进程 axum；启动 < 1s；常驻内存 < 160MB（RK3318 预算） |
| 只读保障 | 查询只走 `pk_reader` 池，SQL 集中在 `dialect.rs`，拒绝外部 SQL 字符串 |
| 写库隔离 | 导入/采集/管理走 `douyin_writer` 池，与读池分离 |
| 确定性 | 机器人命令路径不调用模型，纯规则；同命令同输入同输出 |
| 降级 | 数据库不可用 → 展示页用方案快照 + `stale` 标记，不白屏 |
| 缓存 | 音浪/主播结果缓存 10 分钟（`WAVE_CACHE_TTL`），支持强制刷新 |
| 并发 | 展示读者 ≥ 100 人同时在线；公开接口缓存命中 P95 < 50ms、未命中 < 300ms；读池 ≤ 10、写池 ≤ 4 连接 |
| 限流 | 公开 API 按 IP 限流；机器人按会话限流（默认 10 条/分钟）；服务端并发导出上限 10，超出排队 |
| 可测 | `pk-core` 与 `pk-server` 均有单测；`cargo clippy -D warnings` 门禁 |

### 3.4.3 访客地域门禁 + 访问日志（2026-10-10）

用户口径：展示端只对**河南 / 安徽**（省级）+ **江苏徐州**（城市级白名单）访客开放，
判定在服务端做（**不做 Cloudflare 规则**）；本地先开发测试再部署 147 生产。归属数据源为 ihmily/ip-info-api
（<https://github.com/ihmily/ip-info-api>）收集的免费接口，共 19 个可选（pconline(GBK) / baidu /
ip9 / ip-api / ip.sb / geojs / ipwhois / db-ip / ipinfo / ipquery / ipdata.info / ip2location /
freeipapi / nc.gy / ipwtf / realip.cc / geolocation-db / ipapi.co / db-ip-demo），
**默认只并行打 3 个（可配置）后投票合并**，单次外部查询超时 3s。

| 项 | 行为 |
|---|---|
| 中间件 | `ip_gate_mw`（`ipinfo.rs`）挂在 `/api/public/*` 路由层；放行 / 拒绝都写访问日志 |
| 数据源配置 | 门禁 `IP_GATE_SOURCES`（默认 `pconline,baidu,ip9`）；后台 IP 查询 `IP_QUERY_SOURCES`（默认 `ip.sb,ip2location,ipwhois`）。逗号分隔、未知名忽略、留空回默认；19 个来源全部仍可选（每个列表除默认 3 个外还有 16 个） |
| 判定口径 | **fail-closed**：任一来源识别出河南 / 安徽 / 江苏徐州（城市级白名单 `allowed_city()`，萧县 IP 归属地常落徐州）即放行；都没识别出来或全部失败一律 403 `{"error":"当前地区暂不支持访问"}`（展示省份取票数最多者，并列优先河南 / 安徽） |
| 例外通道 | 环境变量 `IP_GATE_ALLOWLIST=1.2.3.4,10.0.0.0/24`（精确 IP 或 CIDR，逗号分隔）与数据库 `ip_allowlist` 表（迁移 `014_ip_allowlist`）命中即放行，访问日志照记；用于管理员本机出口等固定 IP。后台接口 `GET/POST /api/admin/ip-allowlist`、`DELETE /api/admin/ip-allowlist/{id}` |
| 门禁开关 | `IP_GATE_DISABLED=1` 整体关闭拦截（本地调试用，访问日志照记）；生产留空 |
| 拦截范围 | 只拦 API；HTML 页面不拦（页面加载后第一个数据接口 403，前端整页提示）。登录 / ~~注册~~ / 「我的」等所有 `/api/public/*` 一律同样受限（注册入口已于 2026-10-14 移除，门禁口径不变）；`verify` 不记 api 条目，改由 handler 判定（同口径）并记一条登录尝试，带账号与成败、**外省被拒也记** |
| 内网 / 本地 | loopback / 私网 IP 不发外部查询，记为「内网」且**默认拒绝**；`IP_GATE_DISABLED=1` 关闭拦截（访问日志照记） |

**两张表**（迁移 `011_ip_geo`，`pk-server migrate` 幂等新增）：

| 表 | 用途 | 关键字段 |
|---|---|---|
| `ip_geo_cache` | 归属结果缓存 **7 天**（`ip` 主键，VARBINARY(16)） | `province` / `city` / `isp` / `source` / `allowed` / `looked_up_at` |

#### 3.5.2 微信推送多账号并发模型与已知边界（2026-10-11）

主路径（`wxpush.rs`）：**每个展示端账号自己扫一个 iLink 账号**，凭证（`bot_token` /
`ilink_bot_id` / `ilink_user_id` / `base_url`）落 `wx_push_accounts`（迁移 `013`），
服务端为**每个账号各跑一条独立的 `getupdates` 长轮询**。管理员全局机器人
（`bot/weixin.rs` 的 `WxTransport`，一条轮询、凭据存 `config` 表）是**回落路径**，
`push.rs::send_binding` 在账号没有扫码凭证时才用它（旧手机号 / 绑定码绑定仍走这条）。

| 项 | 现状 |
|---|---|
| 任务模型 | 一个账号 = 一个 `tokio::spawn` 任务（`wxpush::poll_loop`），任务句柄存进程内 `TASKS: HashMap<name, JoinHandle>`；`ensure_account` 幂等（已在跑则跳过，已结束的句柄先清理） |
| 拉起时机 | ① 进程启动 `wxpush::bootstrap` 全量恢复所有 `bot_token` 非空的账号；② 新账号扫码确认后由公开接口调 `ensure_account` |
| 账号隔离 | 账号之间互不影响：某账号的轮询报错 / 退出**不影响**其它账号；任务是纯异步，不独占线程 |
| 停止条件 | 账号行被删（解绑）、`bot_token` 变空、连续 4 次 `-14`；下一轮循环读不到账号即自然结束 |
| cursor | `get_updates_buf` 非空才写回 `wx_push_accounts.updates_buf`（空游标会把进度打回去） |
| 空回包 | 无消息时按服务端下发的 `longpolling_timeout_ms`（上限 35s）sleep 再拉下一轮；有消息则立即处理完再拉 |

**登录过期（-14）语义**：`errcode/ret == -14` 不清凭据，暂停 **1 小时**重试；
连续 **4 次**（`SESSION_EXPIRED_MAX_RETRY`）仍过期才认定彻底失效、停止该账号轮询，
需要用户重新扫码。管理员机器人侧同样策略，多一步把 `phase` 置回 `awaiting_scan`。

**已知弱点（当前正在修，先记口径以免误判）**：

| 弱点 | 现状 | 影响 |
|---|---|---|
| 固定 5 秒重试，无指数退避 | `poll_loop` 里非 `-14` 错误一律 `sleep(5s)` 后重试（管理员通道是 3s） | 网络抖动或 iLink 侧限流时，N 个账号同时 5s 重试会形成同步尖峰 |
| 全局共享 `reqwest::Client` | `bot/weixin.rs::shared_http()` 是 `OnceLock` 单例，超时 75s | 100+ 账号共用同一连接池；单账号慢请求可能占满连接，波及别人 |
| cursor 每次写库 | 每轮拿到非空 cursor 就 `UPDATE wx_push_accounts`（走写池） | 100+ bot 长轮询时写库 QPS 与轮询频率同量级，写池（≤4）是瓶颈点 |
| 任务退出不自动重启 | 只有进程启动 `bootstrap` 或新扫码会拉起任务；任务因连续 `-14` 退出后**不会**自愈，必须用户重扫或重启进程 | 静默失效：账号看着还绑着，实际已不再收消息 |
| `updates_buf` 长度 | 列宽 `VARCHAR(255)` | 官方 cursor 变长时可能被截断（当前够用） |

**100+ bot 规模运维注意事项**：

1. 轮询任务本身很轻（空闲时一个长连接 + 定时 sleep），内存开销主要在 `reqwest` 连接与
   tokio 任务栈；rk3318 这种小内存盒子按「单进程 160MB 预算」评估，扩容前先实测。
2. 写池上限 4，`wx_push_account_set_updates_buf` 与推送写 `push_touch` 抢同一个池 ——
   bot 数量上来后优先观察写池等待，而不是 CPU。
3. 进程重启 = 全部账号重新 `bootstrap`，会瞬间发起 N 个 `getupdates`；分批/错峰启动前
   先确认 iLink 侧频控。
4. 排障看日志关键字：`扫码账号 getupdates 失败，5 秒后重试`（普通错误）、
   `扫码账号登录过期，一小时后重试`（-14 前 3 次）、
   `扫码账号登录连续过期，停止轮询；需要重新扫码`（已失效，需人工重扫）。
5. 孤儿凭证：主播离职删了 `person` 但 `wx_push_accounts` 行还在时，进程启动仍会为它拉一条
   轮询（空占连接）。身份锚点统一后按 `person_id` 扫孤儿并清理，见 `docs/12` 与
   `identity_orphan_log`（迁移 `015`）。

## 4. 数据流

```text
前端（apps/douyin-web，挂 /admin）
  ├─ /api/group/*       → pk-core 算法 → MariaDB(pk_reader) 取音浪
  ├─ /api/plans         → MySQL 业务库（单库化后读写同库，分池分账号）
  ├─ /api/admin/import  → MariaDB(douyin_writer) 写入 daily_metric
  └─ /api/admin/bots    → bot/ 模块 → MariaDB(douyin_writer) 取数/写日志

采集定时器（pk-server 内 collect/）
  → DouyinLang 推 API → MariaDB(douyin_writer)
  → 漏采告警 → 微信管理员群
```

## 5. 迁移验收（R1 / R2）

| # | 验收项 | 说明 |
|---|---|---|
| 1 | 机器人命令路由与 Go 版一致 | `help / query / rank / group` 四命令单测（Rust 端已迁完） |
| 2 | CSV 导入三步流可用 | 字段映射预览 → 确认 → `daily_metric` 落库 |
| 3 | 写库只走 `douyin_writer` | 读池永远 `SELECT`，单测覆盖 SQL 白名单 |
| 4 | 机器人双通道上盒 | QQ + 微信 iLink，断电自动恢复，会话落 MySQL |
| 5 | 单镜像部署 | `deploy/rk3318` 只引用 `pk-server`，离线包可 load |

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 机器人渠道 SDK 需长连接 + 扫码 | 独立 `Channel` trait，SDK 隔离；会话状态存 MySQL `bot_sessions`（单库化后） |
| 写库路径引入非预期写 SQL | 写操作全部走单一 repo 层，review 门禁 + 单测 |
| RK3318 内存吃紧 | 单进程预算 160MB，采集定时器可关（env 开关） |
