# 07 · 后端需求文档（Rust 单技术栈）

> 版本 v2 · 2026-10-02 · 取代 v1 的 Go 后端需求
> 实现：`rust/crates/pk-server`（axum + sqlx + SQLite），前端照常走 `api.ts`

## 1. 定位

`pk-server` 是唯一后端，承担五类职责：

1. **PK 分组**：名单解析、自动分组、拖拽后体检、均衡微调（算法权威在 `pk-core`）
2. **对外展示**：方案上架、裁剪字段、实时音浪/每日榜单
3. **方案与名单**：SQLite 持久化，刷新不丢
4. **数据管理**：采集、导入、主播台账（原 Go `/dy/*` 职责）
5. **机器人**：QQ / 微信 iLink 确定性命令路由

## 2. 非功能需求

| 项 | 要求 |
|---|---|
| 运行时 | 单进程 axum；启动 < 1s；常驻内存 < 160MB（RK3318 预算） |
| 只读保障 | 查询只走 `pk_reader` 池，SQL 集中在 `dialect.rs`，拒绝外部 SQL 字符串 |
| 写库隔离 | 导入/采集/管理走 `douyin_writer` 池，与读池分离 |
| 确定性 | 机器人命令路径不调用模型，纯规则；同命令同输入同输出 |
| 降级 | 数据库不可用 → 展示页用方案快照 + `stale` 标记，不白屏 |
| 缓存 | 音浪/主播结果缓存 10 分钟（`WAVE_CACHE_TTL`），支持强制刷新 |
| 并发 | 展示读者 ≥ 100 人同时在线；公开接口缓存命中 P95 < 50ms、未命中 < 300ms；读池 ≤ 10、写池 ≤ 4 连接 |
| 限流 | 公开 API 按 IP 限流；机器人按会话限流（默认 10 条/分钟）；服务端并发导出上限 10，超出排队 |
| 可测 | `pk-core` 与 `pk-server` 均有单测；`cargo clippy -D warnings` 门禁 |

## 4. 数据流

```text
前端（apps/web）
  ├─ /api/group/*  → pk-core 算法 → MariaDB(pk_reader) 取音浪
  ├─ /api/plans    → SQLite（写） + MariaDB（读音浪实时值）
  ├─ /dy/import    → MariaDB(douyin_writer) 写入 daily_metric
  └─ /dy/api/robot → bot/ 模块 → MariaDB(douyin_writer) 取数/写日志

采集定时器（pk-server 内 collect/）
  → DouyinLang 推 API → MariaDB(douyin_writer)
  → 漏采告警 → 微信管理员群
```

## 5. 迁移验收（R1 / R2）

| # | 验收项 | 说明 |
|---|---|---|
| 1 | `/dy/api/robot/commands` 返回与 Go 版一致 | `help / query / rank / group` 四命令单测 |
| 2 | CSV 导入三步流可用 | 字段映射预览 → 确认 → `daily_metric` 落库 |
| 3 | 写库只走 `douyin_writer` | 读池永远 `SELECT`，单测覆盖 SQL 白名单 |
| 4 | 机器人双通道上盒 | QQ + 微信 iLink，断电自动恢复，消息落 SQLite |
| 5 | 单镜像部署 | `deploy/rk3318` 只引用 `pk-server`，离线包可 load |

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 机器人渠道 SDK 需长连接 + 扫码 | 独立 `Channel` trait，SDK 隔离；状态存 SQLite |
| 写库路径引入非预期写 SQL | 写操作全部走单一 repo 层，review 门禁 + 单测 |
| RK3318 内存吃紧 | 单进程预算 160MB，采集定时器可关（env 开关） |
