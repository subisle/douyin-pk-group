## 1. 一句话问题

师傅现在只能从全团日报里「大海捞针」看徒弟：日报按全团排名排，师傅要自己找
名下几个徒弟在哪、涨了还是跌了。运营想给师傅推一张**师门专属图**：徒弟音浪 +
与上日的差距，一眼看清谁在冲、谁掉队。

同时运营缺一个**主动触达工具**：现在只能等用户开订阅后推日报/追分，没有
「管理员主动给某人/某批人发一条消息」的入口。要补一个消息下发页，支持
多选、批量、按师傅圈人（师傅 + 徒弟一起收），内容同时走 wxbot 与 web 弹窗。

| # | 需求 | 本方案的答案 |
|---|---|---|
| 1 | 师傅推「徒弟音浪 + 对比上日」图 | §3 师门日报：新渲染器 + push.rs 集成，`lineage_report` 开关 |
| 2 | 管理员发消息到任何人的 wxbot | §5 消息下发：收件人解析 + outbox 队列 + 限速 worker |
| 3 | web 弹窗接收 + wxbot 接收 | §6 双渠道：`admin_messages` + 「我的」页弹窗 + 已读回执 |
| 4 | 批量 / 多选 / 按师傅含徒弟 | §5.2 服务端收件人解析（客户端只传 id，防篡改） |

### 1.1 需求理解的两个确认点（开工前请拍板）

1. **「web 页面显示弹窗」**按「**展示端『我的』页登录后弹窗显示管理员消息**」设计，
   同时管理端发送页自带**发送前预览弹窗**。如果本意只是管理端预览，砍掉 §6.2 即可。
2. **「师傅类别的自动推送」**默认做成**与每日报告并列的第三种订阅开关**
   （`lineage_report`，用户可在「我的」页自己关，管理员可一键为所有师傅开启）。
   如果要的是「所有师傅无条件必推」，把 §4.3 的开关改成全局 config 即可，改动很小。

## 2. 总体设计

```
                    ┌─ 数据入库（导入）→ push_jobs 延迟队列（现有）
                    │
push.rs run() ──────┼─ daily_report  → 全团月榜图（现有）
                    ├─ notify_target → 追分提醒（现有）
                    └─ lineage_report→ 师门日报图（新）★
                                          │
              lineage_report.rs（新）      │ send_binding_images（复用）
              build_lineage_report()       ▼
              render_lineage_svg()   wx_push_accounts（收件人自己的扫码 bot）
                                          ▼
                                    微信 iLink → 师傅

管理员消息下发页（/admin/send，新）
   │  选收件人（多选/按师傅/批量）→ POST /api/admin/send
   ▼
admin_messages（消息主档）
   ├─→ admin_outbox（wxbot 渠道行）→ 限速 worker → 复用 push.rs 发送链路
   └─→ web 渠道（不入队）：我的页登录后 GET /api/public/my/messages
                            → 弹窗显示 → POST .../read（已读回执）
                            → GET .../image.png（按需渲染图片）
```

两条链路**共用同一套发送原语**（`wxmedia::user_send_image` / 会话上下文解析），
只是触发方不同：师门日报由入库延迟队列触发，消息下发由管理员手动触发。

## 3. 师门日报图

### 3.1 数据口径（全部复用既有口径，不新造）

| 列 | 口径 | 来源 |
|---|---|---|
| 今日音浪 | `SUM(wave) WHERE wave_reliable=1 AND biz_date = D` | `daily_metric`（同 report.rs::build） |
| 昨日音浪 | 同上，`biz_date = D-1` | 同上 |
| 较昨日 | 今日 − 昨日；昨日无数据行 = `—`（不显示 0 差） | Rust 内存计算 |
| 本月累计 | `SUM(wave) WHERE wave_reliable=1 AND TO_CHAR(biz_date,'YYYY-MM') = D[..7]` | 同 report.rs / 展示端榜单 |
| 状态 | 今日音浪 < 2 = 未播（`dialect::is_live_wave`） | 唯一口径 |
| 名单 | 师傅本人 + **直系徒弟**（`person.master_id = 师傅id`），`deleted_at IS NULL AND hide_in_daily_report=0 AND status<>'left'` | 与全团日报 P1-10 口径一致 |

- **只含直系徒弟**，不含徒孙（与族谱页「直系徒弟」口径一致）；含徒孙留到以后按需加开关。
- 昨日判定用业务日 `D-1` 的日历日（`biz_date` 是 DATE 列，直接减一天，不受时区影响）。
- 补录昨日数据后图片按发送时刻实时重算，不做快照缓存。

### 3.2 布局（1440 宽，沿用 report.rs 模板风格）

```
┌──────────────────────────────────────────────────────────────┐
│  XX 师门 · 10月14日音浪                     内部数据 · 请勿外传 │
│  门下 6 人 · 今日合计 8.3 万 · 较昨日 ▲1.2 万                  │
├──────┬────────┬────────┬─────────┬──────────┬───────────────┤
│ 主播  │ 今日音浪 │ 昨日音浪 │  较昨日  │ 本月累计  │ 状态          │
│ XX(师)│  2.1万 │  1.8万  │ ▲ 3000  │  15.6万  │ 开播          │  ← 师傅本人行，高亮
│ 徒弟A │  1.9万 │  1.1万  │ ▲ 8000  │  12.3万  │ 开播          │
│ 徒弟B │  9800  │  1.2万  │ ▼ 2200  │   8.9万  │ 开播          │
│ 徒弟C │    0   │  6600   │ ▼ 6600  │   3.2万  │ 未播(本月2天)  │  ← 未播行红底
│   …  │        │         │         │          │               │
├──────┴────────┴────────┴─────────┴──────────┴───────────────┤
│ 合计：8.3 万（较昨日 ▲1.2 万）· 未播：徒弟C、徒弟E             │
└──────────────────────────────────────────────────────────────┘
```

- 排序：师傅本人固定首行，徒弟按**今日音浪降序**（同分按姓名，与日报一致）。
- 较昨日：▲ 红 / ▼ 绿（涨红跌绿的国内习惯）；差值为 0 显示 `—`。
- 未播者底部汇总一行（呼应全团日报的师傅分组条，这里是**单一师门视角**）。
- 水印：`personal_mark` = **收件人姓名**（与月榜图同机制，防止截图外传不认账）。
- 分页：复用 `PAGE_ROWS = 40` 的分页逻辑，多页时第二张起页码提示（同现有图片推送）。
- 说明文字（首图 caption）：`👨‍🏫 XX 师门 · 10月14日：门下 6 人，今日合计 8.3 万（▲1.2 万），未播 1 人`。

### 3.3 新模块

新文件 `rust/crates/pk-server/src/lineage_report.rs`（渲染 + 组数都在一处，report.rs 不再变大）：

```rust
pub struct LineageRow { name, today, yesterday, diff, month_total, live, is_master }
pub struct LineageReport { master_name, date, rows, total_today, total_diff, absent_names }

pub async fn build(st, date, master_person_id) -> anyhow::Result<LineageReport>
pub fn render_svg_pages(rep, per_page, personal_mark) -> Vec<String>   // SVG
// PNG 复用 push.rs::svg_to_png —— 顺手把该函数从 push.rs 挪到 lineage_report.rs
// 或提为 pub(crate)，避免两处各留一份 resvg 调用
```

`build()` 4 条聚合 SQL（今日/昨日/本月/名册）全走 `pgrs::query(LOCAL)` + 参数化，
人员 id 用 bind 不内联；`date` 进 SQL 前过 `valid_biz_date` 白名单（与 push_run_now 同款）。

## 4. 师门日报的触发与开关

### 4.1 触发点

**完全复用现有延迟推送队列**：数据入库 → `push_jobs`（同 team+biz_date 去重）→
延迟 30 分钟 → `push.rs::run()`。run() 在现有循环里对每个 binding 增加一路：

```
if b.lineage_report && 此人名下有直系徒弟 {
    if b.last_lineage_date == date { skip（同业务日只推一次，与 daily_report 同机制） }
    build_lineage_report → svg_to_png → send_binding_images（或失败退回文本摘要）
    成功后写 last_lineage_date = date
}
```

- **图片构建失败降级为文本摘要**（一行 caption 也会发），与月榜失败退文本的策略一致。
- 收件人没有扫码账号 / 会话失效：只记 `last_error`，不影响其他订阅者（现有行为）。

### 4.2 有徒弟才算「师傅」

`lineage_report` 开着但名下没有徒弟的人**不推**（不推空图）。判断即 §3.1 名册查询
COUNT = 0 时跳过，outbox / 日志记 `skipped: 无徒弟`。

### 4.3 开关落点

| 落点 | 行为 |
|---|---|
| `push_bindings.lineage_report`（新列，SMALLINT DEFAULT 0） | 每人开关；「我的」页推送设置里第三项「师门日报（徒弟音浪对比）」，**仅当本人有徒弟时显示** |
| 管理端一键开启 | 消息下发页按钮「为所有师傅开启师门日报」：一条 UPDATE 把名下有徒弟的绑定批量置 1，返回影响行数 |
| `push_bindings.last_lineage_date`（新列） | 同业务日去重（补数重推不重复发，对齐 `last_report_date`） |

## 5. 管理员消息下发

### 5.1 定位

`/admin/send`（导航名「消息下发」，排在「机器人」之后）。管理员手动动作，
与自动推送互不相干；发送**不写入** `last_report_date` / `last_lineage_date`，
不会顶掉当日自动推送的去重。

### 5.2 收件人解析（服务端权威，防篡改）

前端只传**意图**，展开与校验都在服务端做：

```rust
enum TargetSpec {
    Persons(Vec<u64>),          // 多选：person.id 列表（去重、过滤已删除/离职）
    Masters(Vec<u64>),          // 按师傅：本人 + 直系徒弟一起收
    Team(String),               // 批量：male / female
    All,                        // 批量：全部已绑定用户
}
```

- `Masters` 展开：`person WHERE master_id = ?`（口径同 §3.1，隐藏/离职的徒弟不发）。
  请求体带 `includeMaster: bool`（默认 true，即师傅本人也收一份）。
- 展开后统一投影到**收件人三元组** `(person_id, name, 团别)`，再按渠道解析：
  - **wxbot 渠道**：`push_bindings`（拿 conversation_id）+ `wx_push_accounts`（拿凭证）；
    两处都查不到 → outbox 行记 `skipped: 未绑定微信 bot`。
  - **web 渠道**：`my_accounts WHERE person_id = ? AND bound = 1`；查不到 →
    web 行记 `skipped: 未开通我的页账号`（不影响 wxbot 渠道）。
- 上限保护：展开后 > 500 人直接 400 拒绝，提示缩小范围（防止误操作全团轰炸）。

### 5.3 数据模型（迁移 `022_admin_messages.sql`）

```sql
CREATE TABLE IF NOT EXISTS admin_messages (
  id BIGINT GENERATED ALWAYS AS IDENTITY,
  title VARCHAR(128) NOT NULL DEFAULT '',        -- 弹窗标题
  content TEXT NOT NULL DEFAULT '',              -- 纯文本，≤1000 字（写入口校验）
  image_kind VARCHAR(16) NOT NULL DEFAULT 'none',-- none|lineage|daily|month
  image_date DATE,                               -- 图片业务日（默认今天）
  channels VARCHAR(32) NOT NULL DEFAULT '',      -- 逗号分隔：wxbot,popup
  target_type VARCHAR(16) NOT NULL DEFAULT 'persons',
  target_ids TEXT NOT NULL DEFAULT '[]',         -- 原始请求 JSON（审计可回放）
  created_by VARCHAR(64) NOT NULL DEFAULT 'admin',
  created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id)
);

CREATE TABLE IF NOT EXISTS admin_outbox (
  id BIGINT GENERATED ALWAYS AS IDENTITY,
  message_id BIGINT NOT NULL,
  person_id BIGINT NOT NULL DEFAULT 0,
  recipient_name VARCHAR(64) NOT NULL DEFAULT '',
  channel VARCHAR(16) NOT NULL DEFAULT 'wxbot',  -- wxbot | popup（popup 行只做状态记录）
  status VARCHAR(16) NOT NULL DEFAULT 'pending', -- pending|sent|failed|skipped
  error VARCHAR(255) NOT NULL DEFAULT '',
  created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  sent_at TIMESTAMPTZ,
  PRIMARY KEY (id)
);
CREATE INDEX IF NOT EXISTS idx_outbox_msg ON admin_outbox (message_id);
CREATE INDEX IF NOT EXISTS idx_outbox_status ON admin_outbox (status);

CREATE TABLE IF NOT EXISTS admin_message_reads (
  message_id BIGINT NOT NULL,
  name VARCHAR(64) NOT NULL DEFAULT '',          -- my_accounts 账号名
  person_id BIGINT NOT NULL DEFAULT 0,
  read_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (message_id, name)
);
```

- 渠道与状态拆行：一条消息 × 每收件人 × 每渠道 = 一行 outbox，失败互不影响，
  页面能精确显示「wxbot 发成功、弹窗已读 / 未读」。
- 写入全走 writer 池（`writer.rs` 写守卫），读走 LOCAL。

### 5.4 发送 worker（限速 + 断点续发）

```
POST /api/admin/send
  → 校验（口令鉴权已有；target 展开 ≤500；content ≤1000 字）
  → 落 admin_messages + admin_outbox（pending）
  → tokio::spawn(worker(message_id))
  → 立即返回 { messageId, recipients: n }   // 页面跳到发送详情

worker：
  逐行取 pending（FOR UPDATE SKIP LOCKED 语义用「UPDATE ... WHERE status='pending'
  RETURNING」占行，防止重启后双发）
  wxbot 行：解析 push_ctx（复用 push.rs 的会话上下文逻辑）→
     文字：wx_proactive 同款 sendmessage
     图片：image_kind ≠ none 时按收件人实时渲染（lineage 图只发给有徒弟的，
           无徒弟自动降级纯文本并记 skipped note）→ user_send_image
  行间 sleep 1.5–3.5s 随机抖动（防 iLink 风控；单批 100 人 ≈ 3–5 分钟）
  单行失败只记 error 继续；进程重启后 bootstrap 扫 pending 行续发
  （与 wxpush supervisor 的补拉模式同款）
```

### 5.5 API 清单（全部在 `/api/admin/*` 鉴权内）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/send/targets?q=` | 收件人树：主播列表（id/name/团别/是否绑bot/师傅id/直系徒弟数），供多选与按师傅圈人 |
| POST | `/api/admin/send` | 创建消息 + outbox 并启动 worker（body: title/content/imageKind/imageDate/channels/target{type,ids,includeMaster}） |
| GET | `/api/admin/send/messages?limit=` | 发送历史（含 sent/failed/skipped/pending 计数） |
| GET | `/api/admin/send/messages/{id}` | 详情：每收件人每渠道状态（页面轮询进度） |
| POST | `/api/admin/send/enable-lineage` | 一键为所有师傅开启师门日报（返回影响行数） |

## 6. Web 弹窗渠道

### 6.1 展示端「我的」页弹窗（收件侧）

- 登录成功后 `GET /api/public/my/messages`（`X-My-Token`，复用现有登录 token 机制）→
  有未读消息就弹窗（复用 st_page.html 现成的引导弹窗样式与手势/键盘逻辑）。
- 弹窗内容：标题 + 正文（**textContent 渲染，绝无 innerHTML**，防注入）+
  可选图片（`<img src="/api/public/my/messages/{id}/image.png">`，带 token 过 fetch 取 blob）。
- 多条未读：一个弹窗内列表展示（最新在上），不做连续弹。
- 关闭 / 「知道了」→ `POST /api/public/my/messages/{id}/read`（幂等，重复点不报错）→
  写 `admin_message_reads`。**已读即不再弹**，历史消息后续可在「我的」页加「消息」入口查看（本期不做，只弹未读）。
- 图片按需渲染：`image.png` 按 **该收件人** 实时渲染对应 `image_kind` 的图
  （水印 = 本人姓名），与 wxbot 渠道同一渲染器；渲染失败 404 兜底，不挡正文。

### 6.2 管理端发送前预览（发送页内）

编辑区右侧实时预览卡片（等宽手机壳样式）：标题/正文/按钮怎么弹、图片占位。
纯前端渲染，不发请求。发送确认弹窗里显示「将发送给 N 人 × 渠道」。

### 6.3 已读回执展示

发送详情页 web 渠道列显示：`已读 / 未读 / 未开通`（读 `admin_message_reads`
与 `my_accounts` 联查）。wxbot 渠道没有已读概念，只有 `已发 / 失败 / 跳过`。

## 7. 安全与风控

| 面 | 措施 |
|---|---|
| 鉴权 | `/api/admin/send/*` 走既有 admin token；`/api/public/my/messages*` 走 X-My-Token，**按 person_id 过滤**，绝不下发他人消息（含图片端点按收件人出图） |
| 收件人篡改 | 客户端只传 id/意图，师傅→徒弟展开、团别过滤、绑定状态判断全在服务端 |
| 注入 | 全部参数化 bind；`date` 过白名单；弹窗正文 textContent；wxbot 只发纯文本 |
| 内容上限 | title ≤64 字、content ≤1000 字、收件人展开 ≤500，超限 400 带人话文案 |
| 频控 | worker 串行 + 1.5–3.5s 抖动；同批次单 bot 失败隔离（沿用 wxpush 的 per-account 隔离思路） |
| 审计 | `admin_messages.created_by` + `target_ids` 原样留档；outbox 全量留痕可追责 |
| 误操作 | 发送确认弹窗（人数 × 渠道）；>100 人二次确认 |

## 8. 边界与降级

| 场景 | 行为 |
|---|---|
| 师傅没有徒弟 / 徒弟全隐藏离职 | 自动推送跳过不推空图；下发选了他且 image_kind=lineage → 图片降级纯文本 |
| 收件人未绑 wxbot / 未开通我的页 | 对应渠道行 `skipped` + 原因；另一渠道照发 |
| 会话 context_token 失效 | 现有错误文案（「让对方先给机器人发一条消息」）落到 outbox.error，页面可见 |
| 昨日未导入数据 | diff 显示 `—`，不显示 0 差误导 |
| 发送中进程重启 | pending 行由 bootstrap 续发；已 sent 的不重发（占行机制） |
| 补录昨日音浪后 | 图片按发送时刻实时渲染，已发的图不追改（明确不承诺） |

- **单测**（cargo test）：diff 计算（昨日缺失/补零/负差）；`render_lineage_svg` 快照
  （对照 testdata，同 report.rs 的 SVG 断言法）；TargetSpec 展开（去重、过滤离职、

- **集成**：`uicheck-admin.mjs` 增加只读段：`/admin/send` 深链 + 渲染断言 +
  targets 接口字段白名单（不下发手机号等内部字段）。
- **真发验证**：测试环境挑 1 个测试师傅 + 1 个测试徒弟走全链路
  （入库 → 延迟推送收图；后台下发 → wxbot 收到 + 我的页弹窗 + 已读回执）。
- **验收口径**（与 §3.1 对齐）：图内「今日」列与全团日报同日数字一致；
  diff = 今日−昨日可手算复核；未播判定 = 当日音浪 < 2。
