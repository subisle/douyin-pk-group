### 关键数据事实

1. **名单匹配率 53/55**：55 个主体名字里，**`目`、`阿楠` 在 `person` 表中不存在**（库里有 `浩楠`、`晓楠`、`南方楠`、`楠枫`，需人工确认对应关系）。
2. **数据只到 2026-09-22/23**：`daily_metric` 仅 3 天（09-20 ~ 09-22，287 行），`wave_snapshot` 仅 3 天（09-21 ~ 09-23）。今天是 09-27，采集链路有 4~5 天缺口，需确认是否还在跑。
3. **`daily_metric` 首日差分不可信**：首日 `prev_snapshot_date IS NULL`，`wave` 直接等于 `cumulative_wave`（如玖玉 170 万、浩龙 161 万），而 `wave_snapshot` 最新累计才 10 万级。**直接对近 3 天求和会严重虚高**，必须过滤 `wave_reliable = 0` 或 `prev_snapshot_date IS NULL` 的行。

## 3. 后端设计

### 3.1 只读保障（硬约束，三层）

1. **代码层**：所有查询集中在 `server/src/repos/readonly/*.ts`，对外只暴露函数，**不接受任何外部传入的 SQL 字符串**。
2. **驱动层**：封装 `queryReadonly(sql, params)`，正则校验必须以 `SELECT` / `SHOW` 开头，含 `INSERT|UPDATE|DELETE|DROP|ALTER|CREATE` 一律抛错。
3. **账号层**：若 sqlpub 允许建子账号，另建一个 `GRANT SELECT` 用户写入 `.env`，当前全权账号仅作兜底。

### 3.2 连接池 + 缓存（免费库必须做）

```ts
createPool({
  host, port, user, password, database,
  waitForConnections: true,
  connectionLimit: 3,        // 免费库连接数极少，别超
  connectTimeout: 8000,
  enableKeepAlive: true,
})
```

- 音浪查询结果 **内存缓存 10 分钟**（node-cache），避免每次刷新打全表。
- 提供 `POST /api/cache/refresh` 手动强刷。

### 3.3 音浪口径（可切换，默认方案见 §6）

```sql
-- 口径 A：区间音浪（默认，推荐）
-- 用 wave_snapshot 最新日 - 最早日，避开首日差分陷阱
SELECT person_id, MAX(CASE WHEN biz_date = @last THEN wave_value END)
                - MAX(CASE WHEN biz_date = @first THEN wave_value END) AS wave
FROM wave_snapshot WHERE biz_date IN (@first,@last) GROUP BY person_id;

-- 口径 B：本月音浪
SELECT person_id, wave FROM monthly_metric WHERE period = '2026-09';

-- 口径 C：近 N 天（必须过滤首日不可信行）
SELECT person_id, SUM(wave) FROM daily_metric
WHERE biz_date >= ? AND wave_reliable = 1 AND prev_snapshot_date IS NOT NULL
GROUP BY person_id;
```

## 4. 前端设计

### 4.1 页面流程（4 步）

1. **导入名单**：大文本框粘贴 → 右侧实时解析预览，未匹配项标红并可下拉绑定/手动录入音浪。
2. **选口径 + 自动分组**：口径下拉（区间/本月/近N天）、每组人数上限（默认 8）、策略（蛇形均衡 / 随机 / 同门回避）→ 生成看板。
3. **拖拽微调**：`@dnd-kit` 多容器拖拽，支持组内排序 + 跨组移动；顶部实时显示各组总音浪、极差、标准差。
4. **导出**：`html-to-image` 生成 750px 宽长图（PNG），可选带/不带音浪数值、带团队标题与日期。

### 4.2 组件拆分

```
RosterImport  →  WaveConfig  →  GroupBoard
                                ├─ GroupColumn（Droppable）
                                └─ PlayerCard（Draggable，头像+名字+音浪+队长）
                             →  ExportBar（PNG / 复制文字版）
```

### 4.3 拖拽要点（易踩坑）

- 用 `DndContext` + `SortableContext`，**每个分组列是一个 droppable 容器**，卡片是 draggable item。
- 必须实现 `onDragOver` 处理跨容器移动，`onDragEnd` 才落状态，否则跨组拖过去会瞬移回原位。
- 移动端加 `TouchSensor`（`activationConstraint: { delay: 150, tolerance: 5 }`），否则页面无法滚动。

## 5. 名单解析规则（v1）

输入格式（接龙常见）：

```
1. 目
5. 浩鸣   李斌
15. 啸安➕狼兴
22. 啸阳（狼泽）
26. 啸森——狼俊
28. 狼明+浩龙
46.  啸宇 + 狼俊
54. 狼辰—浩杰
```

解析算法：

1. 去掉行首序号：`/^\s*\d+\s*[.、)]?\s*/`
2. 按分隔符切分：`空格` `+` `➕` `（` `）` `——` `—` `-`
3. **第 1 个 token = 参赛主播**，其余 token = **队长/师傅**（仅标注，不参赛）
   - 理由：`狼兴` 在 11 号已单独出现，15 号 `啸安➕狼兴` 若算两人会重复；`浩龙` 同理出现在 8 号与 28 号。故后缀名是归属关系。
   - ⚠️ 此规则需业务确认，做成**可配置项**（`leaderMode: 'suffix' | 'both'`）。
4. 归一化后匹配 `person.name`：精确 → 去空格/全角半角/繁简 → 模糊（Top3 候选）
5. 未命中：标红，允许手动填音浪或绑定已有 person，或排除出分组。

按此规则：**55 人参赛，53 人命中库，2 人待确认（`目`、`阿楠`）**。

## 6. 分组算法

### 6.1 蛇形均衡（默认）

保证各组**总音浪**接近，而不是人数平均：

```ts
const G = Math.ceil(N / maxSize);        // 55 人 / 8 = 7 组
sorted = players.sort(desc by wave);
for (i in sorted) {
  const round = Math.floor(i / G);
  const idx   = i % G;
  const g = round % 2 === 0 ? idx : G - 1 - idx;  // S 型折返
  groups[g].push(sorted[i]);
}
```

效果：第 1 名和第 14 名同组、第 2 名和第 13 名同组……各组总量自然收敛。

### 6.2 可选策略

| 策略 | 说明 |
|---|---|
| `snake` | 蛇形均衡（默认） |
| `random` | 随机（抽签感，PK 常用） |
| `snake-no-master` | 蛇形 + **同门回避**：`person.master_id` 或解析出的队长相同的尽量不同组，冲突时局部交换 |

### 6.3 均衡度指标（拖拽时实时显示）

- 各组总音浪 `S_i`
- 极差比 `(max - min) / mean` —— < 5% 优秀，< 15% 可接受
- 标准差 `σ`

## 9.5 实现状态（v1 已落地）

代码已按本设计实现并跑通，与设计的差异：

| 项 | 设计 | 实际 |
|---|---|---|
| 本地库 | better-sqlite3（需原生编译） | **`node:sqlite`**（Node 26 内置，零依赖零编译） |
| 只读第二层 | 连接级 `SET TRANSACTION READ ONLY` | 移除（mysql2 pool 的 `on('connection')` 回调是 callback 版连接，会污染连接池导致请求挂起），改为纯应用层 `queryReadonly` 守卫 |
| 音浪口径 | 三选一 | `lastN`（天数可调，默认 3）+ `total`（全期求和） |
| 数据事实修正 | 认为 `daily_metric.wave` 是差分 | 实测 **wave 即当日音浪值**（与 `cumulative_wave` 同值，属导入冗余），9-21 首日 1490 万、后两天各约 80 万 |

实测结果：54 人参赛（排除"目"）、**54/54 全部命中**；近 3 天合计 1137 万，取最新 1 天合计 56 万（8 人当天无数据）。

## 10. 风险

- 免费版 MySQL 公网连接**慢且连接数极少** → 连接池上限 3、必加缓存，页面 loading 要有预期。
- 数据新鲜度缺口 4~5 天，分组结果取决于采集是否恢复。
- 数据库密码只存在后端 `.env`（已加入 .gitignore），**绝不进前端产物、绝不进仓库**。
