### 4.4 为什么 147 还没切 PG：分支没推、CI 没构建

PG 切换的三次提交全在**本地 `pg-migration` 分支**，远端只有 `main`：

```
02be46b  10-12 14:39  refactor: 拆分超大文件 store.rs / public_teams.rs   ┐
b8d7b16  10-12 14:34  feat: 拉取 147 生产库到本机 PG                      ├ 只在本地
b8c7088  10-12 14:32  feat: 数据库全量切换 MySQL/MariaDB → PostgreSQL     ┘
e77c78f  10-12 12:50  checkpoint: PG 迁移前快照                          ← origin/main 停在这里
```

- `git ls-remote origin` 只有 `refs/heads/main` = `96c7f8b`（比 e77c78f 还早一条）
- `.github/workflows/ci.yml` 只在 `push: branches: [main]` 和 PR 到 main 时触发
- `scripts/deploy/147.sh` 的流程是「等 CI 绿 → 触发 `amd64-bundle.yml` → 从 rolling release 下载镜像包 → `docker load` 取出二进制和前端替换」

所以**即使现在跑 `scripts/deploy/147.sh`，推上去的仍是 MySQL 版二进制**。

### 4.5 切 PG 到 147 需要补的东西

1. 分支推送到远端（或合并进 main）并让 CI 构建出新 bundle
2. 147 上加 PG 服务（容器或系统包）——当前 `docker-compose.yml` 里没有
3. 把 `pk.env` 的 `DB_LOCAL_*` / `DB_WRITER_*` / `DB_MIGRATOR_*` 从 `3306 + pk_reader/douyin_writer/douyin_migrator` 改成 PG 的端口与账号
4. 用 `scripts/mysql2pg.py` 把 147 的 `douyin` 库（24 表 / 13 迁移）转进 PG，并补齐 015–018 迁移（147 缺 `person.phone` 等）
5. 回滚预案：`pk-server.bak-<ts>` / `web.bak-<ts>` 已在 `deploy/147.sh` 里自动留，数据库侧需手工 dump

> 注意：本机 `deploy/docker-compose.yml` 已改成 `pk-postgres`，但那份是**给 64 用的**（文件头注释写明「部署到 64」），不是 147。147 跑 systemd + 静态目录，不用这个 compose。
