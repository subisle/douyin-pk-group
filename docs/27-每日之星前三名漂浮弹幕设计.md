## 1. 需求理解与范围

### 1.1 用户原话

> 「准备做一下这个漂浮的弹幕效果。为每日之星前三名的」

本稿把这句话落成可实现的规格：

- **「每日之星前三名」= 当日榜（每日之星榜）的第一、二、三名**，即页面上领奖台的冠军/亚军/季军三个人。
- **「漂浮的弹幕效果」= 三枚弹幕胶囊从右向左飘过页面，并带轻微上下浮动**；不是视频弹幕那套「观众评论」，而是**荣誉展示 + 动效**。
- 场景：主播/观众打开展示端看数据时，第一眼看到今天前三名的名字飘过 —— 强化「每日之星」的存在感。

### 1.2 本期做 / 不做

| 做 | 不做 |
| --- | --- |
| 展示端数据看板每日口径的弹幕浮层 | 视频/直播弹幕、评论、发送弹幕输入框 |
| 前三名（冠军/亚军/季军）的奖杯 + 头像 + 艺名 + 音浪 | 月榜/年榜、累计榜的弹幕 |
| 后台开关 + 速度/间隔/范围/内容显隐 | 用户自定义弹幕颜色/皮肤 |
| 与选中日期联动（切日期跟着换人） | 服务端推送/实时弹幕（WebSocket） |
| 降级、`prefers-reduced-motion`、性能暂停 | 单独的管理端预览页面（可后续加） |

### 1.3 非目标

- 不改 `/daily` 接口的既有字段与语义。
- 不改推送/日报图里的「🚩 每日之星」口径（那套仍是**单星**，见 §4.2）。
- 不引入任何外网资源（奖杯图沿用页面里已内嵌的 base64，头像沿用 `/api/public/avatars/` 同源图）。

## 3. 总体方案

### 3.1 数据流

```
GET /api/public/teams/{team}                GET /api/public/teams/{team}/daily?date=
        │  starDanmaku 配置                        │  items（含 rank/avatar/wave）
        ▼                                          ▼
   site.starDanmaku ────────────────►  starDm.refresh()
                                            │  1) enabled? 2) view==='data'? 3) period==='daily'?
                                            │  4) reduced-motion? 5) 有 1~3 名？
                                            ▼
                                   取 rank=1/2/3 各第一个人（与 podHtml 同口径）
                                            │  内容签名变了才重启
                                            ▼
                            #starDm 浮层：每轮生成 3 枚 .sd-item
                                            │
                              CSS 右→左漂移 + 上下浮动，animationend 清理
                                            │
                                    mode=loop → 等 intervalSec 再来一轮
                                    mode=once → 本页生命周期只跑一轮
```

### 3.2 关键设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 数据来源 | 复用 `/daily` 的 `items` | ① 零新增请求/接口；② 与同页领奖台、榜单**必然一致**；③ 后台的「音浪/时长显隐」开关天然生效；④ 已排除已删/离团/隐藏的人 |
| 是否联动 `star_override` | **不联动** | `star_override` 是「手动颁奖」的单星（如争霸赛冠军），套到「前三名」会串味；弹幕固定取当日榜前三，避免运营改一个单星配置导致弹幕换人（§4.2 详述） |
| 播放节奏 | 默认「循环，60s 一轮」；可切「每页一次」 | 循环才有「弹幕」的持续感；60s 足够稀疏、不烦人；运营可切一次性 |
| 关闭方式 | 后台总开关 + 系统级 reduced-motion 自动关 | 本期不做页内「关闭弹幕」按钮（会引入 localStorage 状态与误触，见 §13 Q3） |
| 实现技术 | DOM + CSS `transform` 动画（3 个节点） | 比 canvas 简单、可复用奖杯/头像/样式；3 条弹幕的规模 CSS 足够，且 `prefers-reduced-motion` 好处理 |
| 位置 | 页面上部浮层（头部/工具栏下方区域） | 不遮挡榜单首屏核心信息（领奖台），又能在滚动前看到 |

### 3.3 页面效果示意

```
┌────────────────────────────────────────────────────┐
│  masthead（毛玻璃吸顶：标题 / DATA 日期 / 公告行）      │  z 30
├────────────────────────────────────────────────────┤
│  toolbar（口径 tab / 日期条 / 搜索）                  │  z 8（吸顶）
│                                                     │
│   🚩每日之星 🥇(头像) 张三 · 12万3456 ──────────▶   │  ← 车道 1（冠军，紫金）
│        🥈(头像) 李四 · 9万8000      ──────────▶    │  ← 车道 2（银）
│   🥉(头像) 王五 · 7万1000        ──────────▶       │  ← 车道 3（铜）
│  ───────────────────────────────────────────────   │
│   领奖台 + 榜单（可滚动）                              │
└────────────────────────────────────────────────────┘
```

> 方向：从右向左（`translate3d` 由 `100vw` 附近飘到 `-100%` 之外）；三枚弹幕各占一条车道，错峰入场。

## 4. 数据口径

### 4.1 「前三名」的严格定义

**取当日榜 `items` 中 `rank === 1 / 2 / 3` 的第一个人**（`hasData !== false`），与 `podHtml()` 完全一致：

```js
// 与 podHtml 的 pick(r) 同口径；不按数组前三个硬切，避免并列/缺位时与领奖台不一致
const pick = (r) => listAll.find(x => x.hasData !== false && x.rank === r);
const stars = [pick(1), pick(2), pick(3)].filter(Boolean);
```

- **并列名次**（同分同名次，`daily` 现有口径）：`rank=1` 有两人时，领奖台只展示 `find` 到的第一个；弹幕同样只取第一个 —— **弹幕与领奖台永远同一批人**，不会出现「弹幕三个人、领奖台另外三个人」的错位。
- **缺位**：只有 1~2 名有数据 → 只飘 1~2 条，不补空位、不占空车道。
- **0 条**（当天没人有数据 / 口径被后台关 / 接口失败）→ 整层不出现（不是空浮层）。
- **谁不进榜**：已删、离团、`hide_in_daily_report=1`、当天无采集记录（`rank=0`）都不进 —— 这三类由 `/daily` 的 SQL 保证，前端不再二次过滤名单（只做 `rank>=1` 的判断）。

### 4.2 与「每日之星」单星 / `star_override` 的关系

| 概念 | 现有语义 | 本弹幕是否使用 |
| --- | --- | --- |
| 日报图 / 推送的 🚩 每日之星 | `star_auto()` 当日音浪第一；可被 `star_override`（`称号\|人名\|音浪`）手动改 | **不用** |
| `star_title` 配置（称号，如「初级争霸赛冠军」） | 单星条/庆祝的标题兜底 | **不直接复用**；弹幕自己有 `title` 字段（空 = 「每日之星」），避免「手动指定冠军」把弹幕称号带偏 |
| 当日榜前三（领奖台） | 页面已经展示的冠军/亚军/季军 | **本弹幕的数据源** |

**为什么不用 `star_auto` 的 top3**：`star_auto` 是「单星」服务，SQL 只取 `LIMIT 1`，且不带 `hide_in_daily_report` / `deleted_at` 过滤；扩成 top3 会与页面榜单出现口径差。用 `/daily` 的 `items` 是「所见即所得」。

> 另外：当天榜的 `rank` 只给「有数据」的人，`liveCount`/`teamSize` 也在响应里 —— 设计上不依赖这两个字段，弹幕只看 `rank`。

### 4.3 日期跟随

- 弹幕内容**跟随当前选中的业务日**（`curDate`）：用户在日期条上切到 `10.12`，数据加载完成后弹幕换成 10.12 的前三名。
- 默认日期 = 昨天（页面既有口径），即打开页面看到的是最近一次完整数据的前三名。
- **月/年口径不显示弹幕**（那两套没有「每日之星」概念，且弹幕语义是「今天谁最亮」）。
- 切换日期但内容没变（同一个人、同样音浪）→ **不重启正在跑的那一轮**（内容签名比较，避免静默刷新把动画打断）。

### 4.4 后台显隐开关的叠加

| 后台开关 | 对弹幕的影响 |
| --- | --- |
| `settings.dataEnabled=false` | `/daily` 返回 `dailyEnabled:false`，`listAll` 为空 → 不显示 |
| `settings.daily=false` | 同上（每日榜关） |
| `settings.wave=false` | `wave=null` → 胶囊里**不显示音浪数字**（只显示奖杯+头像+名字），不是显示 0 |
| `settings.duration/trend` | 与本弹幕无关（胶囊不显示时长/涨跌） |
| `team_enabled=false`（团链接关） | 整页 `published:false`，页面本身不可用 → 自然不显示 |

### 4.5 「前三名」是否要包含「今日未开播」的人

**不包含。** `rank=0`（当天没采集记录 / 音浪未达开播阈值）的人不进前三。理由：每日之星是「今天的数据荣誉」，没播的人不该被飘出来。这与领奖台一致。

## 5. 接口与配置契约

### 5.1 配置结构（后端 `Announcement` 新增字段）

```rust
/// 每日之星前三名漂浮弹幕（2026-10-18）
#[derive(Clone, Debug, serde::Serialize, serde::Deserialize)]
#[serde(default)]
pub struct StarDanmaku {
    /// 总开关（默认 false：上线后由运营在后台打开）
    pub enabled: bool,
    /// 称号前缀；空 = 「每日之星」
    pub title: String,
    /// 展示范围：`top3`（默认，冠亚季）/ `top1`（只飘冠军）
    pub scope: String,
    /// 播放方式：`loop`（默认，循环）/ `once`（本页只跑一轮）
    pub mode: String,
    /// 循环间隔秒（mode=loop 生效；15..3600，默认 60）
    pub interval_sec: i64,
    /// 飘动速度 px/s（30..160，默认 70）
    pub speed: i64,
    /// 胶囊里是否显示头像
    pub show_avatar: bool,
    /// 胶囊里是否显示音浪
    pub show_wave: bool,
}

impl Default for StarDanmaku { /* enabled:false, title:"", scope:"top3",
    mode:"loop", interval_sec:60, speed:70, show_avatar:true, show_wave:true */ }
```

挂到 `Announcement`：

```rust
pub struct Announcement {
    // ...既有字段不动...
    #[serde(default)]
    pub star_danmaku: StarDanmaku,
}
```

**序列化口径**：

- 存库 JSON 用 `snake_case`（`starDanmaku` 作为键名，字段 `intervalSec` 等已在前端 camelCase；后端 serde 用 `rename_all = "camelCase"` 或逐字段 rename —— **二选一，实现时与 `AnnounceItem` 的现有风格对齐**：现有 `Announcement` 的 JSON 是 camelCase（`placements` 内字段原样），本结构统一用 camelCase，避免管理端再转一层）。
- `GET /api/admin/announcement`（`to_json`）增加 `starDanmaku` 键，永远带**归一化后的完整对象**（不省略字段）。
- `POST /api/admin/announcement` 支持 **部分更新**：只传 `starDanmaku` 里的部分字段就只改这些字段，缺省保持原值（与 `celebrate`/`placements` 同语义）。
- `load_effective()` **不做**内存合成（不参与「items 为空时按 celebrate/champ 合成」那套迁移逻辑）。

### 5.2 公开下发

**只加在 `GET /api/public/teams/{team}`（site 接口）**，与 `celebrate`/`items` 同级：

```json
{
  "published": true,
  "celebrate": { "...": "..." },
  "items": [ "..." ],
  "starDanmaku": {
    "enabled": true,
    "title": "",
    "scope": "top3",
    "mode": "loop",
    "intervalSec": 60,
    "speed": 70,
    "showAvatar": true,
    "showWave": true
  }
}
```

- 无论 `enabled` 真假都下发**归一化后的完整对象**（前端按 `enabled` 判断即可；老前端忽略新键不受影响）。
- **不**加到 `GET /api/public/announcements`：弹幕只在登录后的展示页看板出现，登录页不需要；若将来运营要「登录门也有」，再按同一结构补下发（结构已可复用）。
- 前端兜底：`site.starDanmaku` 缺失（老后端）→ 视为 `enabled:false`。

### 5.3 管理端保存与归一化

`update_announcement` 内新增一段（与 `celebrate` 同风格）：

| 字段 | 归一化规则 |
| --- | --- |
| `enabled` | 只认 bool；缺省保留旧值 |
| `title` | `trim` + 截断 24 字符；空串 = 「每日之星」 |

### 6.3 JS 控制器（约 120 行，IIFE，避免全局污染）

```js
/* ==================== 🚩 每日之星前三名漂浮弹幕（2026-10-18） ====================
   数据：复用 loadData() 的 listAll（/daily items），与 podHtml 同口径取 rank 1/2/3。
   时机：loadData 成功 / switchView / setPeriod / visibilitychange 时调用 refresh()。
   生命周期：seq 令牌防过期回调；stop() 清 DOM + 定时器；一页同时最多 3 个节点。 */
const starDm = (() => {
  const RM = window.matchMedia ? window.matchMedia('(prefers-reduced-motion: reduce)') : { matches:false };
  let seq = 0, timer = null, lastSig = '', shownOnce = false;

  const cfg = () => (site && site.starDanmaku) || { enabled:false };
  const box = () => $('starDm');
  const eligible = () => {
    const c = cfg();
    return !!c.enabled && view === 'data' && period === 'daily' &&
      !document.hidden && !RM.matches && listAll.length > 0 &&
      !($('gate') && !$('gate').classList.contains('hidden'));
  };
  const pick = (r) => listAll.find(x => x.hasData !== false && x.rank === r);
  function stars() {
    const c = cfg();
    return (c.scope === 'top1' ? [pick(1)] : [pick(1), pick(2), pick(3)]).filter(Boolean);
  }
  function sig(list) { return list.map(x => x.rank + ':' + x.name + ':' + x.wave).join('|'); }
  function stop() {
    seq++; clearTimeout(timer); timer = null;
    const el = box(); if (el) { el.innerHTML = ''; el.classList.add('hidden'); el.classList.remove('sd-paused'); }
  }
  function itemHtml(it, i, first) {
    const c = cfg();
    const av = it.avatar
      ? '<span class="sd-av" data-n="' + esc(it.name) + '"><img src="' + esc(it.avatar) +
        '" alt="" loading="lazy" decoding="async" referrerpolicy="no-referrer"></span>'
      : '<span class="sd-av" style="' + avSoft(it.name) + '">' + esc(String(it.name || '?').charAt(0)) + '</span>';
    const wave = (c.showWave !== false && it.wave != null)
      ? '<span class="sd-wv">' + wan(it.wave) + '</span>' : '';
    return '<div class="sd-item sd-rank-' + it.rank + '" style="--sd-lane:' + i + '">' +
      '<span class="sd-bob">' + (TROPHY_SRC[it.rank] ? '<img class="sd-cup" src="' + TROPHY_SRC[it.rank] + '" alt="">' : '') +
      (first && c.title !== null ? '<span class="sd-tag">' + esc((c.title || '').trim() || '每日之星') + '</span>' : '') +
      av + '<span class="sd-nm">' + esc(it.name) + '</span>' + wave +
      '</span></div>';
  }
  function run() {
    const my = ++seq, c = cfg(), list = stars();
    if (!list.length) { stop(); return; }
    if (c.mode === 'once' && shownOnce) { stop(); return; }   // 每页一次：已跑过就不再开
    const el = box(); if (!el) return;
    el.innerHTML = '';
    el.classList.remove('hidden');
    const speed = Math.min(160, Math.max(30, +c.speed || 70));
    list.forEach((it, i) => {
      const html = itemHtml(it, i, i === 0);
      // 错峰入场：0 / 0.8s / 1.6s
      setTimeout(() => {
        if (my !== seq) return;
        el.insertAdjacentHTML('beforeend', html);
        const node = el.lastElementChild;
        if (!node) return;
        const dur = (window.innerWidth + node.offsetWidth + 60) / speed;
        node.style.setProperty('--sd-dur', dur.toFixed(2) + 's');
        node.style.animationDelay = '0s';
        node.addEventListener('animationend', () => node.remove(), { once:true });
        // 头像破图兜底（与榜单同一套）
        node.querySelectorAll('img[src]').forEach(img => {
          if (img.classList.contains('sd-cup')) return;
          img.onerror = () => { const p = img.parentElement;
            if (p) { p.innerHTML = esc(String(p.dataset.n || '?').charAt(0)); p.style.cssText = avSoft(p.dataset.n || ''); } };
        });
      }, i * 800);
    });
    // 一轮结束（最后一条过屏）后再排下一轮
    const per = Math.max(3000, (window.innerWidth + 260) / speed * 1000);
    const wait = (c.mode === 'once') ? 0 : Math.max(15000, Math.min(3600000, (+c.intervalSec || 60) * 1000));
    if (c.mode === 'once') shownOnce = true;
    timer = setTimeout(() => {
      if (my !== seq) return;
      if (!eligible() || c.mode === 'once') { stop(); return; }
      run();
    }, per + wait);
  }
  function refresh() {
    const list = eligible() ? stars() : [];
    const s = sig(list);
    if (!list.length) { stop(); lastSig = ''; return; }
    if (s === lastSig) return;      // 内容没变：正在跑的轮次不打断
    lastSig = s;
    stop();
    timer = setTimeout(() => { if (eligible()) run(); }, 900);  // 等数据渲染落一拍
  }
  return { refresh, stop };
})();
```

接入点（三行）：

1. `loadData()` 末尾 `renderList()` 之后 → `starDm.refresh();`
2. `switchView()` 里 `go()` 之前/之后 → `starDm.refresh();`（离开数据页时 `refresh()` 内部会 `stop()`）
3. `setPeriod()` 末尾 → `starDm.refresh();`
4. 全局：`document.addEventListener('visibilitychange', () => { if (document.hidden) starDm.stop(); else starDm.refresh(); });`

> 说明：上述代码是**意图级伪实现**，落地时按 `st_page.html` 的现有风格（`esc`/`avSoft`/`wan`/`TROPHY_SRC` 已存在）整理；`insertAdjacentHTML` 前的无用行删掉，`mode=once` 的 `shownOnce` 逻辑收紧为「本页只跑一轮」。

### 6.4 生命周期与时机

| 事件 | 行为 |
| --- | --- |
| 页面启动 / 登录后 `bootRest` | 等 `loadData()` 成功、`listAll` 有值 → `refresh()` → 约 0.9s 后开跑 |
| 切日期 | `loadData()` 覆盖 `listAll` → `refresh()`；内容签名变了 → 停旧的、开新的；没变 → 不打断 |
| 切月/年口径 | `setPeriod` → `refresh()` → `eligible()` 为假 → `stop()` |
| 切到 我的/分组/族谱 | `switchView` → `refresh()` → `stop()`；切回数据页且每日口径 → 重新开跑 |
| 静默刷新（`bootRest` 定时） | 数据没变 → 不打断；变了 → 无缝换一轮 |
| 页面切后台（`visibilitychange`） | `stop()`（清 DOM + 定时器）；切回前台 → `refresh()`（约 1s 后重开） |
| 登录门弹出（token 失效） | `refresh()` 中 `#gate` 可见 → `stop()`；重新登录后自然恢复 |
| `prefers-reduced-motion` | 不渲染（CSS 隐藏 + JS `eligible()` 为假双保险） |
| 页面卸载 | 无需特殊处理（定时器随页面销毁）；`beforeunload` 不必加 |

### 6.5 与现有弹层的层级

| 层 | z-index | 弹幕相对关系 |
| --- | --- | --- |
| toolbar（吸顶） | 8 | 弹幕在其下方开始（`top` 已让位） |
| masthead | 30 | 弹幕不盖头部（`top` 从头部下方算） |
| **弹幕层** | **35** | — |
| toast | 40 | toast 在弹幕之上（提示更优先） |
| 日历弹层 | 50 | 之上 |
| 族谱全屏 | 60 | 之上 |
| 水印 | 70 | 之上 |
| 公告弹窗 | 89 | 之上（弹窗打开时弹幕被盖住，且弹幕 `pointer-events:none` 不影响翻页） |
| 登录门 | 90 | 之上 |
| 消息弹窗 | 95 | 之上 |
| 引导公告 | 100 | 之上 |
| 彩带 canvas | 9999 | 之上（庆祝彩带仍然最顶） |

> 不用更高的 z-index：弹幕是「气氛」，任何需要用户处理的弹层都应压过它。

### 6.6 性能与内存

- 同时最多 **3 个 DOM 节点**，用 `transform` 动画（合成层，不触发布局）。
- `animationend` 即 `remove()`，不累积节点。
- 定时器只有 1 个（下一轮）+ 每轮 3 个错峰 `setTimeout`；`seq` 令牌保证过期回调直接返回。
- `document.hidden` 时清空；长挂机（后台标签页）不耗 CPU。
- 不轮询、不发请求：数据已由 `loadData()` 拉过。
- 3 条弹幕对低端机的开销可忽略；若实测卡顿，把 `will-change` 保留在 `.sd-item` 即可（已加）。

| 参数 | 值 | 说明 |
| --- | --- | --- |

### 7.3 动效曲线与 paused

- 横向：`linear`（匀速，弹幕标准口味）。
- 浮动：`ease-in-out infinite alternate`。
- 暂停：`.sd-paused` 同时作用于 `.sd-item`（横移动画）与 `.sd-bob`（浮动动画），`animation-play-state:paused`。
- 不使用 `requestAnimationFrame` 手写动画：3 条弹幕用 CSS 更省、更稳。

### 7.4 响应式

| 断点 | 调整 |
| --- | --- |
| ≥ 430px（大屏手机/桌面） | 默认规格 |
| 360~429px | 车道高 46px；`#starDm` 高 150px |
| ≤ 359px | 车道高 44px、`#starDm` 高 138px；胶囊字号 -0.5px；名字 `max-width:6.5em` |
| 横屏 / `height < 500px` | 车道收成 2 条（只飘冠军+亚军）或 `#starDm` 高度 118px，避免压住领奖台 |

> 领奖台在首屏下部，弹幕浮层只占上部 ~150px，不遮挡核心信息；用户滚动时弹幕固定（`fixed`），继续飘。
>
> 浮层会从领奖台区域飘过（弹幕本质是覆盖层）。若视觉评审觉得压住了冠亚季军头像，可把 `#starDm` 的 `top` 整体下移 40~60px，或把车道高收一档 —— 纯 CSS 参数，不影响逻辑。

### 7.5 可访问性

- `aria-hidden="true"`：纯装饰，不进无障碍树。
- 无焦点、无按钮、`pointer-events:none`：不抢点击、不影响读屏。
- `prefers-reduced-motion: reduce`：**完全不渲染**（不是关动画留静态条 —— 静态条也会挡视线）。
- 对比度：冠军紫金底白字 ≥ 4.5:1；亚/季军深字白底 ≥ 7:1。

## 9. 边界与降级

| 场景 | 预期行为 |
| --- | --- |
| 后台总开关关 | 不渲染；`refresh()` 立即 `stop()` |
| 老后端（无 `starDanmaku` 字段） | 前端视为 `enabled:false`，不渲染、不报错 |
| 当天 0 人有数据 / 接口失败 | 不渲染；不出现空浮层 |
| 只有 1~2 人有数据 | 只飘 1~2 条，其余车道空着 |
| 并列名次 | 与领奖台同口径取 `find` 到的第一个；不做「并列双冠军」特殊展示 |
| 后台关音浪（`wave=null`） | 胶囊不显示数字（不是 0）；`showWave=false` 同理 |
| 头像 404/无图 | 首字圆点兜底，不出现破图 |
| 艺名超长 | 8em 省略号（`title` 属性可选，不做 hover 交互） |
| 在「我的/分组/族谱」页 | 不显示（回到数据页再出现） |
| 月/年口径 | 不显示 |
| 登录门打开 / token 失效 | 不显示（层在门之下，且 `eligible()` 检查 gate） |
| 公告弹窗打开 | 弹幕被 89 层盖住；弹窗翻页不受影响（弹幕不接收事件） |
| 页面切后台 | 停止并清理；回前台重开 |
| `prefers-reduced-motion` | 不渲染 |
| 快速连点日期（并发请求） | 只认最后一次 `listAll`（`loadSeq` 已有）；弹幕内容签名比较，不重复开轮 |
| 内容签名相同但用户切走再切回 | 切回时 `refresh()` 重新开轮（`stop` 过 → `lastSig` 重置策略：切走时清 `lastSig`） |
| 同一页面多次 `refresh()` | `seq` 令牌 + `clearTimeout`，永远只有一组定时器 |
| 网络断开后恢复 | 静默刷新拿到新数据 → 自然换一轮；拿不到 → 维持/停止（不报错） |

> 实现细节：`stop()` 时把 `lastSig=''`，确保「切走再切回」能重新开轮；否则会被「内容没变」误判而不出现。

## 12. 风险与回滚

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 循环弹幕打扰阅读 | 主播/观众觉得烦 | 默认 60s 一轮、3 条、速度 70；后台可切「每页一次」或直接关；不挡点击 |
| 低端机掉帧 | 滚动榜单卡顿 | 只 3 个节点 + `transform`；`document.hidden` 暂停；实测卡就默认关或只飘冠军 |
| 视觉与页面风格不搭 | 显得廉价 | 复用现有紫金/毛玻璃/奖杯/头图语言；不引入新色 |
| 与公告弹窗/登录门叠层冲突 | 弹幕盖住弹窗或挡住按钮 | z-index 35；`pointer-events:none`；打开弹层时被自然盖住 |
| 口径误解（运营以为是「手动冠军」） | 配了 `star_override` 但弹幕不跟着换 | 管理端文案写明「取当日榜前三，与领奖台一致」；文档 §4.2 |
| 老后端/老配置兼容 | 反序列化失败/页面白屏 | `#[serde(default)]` + 前端 `site.starDanmaku` 缺失兜底；不需要迁移 |
| 字体/图标加载 | 奖杯是内嵌 base64，无外部依赖 | 零外网，无新增资源 |

**回滚**：后台关「每日之星漂浮弹幕」总开关即可（无需发版）；若前端本身有问题，回滚 `st_page.html` 的 T3 提交即可（后端字段留着不碍事）。
