## 1. P0（3 条，均经主流程核实）

### P0-1 · `plans.days` 类型漂移 → 方案列表恒空、已发布方案页 404 ✅ 已实机复现
`rust/crates/pk-server/src/store/mod.rs:227`（读取点 `routes.rs:417`、`public.rs:177/462`）

`plans.days` 是 **INT4**（`001_core.sql:267`，实库 `information_schema` 确认 `integer`），
但 `map_plan` 用 `r.try_get::<i64, _>(3)?` 读。sqlx 0.8 的解码前类型检查是精确匹配
（i64 只兼容 INT8）→ 每行都返回 `ColumnDecode` → `map_plan` 整体 Err。

错误被**静默吞掉**：`list_plans` 用 `.map(...).filter_map(Result::ok)`（`mod.rs:268`），
Err 直接丢弃、连 `Err(e) => tracing::error!` 分支都到不了；`get_plan` 的 `.ok()` 同理。

**实机复现**（库内 44 个方案、其中 2 个 `published=1`）：
```
GET /api/public/plans      → {"items":[]}
GET /api/public/plans/46   → 404 {"error":"展示页不存在或已下架"}   (published=1)
GET /api/public/plans/45   → 404
```
服务端日志里**没有任何相关错误**，运营侧完全无声。写路径（`save_plan`/`set_published`
走 `RETURNING id`）不受影响 —— 现象正是「上架成功、前台永远打不开」。

影响面：展示端 `st_page.html:3023/3052` 真的在调这两个接口，属**用户可见功能全坏**。

修复：`try_get::<i32, _>(3)? as i64`；`filter_map(Result::ok)` 改显式 match + error 日志
（否则同类漂移还会无声）；补一条真 PG e2e 断言 `days`/`published` 往返正确。

> 另注：`docs/21:166`「无遗留类型漂移」的结论**作废**。

### P0-2 · 忘记密码重置仍是免鉴权账号接管 ✅ 已确认（**这是本项目组本轮自己的不完整修复**）
`rust/crates/pk-server/src/public_teams/my.rs:716,737` + `store/my_account.rs:1053-1090`

2026-10-14 上一轮的修复**只把新密码从「手机号后四位」换成 CSPRNG 随机串**，
但入口身份问题一点没动，而且把随机密码**原样回显给调用者**：

- `my.rs:712-716` 只从请求体读 `phone` —— 无 token、无短信、无归属校验；
- `store/my_account.rs:1065-1067` 仅按 `WHERE phone = ? AND phone <> '' AND is_admin = 0` 定位账号；
- `my.rs:737` `Ok(Json(json!({ "ok": true, "password": password })))` —— **明文返回新密码**。

上一轮我写的注释「展示端只把本次响应里下发的新密码回填一次，攻击者拿不到」
（`my_account.rs:1080`）推理不成立：**攻击者就是调用者本人**。

后果：任何知道某主播手机号的人，`POST /api/public/my/password/reset {"phone":"<该号>"}`
即可拿到新密码并登录接管；同时 `my.rs:729-731` 会吊销该账号全部 my token（把受害者踢下线）。
端点仅受 `ensure_register_open` 与 12次/分/IP 限流约束，而注册开关在有真实自助账号时必然开着。

修复方向（需产品拍板，见 §4）：
1. **身份绑定**：校验 WorkBuddy OAuth 完成态（服务端调 `wb.login_poll` 并核对返回手机号）或服务端短信验证码；
2. **响应绝不回显密码**：只回 `{ok:true}`，新密码走已绑定微信私聊下发，或改由管理员后台执行；
3. 按手机号 + IP 双维度限流，并写管理员可见审计记录。

同类：`push_state` 用 `.ok().flatten()` 把错误吞成 None → 「我的」页推送卡从「已绑定」翻成「未绑定」；

**不会 panic、不会 500，是「静默降级 + 假成功」**，比崩溃更难发现。
场景真实可达：DDL 不随启动自动跑（需显式 `pk-server migrate`），`MIGRATE_ON_BOOT` 默认关
且失败只 error 不阻断启动。本机 `douyin_dev` 已跑 022，但**生产 `douyin` 是否已跑无法从本机验证**。

修复：store 层做缺列兼容（捕获 SQLSTATE 42703 回退旧查询），或启动时校验 schema、
缺列则拒绝启动/健康检查降级；`push_bindings_for_team` 改返回 `Result`，
让失败能让 `push_job` 标 failed，**不允许假成功**。

#### ⚠️ 已知残留风险（如实记录，未消除）

**知道某主播的手机号 ⇒ 可以重置该账号并把新密码拿到手 ⇒ 可以登录接管该账号，并把本人踢下线。**

- 随机化密码**不能**解决这一点：随机化只挡住了「攻击者自行推算密码」（旧口径 = 手机号后四位），
  挡不住「接口直接把新密码告诉你」；
- 手机号在公会内部半公开（台账、群聊、主播之间互相知道），不是秘密；
- 无短信通道 = 服务端无法证明「重置请求来自号码本人」，这是**产品已确认接受的残留风险**，
  不是修好了；本轮只是把攻击面收窄（去掉自助开号这个放大器）；
- 真正收口仍需服务端短信验证码或 OAuth 归属校验（§4 选项 3），或改由管理员后台重置（选项 1）。
  两条都没做。

**已做的补偿**（代码内注释同口径，`store/my_account.rs::my_account_reset_password_random`）：
重置范围只认 `is_admin=0` 的普通账号（管理员观看账号不能被顺带接管）；日志不打账号名与全量手机号；
改动密码后旧 token 立刻失效。

### 6.2 口径二：个人页「设置自定义密码」（已登录）

- 接口：`POST /api/public/my/password`，请求头 `X-My-Token`，体 `{"oldPass":"...","newPass":"..."}`；
- 身份**只**认 token，**请求体不接受任何账号名** —— 杜绝「拿自己的 token 改别人的密码」；
- 成功：`200 {"ok":true,"token":"<新的 my token>"}`。旧 token **全部吊销**，同时给当前用户换发
  同身份（person_id / 团别原样保留）的新 token，避免用户刚改完密码就被自己触发的吊销踢回登录门；
- 失败：`400`（当前密码不正确 / 新密码不能和当前密码相同 / 密码必须是 4~20 位字母或数字 /
  该账号不支持自助改密——未登记密码或属管理员观看账号）、`401`（登录已过期，含内存 miss 时
  从 Redis 回填的 24h 登录态）；
- 限流复用登录门写接口档（每 IP 每分钟 5 次，改密要跑 argon2）；
- 展示端：`st_page.html` 的「我的」页原「重置密码」对话框已改成这个（三个输入：当前密码 /
  新密码 / 确认新密码），**已登录场景不再走手机号重置**。
