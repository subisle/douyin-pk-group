# 14 · 个人页「一人多抖音号」音浪需求

> 版本 v2 · 2026-10-12 · 需求 + 已落地代码
> 目标：一个主播 = 一个姓名 + 一个手机号 + 一个微信推送 bot，但**可以有多个抖音号**；
> 个人（「我的」）页要能看到**每个抖音号**各自的日 / 月 / 年 / 累计音浪，微信 bot 推送的

> 追分目标支持「追人 + 自定义分数」——见 §6-§8。

## 1. 一句话问题

运营侧的真实形态是「**一个人挂好几个抖音号**」：主号带副号，音浪分散在多个号上。
但展示端「我的」页和微信日报**只有一个总数**（按 `person_id` 聚合），主播看不到
「今天哪个号挣了多少」，想停播某个号、想核对平台数据都对不上。
同时身份侧没有硬约束：同一个主播理论上能开两个登录账号、绑两个微信 bot，
推送会重复发、水印会打两个人。

三件事要一起解决：

| # | 问题 | 本方案的答案 |
|---|---|---|
| 1 | 一个主播能开多个账号 / 绑多个 bot | §2：数据库软唯一 + 代码预检，**一人一号一 bot** |
| 2 | 一个主播有多个抖音号，但个人页只有一个总数 | §3：`/my/accounts` 接口 + 「我的」页分号卡片 |
| 3 | 微信日报只有总数，看不出哪个号挣的 | §4：日报追加「我的抖音号」明细段 |

## 2. 一人一个姓名 · 一个手机号 · 一个微信 bot

### 2.1 三个「一」的落点

| 约束 | 落在哪张表 | 软唯一写法 | 为什么软唯一 |
|---|---|---|---|
| 一个主播一个登录账号 | `my_accounts.person_id` | `GENERATED ALWAYS AS (NULLIF(person_id, 0))` + UNIQUE | `person_id = 0` 是「未绑定 / 管理员观看账号」的哨兵（015 定的语义），多人都是 0，不能互相挡 |
| 一个手机号一个人 | `person.phone`（016 已有）、`my_accounts.phone`（012 已有） | 同款 `NULLIF(x, '')` | 空串 = 未登记，不参与唯一 |
| 一个微信 bot 一个人 | `wx_push_accounts.person_id` | `NULLIF(person_id, 0)` + UNIQUE | 同上哨兵语义 |
| 一个微信不被两个人扫 | `wx_push_accounts.ilink_user_id` | `NULLIF(ilink_user_id, '')` + UNIQUE | 历史行该列可能为空（老账号从未激活过） |

**存量有冲突时不建索引**（沿用 012 / 015 / 016 的先例）：迁移只做 `information_schema`
探测 + `PREPARE/EXECUTE` 动态 DDL，检测到重复就 `SELECT 1` 跳过，
**不让迁移失败卡住部署**。运维清理完重复后按 §2.3 补建。

### 2.2 代码侧预检（写路径）

唯一索引是最后一道防线，但 `Duplicate entry` 对运营是天书。三条写路径都要**先查再写**，
给出人话文案：

| 函数 | 场景 | 文案 |
|---|---|---|
| `store::my_accounts_batch_open` | 该主播名下已有账号 | 已有账号→按 skip / forceReset 语义处理，不插第二行 |
| ~~`store::my_account_register`~~ | ~~同名主播已占号 / 手机号已占（已有预检）~~ —— **该函数已于 2026-10-14 随自助注册移除**；同名／手机号占用的查重口径现由后台开号路径承担（`store::my_account_set` / `my_accounts_batch_open` 的 `PhoneClash` 文案） | 历史留档 |
| `store::wx_push_account_save` | 该微信已绑给别人 / 该主播已有 bot | 「该微信已绑定过别的账号」/「该主播已绑定微信推送」 |
| `store::bind_inner` | 绑定目标已挂别的账号 | 管理员改绑：先解绑旧账号再绑新目标（保持不变量)；自助绑定：拒绝 |

**自己更新自己不算冲突**：`wxpush.rs` 的 `supervisor_loop` / `ensure_account` 会反复
save 同一个账号，查重必须排除自身 `name`，否则幂等性被破坏。

### 2.3 运维：存量冲突怎么清

```sql
-- ① 找重复（人 → 多个账号）
SELECT person_id, COUNT(*) n, GROUP_CONCAT(name) names
  FROM my_accounts WHERE person_id <> 0 GROUP BY person_id HAVING COUNT(*) > 1;
-- ② 找重复（微信 → 多个人）
SELECT ilink_user_id, COUNT(*) n, GROUP_CONCAT(name) names
  FROM wx_push_accounts WHERE ilink_user_id <> '' GROUP BY ilink_user_id HAVING COUNT(*) > 1;
```

人工决定留哪一行（一般留 `bound=1` / 最近 `updated_at` 的那条），删掉其余，再补建索引
（补建 SQL 与迁移里的 `IF` 判定同款，见 `018_identity_uniqueness.sql` 注释）。

## 3. 个人页：每个抖音号的日 / 月 / 年 / 累计

### 3.1 接口 `GET /api/public/teams/{team}/my/accounts`

登录态与既有 `/my` 一致（`X-My-Token` 头或 `?token=`）。

```json
{
  "published": true,
  "date": "2026-10-11",
  "accounts": [
    { "accountId": 12, "anchorId": "abc123", "douyinNo": "cyl765", "anchorName": "浩龙",
      "primary": true,
      "daily":   { "wave": 12345 },
      "monthly": { "wave": 234567 },
      "yearly":  { "wave": 3456789 },
      "total":   { "wave": 9999999 },
      "liveToday": true, "lastDate": "2026-10-11", "days": 9 }
  ],
  "summary": { "count": 2, "daily": {...}, "monthly": {...}, "yearly": {...}, "total": {...} }
}
```

| 字段 | 口径 |
|---|---|
| `date` | 最新**业务日**（`get_available_dates[0]`），不是自然日 —— 数据每晚补前一天，用自然日会在凌晨显示全 0 |
| `daily/monthly/yearly/total` | 该账号的音浪；**后台关掉对应展示开关 → `null`**（不给 0，与 `/my` 的可反推口径一致） |
| 有号但当天没播 | 给 **0**（不是 null）—— 只有开关关闭才 null |
| `liveToday` | 当日音浪 ≥ 2（与全站「未播」口径一致） |
| `lastDate` / `days` | 该号最后有数据的业务日 / 有数据的天数；没数据 → `null` / `0` |
| `primary` | `account.is_primary = 1` |
| `summary` | 所有号加总，与 `/my` 大数字卡口径一致 |
| `published: false` | 后台关了该团 → 整张卡不渲染 |

### 3.2 聚合口径（必须一人多号不重复计）

与 `dialect.rs` 的 `WAVES_A` **完全同源**，不得另发明口径：

- **主号**（`account.is_primary = 1`）→ `daily_metric`，且 `d.anchor_id = a.anchor_id`、只算 `wave_reliable = 1`；
- **副号**（`is_primary = 0`）→ `wave_snapshot.wave_value`（**当日值**语义），按 `anchor_id` JOIN 回 `account`；
- 两边 UNION ALL 后按 account 分组做条件聚合（`SUM(CASE WHEN 日期=…)`），**一个号只能落一边**。

排序：主号在前，其余按 `account.id`（与 `admin.rs` 台账 `ORDER BY is_primary DESC, id` 一致）。

### 3.3 展示端卡片（`st_page.html` 的「我的」页）

- 位置：大数字卡之后、系统服务列表之前；标题「我的抖音号」+ 右侧「共 N 个」。
- 一行一个号：左「抖音号 + 主号 chip + 今日开播状态」，副标题「最后有数据日期 · N 天有数据」，
  右侧四格数字（日 / 月 / 年 / 累计），窄屏排 2×2，`tabular-nums` 对齐。
- 只有一个号也显示（不特判隐藏）；**0 个号 → 空态**「还没有绑定抖音号」。
- `wave` 为 `null` 显示「—」，**不显示 0**。
- **降级**：接口报错不能拖垮整个「我的」页 —— 照 `loadMy()` 既有风格 try/catch 吞掉，
  卡片位置显示灰色小字「抖音号数据加载失败」。
- 样式只复用既有 `.st-my-*` class 与 CSS 变量，不引新配色、不引新依赖（该页面无构建步骤，
  纯内联 HTML/CSS/原生 JS）。

## 4. 微信 bot 推送：日报带分号明细

`push.rs` 的每日报告在「我：第 N 名 · X」之后追加一段：

| 号数 | 行为 |
|---|---|
| 0 个 | 不加（保持原样） |
| 1 个 | **不加**（本来就只有自己，重复） |
| ≥2 个 | 追加明细段 |

```
我的抖音号（2 个）
· cyl765（主号） 日 1.2万 / 月 12万 / 年 88万
· abc123 日 3000 / 月 4.5万 / 年 30万
```

- **显示名优先级：`douyin_no` → `anchor_id`（带 `ID ` 前缀），不再用抖音昵称兜底**
  （2026-10-12 用户口径「推送多个号带着抖音号」）：`anchor_name` 是抖音昵称，常常等于主播艺名
  （生产里 `狼佑`/`狼沐`/`狼征` 就是），一人多号时几行全同名，收件人分不清哪个号是哪个 ——
  等于没带抖音号。库里 126 个号有 24 个没登记抖音号，这条路径真实存在。主号后缀「（主号）」。
- 排序：当日音浪降序（日报语境下最有用），全为 0 时退回月音浪。
- **超过 5 个只显示前 5**（2026-10-12 从 3 提到 5：用户要求多个号都带着抖音号，
  折掉就看不见号了；生产实测一人最多 3 个号，5 是留余量），其余折叠成一行「…等 N 个号」。
- 数值一律 `fmt_wan`（推送口径：一律用万）。
- **失败降级**：取数失败退回不带明细的原文案 + `tracing::warn!`，**不中断整个推送循环**，
  也不破坏 `run()` 的分批节拍（`batch_size()` / `batch_interval_secs()`）。

## 6. 「我的」页战队排名：只显示自己的排名（2026-10-12）

### 6.1 用户口径

「我的」页大数字卡下方显示「战队排名」时，只显示本人名次：

- 显示 `第 N 名` 或 `暂未上榜`；
- 不再显示 `共 X 人`；
- 不再显示 `距上一名差 X`。

### 6.2 为什么后端要同步收紧（不是前端藏）

`teamSize + teamRank`、`rankGap` 这类字段可以和公开榜单交叉反推团队分布：
例如知道自己是第 10 名、共 104 人、距第 9 名差 X，就能推出前几名的音浪量级区间。
这与既有「`wave=null` 防反推」的安全约定一致：**可反推的一律不下发**。

### 6.3 契约

| 字段 | 2026-10-12 后 |
|---|---|
| `teamRank` | 保留：本人团内累计音浪名次（0 = 未上榜） |
| `teamSize` | 恒 `null`（字段保留位置，老前端读 `null` 不崩） |
| `rankGap` | 恒 `null`（同上） |

实现同时删除了 `teamSize` 的 COUNT 查询与 `rankGap` 计算（`rank_sql` 保留给 `teamRank`）。
展示端也同步改为不读取这两个字段，避免半改状态下闪旧文案。

## 7. 族谱页音浪：只看徒弟 + 日 / 月 / 年口径（2026-10-12）

### 7.1 用户口径

族谱页「音浪」不再展示历史累计全量，而是：

1. **只显示自己徒弟的音浪**：对普通主播来说，师傅节点上的「门下累计」就是自己 + 所有徒弟/徒孙的窗口音浪；
2. **支持三种口径**：日 / 月 / 年，与全站榜单一致；
3. **无徒弟显示「暂未收徒」**；
4. **移除全局统计与激励文案**：管理员观看的多根树不再展示「公会在册 / 代际分支 / 累计音浪」这类全局概览卡与激励性说明。

### 7.2 接口契约

`GET /api/public/teams/{team}/lineage`

| 参数 | 口径 |
|---|---|
| `period` | `daily`（默认，当天 = 最新业务日）/ `monthly`（本月累计）/ `yearly`（本年累计）；非法回落 `daily` |
| `date` | `YYYY-MM-DD` 直选某一天；`monthly` / `yearly` 以该日期所在月 / 年为窗口。必须通过 `chrono::NaiveDate::parse_from_str` 校验，且在业务日白名单（`get_available_dates`）内；非法回落最新业务日 |
| 响应顶层新增 | `period`（实际生效口径）、`date`（daily 口径用的业务日；monthly/yearly 给该窗口最后一天）、`viewerIsAdmin` |

音浪 SQL 从全量累计改为窗口过滤，仍只算 `wave_reliable = 1`：

```sql
-- daily 示例
WHERE wave_reliable = 1 AND DATE_FORMAT(biz_date, '%Y-%m-%d') = '2026-10-09'
-- monthly
WHERE wave_reliable = 1 AND DATE_FORMAT(biz_date, '%Y-%m') = '2026-10'
-- yearly
WHERE wave_reliable = 1 AND DATE_FORMAT(biz_date, '%Y') = '2026'
```

节点 `wave` 为窗口个人音浪，`totalWave` 为窗口内「自己 + 所有子孙」的门下累计。
`lineage_wave_summary(...)` 签名不变：`my()` 的徒弟统计仍走历史累计，避免族谱日期口径污染个人页。

### 7.3 展示语义与安全口径

- 普通主播：仍能看到全团树结构，但页面语义是「自己徒弟的音浪」；无徒弟（直系徒弟数为 0）时展示端显示「暂未收徒」。
- 管理员：`viewerIsAdmin = true`，仍可看全组树；前端据此不渲染多根全局统计概览卡与激励文案。
- 无业务日（库里没数据）时 `date=""`，SQL 不带窗口条件但结果为空；不会因日期参数报错。
- 防注入：`date` 必须过 `chrono::NaiveDate::parse_from_str` 形状校验后才进 SQL（照 `push.rs::is_biz_date`），再由业务日白名单兜底。

## 8. 追分设置：自定义分数（万）与追人分数（2026-10-12）

### 8.1 用户口径

原 `person` 目标只能「超过他本人本月累计」；现在要支持「**追某个人，并且还要超过他多少分**」：
用户可以选人后填一个目标分（万），不填则维持旧行为。

### 8.2 输入 / 存储 / 评估

| 输入 | 后端行为 |
|---|---|
| `kind=person`、不传 `targetWan` | 旧行为：`target_value=0`，`target_name=对方姓名`，推送按对方本月累计 |
| `kind=person`、`targetWan > 0` | `target_value = round(targetWan * 10000)`；`target_name = "{对方姓名} · {fmt_wan(target_value)} 万"` |
| `targetWan <= 0` / 非数字 | 400 `目标分要大于 0（万）` |
| 上限 | `targetWan <= 100000000`（防误输入单位） |
| 重复 | 同一 `kind=person` + `target_person_id` 已存在仍拒绝，不重复建档 |

`my_targets` 表无需迁移：复用既有 `target_value` / `target_name` 列。

### 8.3 wxbot 推送文案

`push.rs::eval_target` 口径：

- `target_value > 0`：按该固定分对比，忽略对手实际本月涨跌；
- `target_value = 0`：按对手本月累计（旧口径）。

实际效果示例：

```
输入：张三，targetWan=50
我本月累计 200000，张三本月实际只有 100000
推送：· 距「张三 · 50 万」还差 30 万（你 20 万）
```

```
我本月累计 600000
推送：🚀 已追上「张三 · 50 万」！
   你 60 万
```

`target_name` 是展示文案的单一事实源（`targetName`），页面列表与 wxbot 都读它；
数字统一走 `fmt_wan`，保证「距『张三 · 50 万』还差 X」这类句子通顺。

## 9. 不做的事（明确范围外）

| 项 | 为什么不做 |
|---|---|
| 副号的**时长** | `wave_snapshot` 没有时长列，`duration_snapshot` 也只有整月口径；分号明细只给音浪 |
| 分号维度的**追分目标** | 追分口径是「本月累计 person 级」（docs/08 §4.5），拆到号上要重定义目标语义，另开需求 |
| 管理端「我的」页也显示分号 | 管理端是 `apps/douyin-web`，本次只做手机展示端 `st_page.html` 与推送 |
| 手机号变更留痕 | docs/13 §7.3 已定：直接覆盖可接受，要留痕时上 `person_contacts` 子表 |
