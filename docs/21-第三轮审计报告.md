## 已修复（本轮）

### P0-1 · 无鉴权密码重置 = 任意账号接管
`public_teams/my.rs:621` + `store/my_account.rs:1050`

`POST /api/public/my/password/reset` 挂在 `/api/public/` 下免管理员鉴权，handler 内也
不要任何身份证明。原实现只要知道（或猜到）主播手机号，就把该账号密码重置成
**手机号后四位**并明文回显 —— 忘记密码流程完全没有身份绑定，等于任意账号接管 +
强制踢下线。手机号在公会内部半公开，且新密码可自行推算。

修复三处：
1. 受注册开关 `my_register` 约束（与注册同口径，关注册即一并关重置）；
2. 新密码改 CSPRNG 随机串（`random::random_password()`），不再可从手机号推导；
   —— 展示端 `st_page.html` 早已按「后端下发随机临时密码」写文案与回填，本次是
   **后端对齐前端**，不是改前端；
3. 日志不再打账号名：未绑定 / 自助注册账号的 `name` 就是手机号本身，
   `mask_phone` 的脱敏被 `accounts = ?names` 绕过，改打 `names.len()`。

### P0-2 · wx_sessions 写入不存在的列，主动推送链路整体瘫痪
`store/wx_sessions.rs:16` + 迁移 `001_core.sql:350-356`

`wx_sessions` 只有 4 列（conversation_id / to_user_id / context_token / nickname），
代码却写了 5 列（多 `updated_at`）。PG 严格列检查 → 每次私聊入站都失败，而错误被
`let _ =` 完全吞掉、零日志。后果：上下文 100% 写不进库 → `wx_session_get` 恒 None →
**主动推送（追分提醒 / 每日报告）整条链路失效**。这是全库唯一一处「代码写迁移里
根本不存在的列」（对比 `wx_push_accounts.updated_at` 实有其列，属漏改）。

修复：去掉该列（无代码读它）+ 把 `let _ =` 改成 `if let Err(e) = ... tracing::error!`。

### P0-3 · 迁移 020 从未注册 + wave_snapshot 唯一索引撞名
`migrate.rs:79` + `001_core.sql:123/:329`

两条独立缺陷叠加：
- `020_fix_index_collisions.sql` 存在于磁盘，但 `include_str!` 从未引用 →
  `pk-server migrate` **永不执行它**，索引撞车一个都没补上。
- `001_core.sql:123` 与 `:329` 用了同名 `uk_anchor_date` 指向**两张不同的表**。
  PG 索引名在 schema 内全局唯一，`IF NOT EXISTS` 只认名字 → `:329` 静默跳过，
  **wave_snapshot 至今没有 (anchor_id, biz_date) 唯一索引**。
  实打实的后果：`.dbmerge/merge.py` 灌库用 `ON CONFLICT (anchor_id,biz_date)` +
  `ON_ERROR_STOP=1` → 整轮灌库在此终止；且无唯一约束 = 音浪快照可重复插入，
  聚合口径（dialect.rs / minutes.rs / push.rs）重复计音浪。020 也没覆盖这条。

修复：新增 `021_fix_wave_snapshot_unique.sql`（不撞车的新名字补建，旧错名索引保留），
并把 020、021 一起登记进 `MIGRATIONS`。
**另加防回归测试** `migrate::tests::every_migration_file_is_registered`：枚举
`src/migrations/*.sql`，断言每个文件都被登记。已实测能捕获漏登记（注入 999_probe.sql → 红灯）。
原来的「编号连续且无重复」测试防不住这种漏登记 —— 它只检查已登记项之间的关系。
