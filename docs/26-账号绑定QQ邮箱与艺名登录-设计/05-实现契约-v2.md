# 05 · 实现契约 v2（2026-10-18 用户拍板后冻结）

> 本文件是**并行实现的唯一契约**。`01~04` 是设计分册，与本文件冲突处**以本文件为准**。
> 用户 2026-10-18 拍板：
> 1. **凭艺名直接认领开号**（无账号主播可用艺名认领，认领即建号）；
> 2. **没有绑定 QQ 的找管理**（QQ 不强制，绑定提醒保留，重置必须有 QQ）；
> 3. **临时密码登录后提示修改密码**（提示层 + 强制进入改密；不做单次消费）；
> 4. **密码支持中英文、特殊字符、任何符号**；
> 5. **同一 QQ 不能绑定多个账号**；
> 6. **艺名唯一**。

## 2. 存储层契约（`store/my_account.rs`，T1 实现）

### 2.1 QQ 号与密码

```rust
pub const QQ_MAIL_DOMAIN: &str = "@qq.com";

/// 去空白；5~12 位 ASCII 数字；首位非 0；兼容 "123456@qq.com" 剥后缀。
pub fn normalize_qq(raw: &str) -> Result<String, String>; // BIZ:: 前缀

pub fn qq_to_email(qq: &str) -> Result<String, String>;   // "123456@qq.com"
pub fn qq_from_email(email: &str) -> Option<String>;      // 非 QQ 域名 → None
pub fn is_qq_email(email: &str) -> bool;

/// 2026-10-18 用户口径：4~64 个字符，允许中英文/特殊字符/任何符号（含空格）；
/// 不允许 ASCII 控制字符（\x00-\x1F、\x7F）。**不 trim**（首尾空格是密码的一部分）。
pub fn validate_my_password(pass: &str) -> Result<String, String>; // BIZ:: 前缀

/// 用户名沿用现有规则（非空、≤20 字）；密码改走 validate_my_password。
pub fn validate_my_account(name: &str, pass: &str) -> Result<(String, String), String>;

/// 展示端统一脱敏：QQ 邮箱 → "123***@qq.com"（本地部分保留前 3 位，不足 3 位保留首位）；
/// 非 QQ 邮箱 → 沿用 mask_email 口径（首字符 + "***@域名"）；空串 → 空串。
pub fn mask_qq_email(email: &str) -> String;
```

### 2.4 登录（含临时密码）

```rust
pub struct LoginOutcome {
    pub name: String,
    pub person_id: i64,
    pub team: String,
    pub temp_used: bool,       // true = 本次用临时密码登录
}

pub enum LoginFail { BadPassword, NoAccount, TempExpired }

/// 现有签名保留但返回 LoginOutcome；逻辑：
/// 1) 手机号路径命中 → 校验常密码；失败再试临时密码；
/// 2) 姓名路径命中 → 同上；
/// 3) 都没命中 → NoAccount。
/// **密码不 trim**。临时密码有效期内可重复使用（不消费），命中即置 must_change_pass=1。
pub async fn my_account_check_login(st, account, pass) -> Result<LoginOutcome, LoginFail>;

pub enum TempPassResult { Valid, Expired, Mismatch }

/// 临时密码校验：合法且未过期 → 置 must_change_pass=1 并返回 Valid；
/// 已过期 → 惰性清空 temp 两列并返回 Expired；不匹配 → Mismatch。
pub async fn my_account_temp_pass_try(st, name, input: &str) -> Result<TempPassResult, String>;

/// 清空临时密码与强制改密标记（改密成功 / 管理员改密 / 解绑 QQ 时调用）。
pub async fn my_account_clear_temp(st, name) -> Result<(), String>;
```

## 3. HTTP 契约（`public_teams/*`，T2 实现）

### 3.1 登录 `POST /api/public/my/login`、`POST /api/public/teams/{team}/verify`

请求不变 `{account | name, pass}`（pass 不 trim）。

成功（两个接口同形；`verify` 额外保留 `switchable`）：

```json
{ "ok": true, "token": "…", "personId": 1027, "name": "狼佑", "team": "male",
  "bound": true, "needBind": false, "needProfile": false, "needQq": true,
  "mustChangePass": false, "phone": "199****1234", "emailMask": "" }
```

失败（仍 HTTP 200 + `ok:false`）：

```json
{ "ok": false, "code": "BAD_PASSWORD", "error": "密码错误" }
{ "ok": false, "code": "NO_ACCOUNT",  "error": "账号还没开通", "canClaim": true, "claimName": "狼佑" }
{ "ok": false, "code": "TEMP_EXPIRED", "error": "临时密码已过期，请重新获取" }
```

`canClaim` 仅在「账号不存在 + 艺名唯一 + 可认领」时为 true；前端据此显示「认领账号」按钮。

### 3.2 认领 `POST /api/public/my/claim`（新增）

请求 `{ "name": "狼佑", "pass": "任意密码" }`；成功与登录同形（`needProfile:true`、`needQq:true`、`token`）。
失败 400（BIZ 文案）：艺名不存在 / 重复 / 已离团 / 已认领 / 密码不合法；并发撞主键 → 400「账号已存在，请直接登录」。

### 3.3 首次补全 `POST /api/public/my/profile/bind`（新增）

请求 `{ "phone": "13800138000", "qq": "12345678", "newPass": "可选" }`（`qq`/`newPass` 可省略）。
成功同登录形（`needProfile:false`，`needQq` 按是否绑 QQ）。
失败 400：`INVALID_PHONE` / `PHONE_TAKEN` / `INVALID_QQ` / `QQ_TAKEN` / `INVALID_PASS` / `PROFILE_ALREADY_DONE`；401 过期；429 限流（每 IP 5 次/分）。

### 3.4 绑定 QQ `POST /api/public/my/email`

请求 `{ "qq": "12345678" }`，`{ "qq": "" }` = 解绑；兼容旧 `{email}`（只接受 `@qq.com`）。
成功 `{ "ok": true, "emailMask": "123***@qq.com" }`；失败 400 `INVALID_QQ` / `QQ_TAKEN` / `NEED_PROFILE`；401。

### 3.5 忘记密码 `POST /api/public/my/password/reset`

请求 `{ "phone": "…", "qq": "…" }`。
成功 `{ "ok": true, "sent": true, "expiresInMinutes": 15, "emailMask": "123***@qq.com" }`。
错误：400 `INVALID_PHONE` / `RESET_MISMATCH`（统一文案，未绑 QQ 也用它）；429；503 `SMTP_UNAVAILABLE`。
顺序：IP 限流 → 手机号格式 → 同号窗口闸 → 双因子匹配 → 生成临时密码 → 发信 → 落库 → 吊销 token。
被同号闸抑制时回**同形成功包**（`emailMask:""`），不发信、不改库。

### 3.6 改密 `POST /api/public/my/password`

请求 `{ "newPass": "…" }`；成功 `{ "ok": true, "token": "…", "mustChangePass": false }`；清三列、吊销旧 token 换发新 token。密码规则走 `validate_my_password`。

### 3.7 `GET /api/public/teams/{team}/my/who`

原有字段 + `needProfile` / `needQq` / `mustChangePass` / `emailMask`；**不再下发明文 email**；未绑主播分支 `name` 回艺名（无艺名回空串），`phone` 脱敏。

### 3.8 管理端 `GET/POST /api/admin/my-accounts*`

- 列表项新增 `emailMask`、`qqBound`、`mustChangePass`；
- 管理员设密码后清临时态（store 已做）；
- 单条 GET 同步返回上述字段。

### 3.9 中间件

- **不做** `mustChangePass` 的 403 拦截（用户口径是「提示修改」；前端弹提示层）。
- `needProfile` 的 403 拦截同样不做：前端登录后强制引导，后端仅对 `profile/bind` 做 `phone=''` 守卫。
- 保留现有地区门禁、登录日志、重置限流、改密写口限流。

## 4. 前端契约（`st_page.html`，T3 实现）

1. **登录门**：placeholder「手机号 / 艺名」；密码**不 trim**；失败文案按 code 显示。
2. **认领**：登录返回 `canClaim:true` 时，在登录卡下方显示「首次登录？认领账号“狼佑”」；点击弹出认领弹窗（艺名只读 + 设置密码 + 确认密码，规则 4~64 任意字符）→ `POST /my/claim`；成功后按登录成功处理（进强制引导）。
3. **强制引导（needProfile）**：不可关闭的一屏卡：手机号（必填，可预填 `person.phone`）、QQ 号（**选填**，提示「没有 QQ 邮箱请联系管理员」）、新密码（选填；留空沿用当前密码）→ `POST /my/profile/bind`；成功后换 token、重拉 who。
4. **QQ nudge（needQq）**：登录后首次必弹 + 7 天冷却 + 单会话一次；可「以后再说」；文案含「没有 QQ 邮箱？联系管理员」。我的页常驻入口。
5. **忘记密码**：弹窗输入手机号 + QQ 号 → `POST /my/password/reset`；成功提示「15 分钟内有效」；失败统一提示「手机号与 QQ 号不匹配，或未绑定 QQ 邮箱（请联系管理员）」。
6. **临时密码登录**：`mustChangePass:true` 时弹「请修改密码」提示层：主按钮「立即修改」（打开改密对话框）、次按钮「稍后」；改密成功清除标记。
7. **我的页**：QQ 邮箱行显示 `emailMask`；修改/解绑；解绑二次确认 + 风险提示。绑定成功用响应 `emailMask` 回填。
8. **密码规则**：4~64 字符、可中英文/特殊字符/任意符号；前端提示不要 trim；改密对话框同步。
9. 图标子集补 `mail`（`scripts/fonts/subset-material-symbols.py` + 重跑），否则页面出现字面文本。
