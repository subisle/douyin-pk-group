# 26-③ 展示端交互设计：账号绑定 QQ 邮箱与艺名登录

> **需求来源：2026-10-17 用户口径**（原文要点）：
> ① 本地进行开发，账号支持绑定邮箱，**填写 QQ 号码即可，发送到对应的 QQ 邮箱，自动添加后缀**；
> ② 没绑定账号的**支持艺名登录**；如果没绑定手机号，**提示用户绑定 QQ 号码和手机号码然后设置密码**；
> ③ 已经绑定的用户**弹窗提示绑定 QQ 号码**；
> ④ 忘记密码 = **重设密码需要输入手机号和 QQ 邮箱**，然后发送**临时密码**到他的邮箱。
>
> **本文范围**：只设计展示端单文件页面 `rust/crates/pk-server/src/public_teams/st_page.html`（7634 行，CSS + HTML + JS 全内联）的交互与落地改动点；不改管理端、不新增页面路由、不新增前端构建产物。
> **契约口径**：页面调用的接口与字段见 §7。本目录 **`02-登录绑定与重置流程.md` 已定稿**（下称「②」），本文所有字段名、接口路径、错误码均按 ② 对齐：状态字段为 `needProfile` / `needQq` / `mustChangePass`，脱敏邮箱字段为 `emailMask`，强制引导接口为 `POST /api/public/my/profile/bind`，忘记密码为 `{phone, qq}`，绑定 QQ 为 `{qq}`。② 未覆盖的纯交互项（弹窗频控、动效、移动端细节）由本文定义。
> **视觉口径**：沿用现有登录门 iOS 卡风格——主色 `#0066FF`（登录门内为字面量，见 `st_page.html:1459/1465/1475`）、slate/gray 灰阶、输入框与主按钮圆角 12px（`st_page.html:73` 的 `--r-md:12px`、`1462`、`1475`）、登录卡圆角 28px（`1442`）、移动端 375×667 优先。

## 2. 忘记密码弹窗（手机号 + QQ 号 → 临时密码发 QQ 邮箱）

点击登录门「忘记密码？」→ 在登录门之上打开一张卡（**不是新页面**）。实现照 `openMyPwdDlg()` / `openMyEmailDlg()` 的既有模式（`4256-4274`、`4325-4347`）：`document.createElement('div')` + `position:fixed; inset:0; z-index:96` 的半透明遮罩 + 卡体复用 `.gate-box`（`1441-1446`）+ 全局 `toast`（`2210-2215`）。z-index 取 **96**：高于 `#gate`(90) 与 `#msgModal`(95)，低于 `#announce`(100)。

### 2.2 字段与实时校验

| 字段 | id（建议） | 规则 | 前端处理 | 提示 |
|---|---|---|---|---|
| 手机号 | `fpPhone` | `^[0-9]{5,20}$`（与后端 `validate_my_phone` 同口径，`store/my_account.rs:141-154`） | `inputmode="numeric"`，`input` 时剔除非数字、`maxlength=20`；失焦 trim | 行内：「手机号应为 5~20 位数字」 |
| QQ 号 | `fpQq` | `^[1-9]\d{4,11}$`（5~12 位、首位非 0，与 ② §3.2 一致） | `inputmode="numeric"`，剔除非数字、`maxlength=12`、首位不接受 0；右侧固定后缀 `@qq.com`，输入时下方实时显示「将发送到 `123456@qq.com`」 | 行内：「QQ 号应为 5~12 位数字，且不能以 0 开头」 |
| 提交按钮 | `fpGo` | 两个字段都通过本地校验才可点（`disabled`） | 按钮禁用态沿用 `.go:disabled{opacity:.45}`（`1223`）；字段下方常驻规则 hint，避免「按钮灰着不知道为什么」 | — |

> **为什么校验阈值是 5~20 / 5~12**：手机号 5~20 位是现有后端硬口径（`store/my_account.rs:141-154`），照抄保证前后端一致；QQ 号 `^[1-9]\d{4,11}$` 是 ② §3.2 第 6 步的新口径（5~12 位且不以 0 开头）。**两处都必须只收数字**，不做「+86」「国际区号」处理（本系统是内部展示端）。

### 2.3 提交与状态

| 状态 | 表现 |

| 初始 | 两个输入框可编辑，按钮禁用（未填全） |

| 加载中 | 按钮 `disabled`、文案「发送中…」；两个输入 `disabled`；遮罩层不关、禁止重复点击 |
| 成功（200） | 卡内内容替换为成功态（见下），不再显示表单；`toast('临时密码已发送到 QQ 邮箱')` |
| 失败 | 卡保持、输入恢复可编辑、错误写入 `.form-err`；按钮复原「发送临时密码」；按钮**不**关闭弹窗 |
| 关闭 | 「取消」、点遮罩、Esc 关闭；关闭时清空输入与错误，避免下次带脏值 |

**成功态卡面（替换表单区，不换整个弹窗）**：

```
┌──────────────────────────────┐
│           ✓（主色圆）          │
│     临时密码已发送             │
│  已发送到 123***@qq.com       │  ← 脱敏展示，规则见 §5.2
│  · 15 分钟内有效                │
│  · 用临时密码登录后，请立即修改密码 │
│  · 没收到？先看垃圾箱；仍没有请联系管理员帅帅 │
│  [        去登录        ]      │  .btn-main，关闭弹窗并聚焦 #gateAcct
└──────────────────────────────┘
```

- 成功态标题只写「临时密码已发送」，**不回显密码**（与 ② §5.3「只存哈希、不回显」一致）。
- 有效期与单次：② §5.3 已定「临时密码 15 分钟有效且只能使用一次」；成功响应带 `expiresInMinutes: 15` 与 `emailMask`，前端优先用响应值渲染，接口缺字段时回落 15 分钟。
- **二级闸抑制也回 200**（② §5.6，`emailMask` 为空串、不发信不改状态）：前端成功态显示「已发送」即可，脱敏邮箱用本地输入 QQ 计算 `maskQq` 兜底；不向用户暴露「被限流」（沿用现有设计 `my.rs:584-595`）。
- 重置成功会吊销该账号全部 my token（`my.rs:632-634`），成功态补一句：「其他设备上的登录会退出」。

### 2.4 失败态映射表（可直接抄进代码）

按 ② §5.6 的**防枚举决策**：只保留「本地可判定」的明确错误，账号不存在 / 未绑手机号 / 未绑 QQ / QQ 不匹配 / 管理员账号全部并入同一个 `RESET_MISMATCH` 文案。

| HTTP / code / 场景 | 后端文案（② 契约） | 前端展示文案 | 依据 |
|---|---|---|---|
| 400 `INVALID_PHONE` | 手机号格式不对：应为 5~20 位数字 | **请输入 5~20 位数字的手机号** | ② §5.6；`store/my_account.rs:141-154` |
| 400 `RESET_MISMATCH`（未绑账号 / 未绑 QQ / QQ 不匹配 / 管理员） | 手机号与 QQ 号不匹配，或该账号未绑定 QQ 邮箱 | **手机号和 QQ 号对不上，或这个账号还没绑定 QQ 邮箱，请核对后重试（忘记绑定 QQ 的联系管理员帅帅）** | ② §5.6 |
| 429 `RATE_LIMITED` | 尝试太频繁，请稍后再试 | **操作太频繁了，请 1 分钟后再试** | ② §5.6；`my.rs:570-572` |
| 503 `SMTP_UNAVAILABLE` | 邮件服务暂时不可用，请稍后重试或联系管理员 | **邮件服务暂时不可用，请稍后再试或联系管理员帅帅（本次没有改密码）** | ② §5.6；现有 `my.rs:614-618` |
| 200（二级闸抑制） | 与成功同形，`emailMask:""` | 按成功态处理（不发信也不改状态，不额外提示） | ② §5.6 |
| 网络错误 / 超时 | — | **网络不太好，请稍后重试** | 前端 catch |
| 本地校验失败 | — | 行内红字（不走请求） | `.form-err` `1469-1474` |

> **安全口径**：采用 ② 的统一 `RESET_MISMATCH` 后，本弹窗**不会**暴露「手机号是否存在 / 是否绑了 QQ」；用户侧代价是「没绑 QQ 的人只看到统一失败」，由文案里的「忘记绑定 QQ 的联系管理员帅帅」兜住。

### 2.5 键盘与可访问性

- 焦点：打开后 30~60ms 聚焦 `#fpPhone`（与 `4281`/`4352` 的 `setTimeout(..., 60)` 一致）。
- Enter：手机号 → 聚焦 QQ；QQ → 若可提交则提交；Esc → 关闭（新增，`keydown` 绑在 mask 上）。
- 遮罩：`role="dialog" aria-modal="true"`，标题 `id` 供 `aria-labelledby`（照 `openMsgModal` 的写法 `6184-6186`）。
- 打开时 `lockScroll()`、关闭时 `unlockScroll()`（`7431-7440`），避免 iOS 背景滚动。

## 3. 首次登录强制引导（绑定 QQ + 手机号 + 设置密码）

### 3.1 触发条件

登录成功（`/my/login`）或恢复登录态（`/my/who`）后，直接读 ② 定义的三个状态字段，**不要在页面里自己算**：

```js
const needProfile  = !!me.needProfile;   // S1：没绑手机号 → 强制引导（② §2.3/§2.5）
const needQq       = !!me.needQq;        // S2：手机号已绑、QQ 未绑 → 可关闭弹窗
const mustChangePass = !!me.mustChangePass; // S4：临时密码登录 → 强制改密
// 优先级：needProfile > needQq > mustChangePass（② §6.2）
```

- 后端判定规则（② §2.5）：`needProfile = !is_admin && !phone_bound`；`needQq = phone_bound && !qq_bound && !needProfile && !is_admin`；`mustChangePass` 读 `must_change_pass=1`。三者互斥优先级以 ② 为准，前端只按上面顺序串行处理，不并发弹两个层。
- `needBind`（账号没绑主播，`2269-2272`）的账号**不进入**本引导：现有「联系管理员」卡（`3778-3793`）才是它的正确出口，先解决主播绑定问题（② §8 补充、Q10）。
- 管理员观看账号（`admin === true`）**不进入**本引导（② §2.5 已把它排除在 `needProfile` 之外）。
- 登录响应已带 `phone/emailMask/needProfile/needQq/mustChangePass`（② §2.3），所以登录成功那一刻就能判定，不用先等一次 who；恢复登录态时用 who（② §2.5 要求两处一致）。

### 3.2 形态选择：复用登录门容器做「第三张卡」（推荐）

**不要另做全屏遮罩**。理由：
1. 登录门 `#gate` 本身就是全屏（`position:fixed; inset:0; z-index:90`，`1438-1440`），复用它可以**天然不可关闭**——`#gate` 上没有关闭按钮，用户点遮罩、按 Esc 都没有出口；
2. 少一层 z-index 叠层，不会和 `#msgModal`(95)/`#announce`(100) 抢层级；
3. 刷新页面后 `boot()` 的 `ensureLogin()`（`2502-2527`）会重新问 `/my/who`，拿到 `needProfile` 就再渲染一次引导卡，**阻断逻辑自愈**，不需要 localStorage 记「引导过没有」。

实现方式：`closeGate(me)`（`2326-2341`）里加分支——若 `needProfile` 则**不隐藏 `#gate`**，把 `#gate` 的 `innerHTML` 换成引导卡（仍包在 `.gate-col > .gate-box` 里），完成后再走原来的「关 gate + resolve」。

```
┌──────────────────────────────┐  #gate：全屏，不关（阻断式）
│  ┌────────────────────────┐  │  .gate-box max-width 390
│  │       绑定账号信息        │  │  h3
│  │  ①QQ 邮箱 ②手机号 ③密码   │  │  .gate-steps（三段胶囊，当前步主色）
│  │ ───────────────────────  │  │
│  │ ① QQ 邮箱                │  │
│  │  ┌────────────┬───────┐  │  │
│  │  │ QQ 号       │@qq.com│  │  │  #obQq + .qq-suffix
│  │  └────────────┴───────┘  │  │
│  │ ② 手机号                 │  │
│  │  ┌────────────────────┐  │  │
│  │  │ 手机号             │  │  │  #obPhone
│  │  └────────────────────┘  │  │
│  │ ③ 设置登录密码            │  │
│  │  ┌────────────────────┐  │  │

│  │  └────────────────────┘  │  │
│  │  ┌────────────────────┐  │  │
│  │  │ 确认密码            │  │  │  #obPass2 type=password
│  │  └────────────────────┘  │  │
│  │  ! 错误行                 │  │  .form-err
│  │  ┌────────────────────┐  │  │

```

**「一屏三步」而不是分步向导**：三步字段总量（QQ + 手机 + 密码 + 确认）在 375 宽下约 300px 高，加上标题/步骤条/按钮总高约 560px，能塞进 667 高的一屏；分步向导要 3 次点击、且中途退出会留下「绑了一半」的半成品。若②坚持分步，本设计的校验/文案/提交逻辑可平移到每一步。

### 3.3 字段校验规则

| 字段 | 前端规则（与 ② 同口径） | 前端提示 | ② 校验依据 |
|---|---|---|---|
| QQ 号 | `^[1-9]\d{4,11}$`（5~12 位、**首位非 0**），只收数字，右侧固定 `@qq.com` | 「QQ 号应为 5~12 位数字，且不能以 0 开头」 | ② §3.2 第 6 步 |
| 手机号 | `^[0-9]{5,20}$`，只收数字 | 「手机号应为 5~20 位数字」 | ② §3.2 第 4 步；`validate_my_phone` `store/my_account.rs:141-154` |
| 新密码 | `^[A-Za-z0-9.]{4,20}$`（与现有改密完全一致） | 「密码必须是 4~20 位字母、数字或点」 | ② §3.2 第 8 步；`st_page.html:4293` |
| 确认密码 | 与新密码逐字符相等 | 「两次输入的密码不一致」 | `st_page.html:4294` |
| 附加校验（前端软提示，不阻断） | 密码不得等于手机号后四位、不得等于 QQ 号、不得全为同一个字符 | 灰色 hint「建议 8 位以上、别用手机号或 QQ 号」 | 产品建议，不写死 |

- **密码强度**：② 沿用统一口令规则（4~20 位字母、数字或点，`validate_my_account`），本次**不提高硬门槛**，避免存量用户改密后登不进；只在引导页给一条灰色建议。
- **不是「预填已绑定值」而是「一次性绑定」**：② §3.2 第 3 步规定 `phone=''` 才能调 `profile/bind`，已绑手机号的账号再调会回 `PROFILE_ALREADY_DONE`「该账号已完成绑定，如需修改手机号请联系管理员」。因此引导页**不预填、不置灰**：进入引导就说明手机号一定是空的，三个字段都是「新填」。若用户刷新期间被别人绑过（极边缘），按该错误码提示并回正常页。
- **前端错误码映射**（② §3.2）：`INVALID_PHONE` / `PHONE_TAKEN`「该手机号已被其他账号绑定，请联系管理员」/ `INVALID_QQ` / `QQ_TAKEN`「该 QQ 邮箱已被其他账号绑定」/ `INVALID_PASS` / `PROFILE_ALREADY_DONE`；429「尝试太频繁，请稍后再试」。前端一律显示后端 `error`（已可直接展示），`code` 只用于分支。

### 3.4 提交、刷新 who、收尾

1. 点「完成绑定，进入数据榜」→ 本地校验 → 按钮 `disabled` + 「提交中…」，三个输入全部 `disabled`。
2. 提交：`POST /api/public/my/profile/bind`，Header `X-My-Token`，Body `{phone, qq, newPass}`（② §3.2 已定**单事务原子接口**，不存在「绑一半」）。
   - 成功：200 `{ok:true, token, personId, name, team, bound, needProfile:false, needQq:false, emailMask}`。
   - 失败：按 §3.3 错误码回显，保持引导卡、输入恢复可编辑；`PROFILE_ALREADY_DONE` 特殊处理——先 `refreshWho()`，若 who 已 `needProfile=false` 就按成功收尾（见第 6 步），否则提示「该账号状态异常，请联系管理员帅帅」。
3. **必须先换 token**：② §3.2「成功后」会 `my_tokens_revoke(name)` 吊销全部旧 token（含当前引导 token），再用原身份换发新 token。前端**必须** `setMyToken(d.token)`（`st_page.html:3708-3717`），否则下一个请求就 401 被踢回登录门（与改密对话框踩过的同一个坑，`4307-4308` 注释）。
4. 然后用响应更新状态并重拉 who：
   - `setMyToken(d.token)`；
   - `GET /my/who` → `applyLoginState(who)`（`2249-2279`）——保证水印从艺名切成打码手机号（`2276`）、`emailMask/needQq/mustChangePass` 与服务端一致；
   - 若 who 失败，至少用 `profile/bind` 响应里的 `phone/emailMask/needProfile` 更新 `meState`，不让页面卡在引导。
5. 关闭 `#gate`（走原来的 `closeGate` 收尾：`innerHTML=''`、resolve Promise、补弹公告引导 `2326-2341`）→ `toast('绑定完成，开始使用吧')` → `bootRest()` 继续。
6. **失败重试**：网络失败可直接重试（后端事务失败无残留）；已成功但前端没收到响应（超时）后再提交会拿 `PROFILE_ALREADY_DONE`，此时按成功处理：先 `refreshWho()`，再关引导。

### 3.5 不可关闭的阻断式细节

| 关闭动作 | 处理 |
|---|---|
| 点遮罩/卡外空白 | 不关（`#gate` 没有点外关闭逻辑；引导卡不绑 mask 点击） |
| Esc | 不绑 Esc 关闭；若全局有兜底，加 `if (guideLocked) return` |
| 浏览器返回键 | 不额外拦截：返回会触发页面重载 → `ensureLogin()` 重新判定 `needProfile` → 再次渲染引导（自愈） |
| 刷新 | 同上，引导再出现 |
| 退出登录 | 不提供「退出」主按钮（避免误触）；只提供底部小字「换个账号登录」→ `myLogout()` + `location.reload()`（与 `4046-4050` 同款） |
| 关闭按钮 X | **不渲染** |

### 3.6 「不能跳过」的文案

- 主按钮下方常驻：**「绑定后才能正常使用（忘记密码、接收通知都要用到 QQ 邮箱和手机号）」**
- 用户若尝试返回/点空白，不弹 toast（没有可点的出口，弹了反而像「可以关」）。
- ② §3.2 把手机号、QQ、密码放在**同一个事务接口**里，因此**前端没有「只绑一部分」的合法路径**；「暂不设置密码」需要②改接口语义（Q1 已作为阻断级问题留给产品）。
- 若用户确实没有 QQ，见 ② §11-Q1（阻断级）：本文前端只能按「必须绑」实现；产品若改为「可先只绑手机号+密码」，引导页隐藏 QQ 段、`needQq` 走 §4 的可关闭 nudge，其余交互不变。

## 4. 已绑定用户「绑定 QQ」弹窗（可关闭）

### 4.1 触发时机与频率

- 触发：登录成功且 `needQq = true`（② §4.1：`needProfile=false && !is_admin && phone_bound && !qq_bound`）。后端 `login` 与 `who` 双处下发同一字段（② §4.1 硬约束），前端两个入口都以该布尔为准，**不用 `email` 是否为空去推导**（存量非 QQ 邮箱会导致误判，② §4.3）。
- 编排位置：`closeGate(me)` 的收尾（`2326-2341`）。**不要**在登录门还没关时弹，否则两层遮罩叠着（文件里已有「引导让位给登录门」的同款教训，`2373-2378`）。推荐 `requestAnimationFrame(() => setTimeout(openQqNudge, 600))`：等 gate 的 `hidden` 生效、首屏数据先出来。
- **频率（推荐）**：
  1. 本次页面会话最多自动弹 **1 次**（`sessionStorage.qqNudged='1'`，关浏览器即失效）；
  2. 用户点过「以后再说」后 **7 天内不再自动弹**（`localStorage.qqNudgeAt=Date.now()`；读取时 `Date.now()-ts > 7*864e5` 才允许再弹）；
  3. 「我的」页入口**常驻**，随时可绑。
  
  即「**首次登录必弹 + 之后 7 天冷却 + 会话内一次**」。比「每次登录都弹」体验好（每天进来看数据被弹一次很烦），比「只弹一次」安全（长期不绑会一直有风险）。最终档位见 Q5。

- **name**：登录名 = 艺名 = `my_accounts.name`（`store/my_account.rs:1204-1262`）。绑 QQ/手机号**不改 name**，因此「我的」页头部资料卡、水印 fallback、榜单口径都不受影响。
- **phone**：服务端打码后下发（`minutes.rs:884-892`）；绑定新手机号后 who 的值会变，前端只用于水印与展示，不写入 localStorage（现状只存 `myName_*`，`2422`）。
- **团别**：绑 QQ/手机号不改变 `team/switchable`，不需要切换逻辑；`applyLoginState` 里换团条的重建（`2255-2268`）照旧。
- **needBind**：未绑主播账号不进入新引导（§3.1），`#bindBar`（`1923`、`2270-2272`）保持原逻辑。
- **mustChangePass（临时密码登录）**：不写 localStorage、不进水印、不改变 `name/phone/team`；只在内存里挂一个 `forcePwd` 标志，改密成功后清掉（`setMyToken` + 刷新 who）。

### 6.6 临时密码登录后的「强制改密」层（② §6.3/§6.4）

触发：`login`/`who` 返回 `mustChangePass=true`，或任意接口 403 `MUST_CHANGE_PASS`（② §6.4 后端双层：写接口统一 403，放行 `who`/`profile/bind`/`/my/password`/登录/重置/登出）。

形态（复用现有改密实现，不新写）：

- 直接复用 `openMyPwdDlg()`（`4247-4316`）：两个密码框 + 前端 4~20 位校验 + `POST /api/public/my/password {newPass}` + `setMyToken(d.token)`，全部现成。
- 改造点：加参数 `openMyPwdDlg({force:true})` → 标题改「请设置新密码」、说明改「你正在用临时密码登录，请先设置自己的登录密码」、**去掉「取消」按钮**、点遮罩不关、Esc 不关（阻断式）；成功后 `close()` + `toast('密码已修改')` + `refreshWho()`。
- 用户没有合法跳过路径；唯一出口是「退出登录」（清 token + reload），避免把人锁死（② §6.4 放行登出）。
- 失败：密码格式/两次不一致行内红字；429 显示后端文案；401 关层回登录门。
- **不要**与 §3 强制引导同时出现：`needProfile` 优先（② §6.2），先引导（其中会设置新密码），完成后 mustChangePass 必为 false。
- **边界：`needQq` 与 `mustChangePass` 同时为 true**（临时密码登录、手机号已绑但未绑 QQ）：② §6.2 的登录响应按 `needQq` 分支只亮一个标志；前端应先 `refreshWho()` 读一次 `mustChangePass`，**改密层优先于可关闭的 nudge**（否则用户点掉 nudge 后写接口全 403，体验更差）。

### 7.3 绑定 QQ：`POST /api/public/my/email`（② §4.2）

- 入参首选 `{qq:"123456789"}`（纯数字，服务端拼 `@qq.com`）；`{qq:""}` = 解绑；旧前端兼容 `{email}`，但前端**只发 `{qq}`**。
- 校验顺序（②）：401 → 429 → 403 `NEED_PROFILE`（S1 账号不许先绑 QQ）→ 解绑直接落库 → `INVALID_QQ`（`^[1-9]\d{4,11}$`）→ `QQ_TAKEN`（邮箱唯一）→ 写入 → 返回脱敏。
- 前端：成功只用 `d.emailMask` / `d.email` 回填（**修正现状 `4370` 用用户输入原值**）；解绑成功后 `emailMask=''`；`needQq=false`。
- 错误文案见 §4.2；429 不自动重试；401 关弹窗回登录门。

### 7.4 忘记密码：`POST /api/public/my/password/reset`（② §5.1/§5.6）

- 入参 `{phone, qq}`（`qq` 必填）；前端本地先按 5~20 / `^[1-9]\d{4,11}$` 校验，不合法不发请求。
- 响应 `{ok:true, sent:true, channel:"qq-mail", expiresInMinutes:15, emailMask:"123***@qq.com"}`；二级闸抑制时同形但 `emailMask:""`（前端用本地 `maskQq(qq)` 兜底显示）。
- 错误：400 `INVALID_PHONE` / `RESET_MISMATCH`；429 `RATE_LIMITED`；503 `SMTP_UNAVAILABLE`（② 明确「不发信、不落库、不改密码、不吊销 token」，所以文案可以说「本次没有改密码」）。
- 成功后的副作用：该账号全部旧 token 被吊销（② §5.2 第 10 步）——**如果用户此刻在别的设备登录着，会被踢下线**，成功态可提示。
- 临时密码规则（② §5.3）：10 位随机、只存哈希、15 分钟、单次、登录后必须改密；前端不接触密码本体。
- ⚠️ **兄弟文档口径冲突**：本目录 ① §3.3 写「30 分钟过期」，② §5.3 写「15 分钟」；用户口径原文是「15 分钟内有效」。本文按 **15 分钟** 写文案，最终以 ①② 统一后的值为准（前端不该写死，读 `expiresInMinutes`，缺失时回落 15）。

### 7.5 强制引导：`POST /api/public/my/profile/bind`（② §3.2）

- 入参 `{phone, qq, newPass}`；单事务写 `phone/email/pass`；**仅当账号 `phone=''` 可调**（否则 400 `PROFILE_ALREADY_DONE`）。
- 成功后：吊销旧 token → **换发新 token**（前端必须 `setMyToken(d.token)`）→ 返回 `needProfile:false, needQq:false, emailMask`。
- 错误码全表与文案：§3.3。
- ② 不提供「分行绑定」接口；本文不再设计 `/my/phone` 之类的额外接口。

### 7.6 错误处理统一收口

`api()`（`2216-2237`）现在的 403 分支只把带 `code` 的错误抛给调用方（`2230-2233`）。本次加两条全局规则：

```js
// api() 内，403 分支
if (d.code === 'MUST_CHANGE_PASS') { openMyPwdDlg({ force: true }); }  // 先弹改密层
if (d.code === 'NEED_PROFILE')     { showGate(); renderProfileGuide(meState); } // 兜底回引导

// 新增文案映射（放 toast 附近，2209 后）
function apiErrText(e) {
  const m = String(e && e.message || ''), c = e && e.code;
  if (c === 'RATE_LIMITED' || /频繁/.test(m)) return '操作太频繁了，请 1 分钟后再试';
  if (c === 'SMTP_UNAVAILABLE') return '邮件服务暂时不可用，请稍后再试或联系管理员帅帅（本次没有改密码）';
  if (c === 'RESET_MISMATCH') return '手机号和 QQ 号对不上，或这个账号还没绑定 QQ 邮箱，请核对后重试';
  if (c === 'PHONE_TAKEN') return '该手机号已被其他账号绑定，请联系管理员帅帅';
  if (c === 'QQ_TAKEN') return '该 QQ 邮箱已被其他账号绑定，请核对后重试';
  if (c === 'PROFILE_ALREADY_DONE') return '该账号已完成绑定，如需修改手机号请联系管理员帅帅';
  if (c === 'UNAUTHORIZED' || /登录已过期/.test(m)) return '登录已过期，请重新登录';
  return m || '操作失败，请稍后重试';
}
```

> 业务错误优先看 `code`（② §8 补充：新增接口必须带 `code`），旧接口无 code 时回落到 `error` 文本；不把原始 SQL/网络错误直接抛给用户。

## 11. 待用户确认问题

> **已由 ② 定稿、本文不再问的项**（照做即可）：艺名登录仍需密码；忘记密码必须同时校验手机号与 QQ；临时密码 15 分钟 + 单次 + 登录后强制改密；脱敏由服务端 `mask_qq_email` 统一；绑定 QQ 入参 `{qq}`；强制引导接口 `POST /my/profile/bind` 单事务；未绑主播账号沿用 `needBind` 不恢复自助绑定主播。

**③ 范围内、需要产品/lead 拍板的问题（按影响从大到小）：**

- **Q1（阻断级，承 ② Q1）没有 QQ 的用户怎么办？** 强制引导要求「QQ + 手机号 + 密码」一次填完；若主播确实没有 QQ，本文前端只能卡在引导。可选：① 一律要求（找管理员代绑）；② 允许先只绑手机号+设密码，QQ 走 §4 可关闭提醒（需 ② 放开 `profile/bind` 的 QQ 必填与 `needProfile` 判定）；③ 允许填其他邮箱（与「QQ 双因子重置」冲突）。**这一条不定，引导页无法最终定稿。**
- **Q2 nudge 频率最终档位？** 本文推荐「首次登录必弹 + 「以后再说」后 7 天冷却 + 单次会话最多一次」；备选「每次登录都弹」「只弹一次」。② §4.1 明确频控由③定义，需确认后写死常量。
- **Q3 忘记密码统一失败文案能否接受？** ② §5.6 选 `RESET_MISMATCH` 统一文案（不泄露手机号存在性），代价是「有账号但没绑 QQ」的用户只看到「手机号和 QQ 号对不上，或该账号还没绑定 QQ 邮箱」——文案已尽量指路，是否够用？
- **Q4 强制引导「换个账号登录」是否保留？** 本文保留为底部小字（清 token + reload），用于设备共享/填错账号；若要求绝对阻断可去掉，但用户填错艺名时会无路可退。
- **Q5 临时密码过期/错误在登录门的文案？** ② §6.1 新增 `LoginFail::TempExpired`「临时密码已过期，请重新获取」；是否需要在登录门额外给一个「重新获取临时密码」的快捷链接（直接打开 §2 弹窗并带上刚才的账号）？
- **Q6 强制改密层是否真的不可跳过？** ② §6.4 已用后端 403 兜底；前端是否也做成「无取消、无 Esc、点遮罩不关」，只留「退出登录」？还是允许「稍后再说」（但仍会被后端 403 拦住，体验更差）？
- **Q7 手机号后续换绑走哪？** ② §3.2 规定 `profile/bind` 只在 `phone=''` 时可用（`PROFILE_ALREADY_DONE`）；换手机号是否只走管理员后台？若用户换号（旧号注销）会永久无法自助重置，需要产品确认兜底流程。
- **Q8 解绑 QQ 后是否立即允许再绑？** 本文不做冷却（解绑成功后 `needQq` 可能变 true）；是否要 7 天内不再自动提醒、或禁止当天重复解绑/绑定？
- **Q9 存量非 QQ 邮箱在「我的」页怎么显示？** ① §1.2 实测本地 `my_accounts.email` **68 行全为空串**（038 从未真实使用），所以本地/当前生产基本不存在存量非 QQ 数据，此项优先级低。若将来出现：UI 选项 ① 行显示「未绑定 QQ 邮箱，去绑定」（忽略旧值，推荐）；② 显示 `a***@163.com` 并加「非 QQ 邮箱，建议更换」。需 ②/产品定 `emailMask` 语义。
- **Q10「我的」页要不要新增「手机号」行？** 当前页面没有任何手机号展示（只有水印用打码值）；用户口径提到「绑定手机号」，建议加一行（打码 + 不可自助改），需确认是否做、以及是否显示「未绑定」引导。
- **Q11 错误提示的粒度**：`PHONE_TAKEN` / `QQ_TAKEN` 会明确告诉用户「这个手机号/QQ 已被别的账号绑了」（可用于探测谁开了号）。内部工具可接受，是否要统一成「该手机号/QQ 暂不可用，请联系管理员」？

## 附录 B · 验收清单（前端侧，可逐条点）

1. 登录门：placeholder 是「手机号 / 艺名」；用艺名能登录；密码错/账号没开通各自文案正确。
2. 忘记密码：点链接弹窗（不再直接发请求）；手机号/QQ 非数字打不进去；QQ 框右侧固定 `@qq.com` 且首位不能是 0；不合法时按钮禁用；提交中按钮「发送中…」；成功态显示 `emailMask` + 15 分钟/单次说明（`emailMask` 为空时用本地 `maskQq` 兜底）；`INVALID_PHONE / RESET_MISMATCH / RATE_LIMITED / SMTP_UNAVAILABLE` 四类失败文案逐一对上（§2.4）。
3. 强制引导：无手机号账号登录后 `#gate` 不关、显示引导；点遮罩/Esc/返回都关不掉；刷新后引导再出现；提交成功后水印从艺名变成打码手机号（说明 who 已重拉）；成功后才进入数据榜。
4. 已绑手机号未绑 QQ：登录成功后弹 nudge；可关闭；「以后再说」后 7 天内不再自动弹；「我的」页入口一直可点；绑定成功后行显示 `123***@qq.com`。
5. 我的页：行文案「QQ 邮箱 / 临时密码发到这个邮箱」；已绑显示脱敏（**不出现明文**）；修改/解绑可用；解绑有黄色风险提示与二次确认；解绑成功后行变「未绑定」，再点可重新绑。
6. 临时密码登录：`mustChangePass=true` 后弹不可关闭的「请设置新密码」层；改密成功后 token 换发、`mustChangePass` 变 false；期间任意写接口返回 403 `MUST_CHANGE_PASS` 也会弹层（不会白屏或只弹 toast）。
7. 交互：所有弹窗 Enter 能提交、Esc 能关（引导/强制改密除外）；请求中不能重复提交；401 关闭弹窗回登录门；375×667 下无横向滚动、按钮不被键盘遮住。
8. 回归：登录、忘记密码、我的页其它行（消息设置/追分/重置密码/关于）、退出登录、换团条、水印、管理员消息弹窗都不受影响。
