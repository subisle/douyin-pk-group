# 02 · 融合架构设计（Rust 单后端）

> 2026-10-02 修订（v2）：目标环境 RK3318，后端统一为 Rust 单技术栈。
> v1 的「Go + Rust 双服务」已由 `docs/04-统一技术栈决策.md` 取代。

## 1. 目标

把「抖音数据管理」（采集 / 导入 / 机器人 / 主播台账）与「PK 分组程序」（分组 / 展示 / 方案）
融合进本仓库，跑在 RK3318 上，后端只用一个 Rust 进程 `pk-server`。

## 2. 架构总览

```text
浏览器 (React；过渡期 apps/web 管理后台 + 展示页，
        统一后台目标落在 apps/douyin-web，见 docs/00 §7)
        │  /api/*      /api/public/*   /admin/*
        ▼
pk-server (Rust, axum, :8787)
  ├─ grouping.rs      分组 API（pk-core 权威算法）
  ├─ public.rs        对外只读展示（裁剪字段 + 实时音浪）
  ├─ routes.rs        方案 / 名单 / 数据源管理
  ├─ admin.rs         数据管理 API（/api/admin/*）：导入 / 主播台账 / 采集
  ├─ bot/             机器人：QQ / 微信 iLink，确定性命令路由
  ├─ import/          CSV / 补录，字段映射 + 校验报告
  ├─ dialect.rs       SQL 方言 + 只读守卫（查询走 pk_reader）
  ├─ mysql.rs         多数据源连接池（读池 + 写池分账号隔离）
  └─ store.rs         运行时表（plans / aliases / roster / my_accounts …），
                      2026-10-10 单库化并入 MySQL（旧 SQLite 只作搬家来源留底）
        │
        └── MariaDB/MySQL(douyin)  douyin_writer 写 / pk_reader 只读（唯一事实源）
```

## 3. 数据模型

主库 `douyin` 沿用源库 `douyinxs` 的核心表（S1 已迁移对齐）：

```sql
person           主播：name / gender / master_id / generation / group_name / status / deleted_at
account          抖音号：person_id / anchor_id / douyin_no / is_primary
daily_metric     日音浪：person_id / biz_date / wave / cumulative_wave / wave_reliable / is_live
monthly_metric   月音浪：period / wave / live_days / best_day_wave
wave_snapshot    账号级累计音浪快照（补充副号数据）
duration_snapshot 账号级直播时长观测
import_batch     导入来源、业务日期、团别、行数和结果审计
```

> 完整实体定义以 `docs/00-统一产品与系统架构.md` §4 为准。

运行时状态表（`plans` / `aliases` / `roster` 等）**已并入 MySQL 业务库**
（2026-10-10 单库化，migrations/003_runtime.sql），与业务指标同库；旧 SQLite 文件
只作一次性搬家来源留底（`pk-server migrate` 幂等搬入）：

```sql
plans       分组方案快照 + 上架状态 + 展示配置
aliases     主播别名映射（如 阿楠 → 南方楠）
roster      名单草稿（刷新页面不丢）
```

## 4. 账号与权限

| 账号 | 权限 | 用途 |
|---|---|---|
| `douyin_writer` | 业务表 `SELECT / INSERT / UPDATE / DELETE` | 导入、采集、管理写入；**不持有 DDL** |
| `douyin_migrator` | 受控 DDL + 业务表写 | 仅显式迁移窗口使用（`pk-server migrate` 子命令，不随启动自动执行；见 docs/00 §4） |
| `pk_reader` | `SELECT` | 分组、展示、榜单查询 |
| `douyin_migrator` | `DDL + 上述` | 仅 migration 使用，启动后可不保留 |

查询路径（`pk_reader`）与写入路径（`douyin_writer`）在进程内分池；
查询 SQL 集中在 `dialect.rs`，执行前拦截非 `SELECT / SHOW`。

## 5. 接口分类

| 前缀 | 鉴权 | 用途 |
|---|---|---|
| `/api/public/*` | 免 | 对外展示：方案、榜单、公告 |
| `/api/auth/*` | 免（登录）/ 口令 | token 换发、会话校验 |
| `/api/*` | 口令 | 分组、方案、名单、数据源管理 |
| `/api/admin/*` | 口令 | 数据管理：导入、主播台账、采集状态、机器人 |
| `/admin/*` | 口令 | 管理端 SPA（apps/douyin-web，history 路由） |

## 6. 机器人

`bot/` 模块化，两个渠道实现同一个 `Channel` trait：

```rust
trait Channel {
    async fn send(&self, text: String) -> Result<()>;
    async fn poll(&self) -> Result<Vec<Inbound>>;
}
```

- 命令路由**确定性**，不调用任何模型：`help / query / rank / group / import`
- 命令表可热更新，无需重启渠道进程
- 会话状态持久化到 MySQL `bot_sessions`（单库化后），断线重连可恢复
- 只有管理员会话能触发写类命令（导入 / 导出），粉丝侧只有展示页一条通路

## 7. 采集与导入

`import/` 分三步，步步可回退：

1. **上传 / 粘贴**：Excel、文本、指定日期补录
2. **字段映射预览**：源列 → 目标字段，确认后才入库
3. **校验报告**：匹配不上标红 + 候选下拉一键绑定；无候选入待处理名单

采集链路（`collect/`）对接 DouyinLang 推 API，写入 `daily_metric`，
`import_source` 记录来源；漏采告警（`wave_span > 1`）进微信群。

## 8. 部署

单镜像 `pk-server`（Rust 静态，约 15MB 级），Compose 只跑它 + MariaDB + 宿主 Nginx。

```text
Nginx :80
 ├─ /s/*   → 127.0.0.1:8787
 ├─ /admin/* → 127.0.0.1:8787
 └─ /*     → 127.0.0.1:8787
MariaDB :3306
 pk-server（douyin_writer 写 / pk_reader 只读）
```

> 部署目标以 RK3318（aarch64 Docker，/opt/pk-server）为准；amd64 镜像仅用于 115
> 开发机（x86_64），不是生产路径。宿主端口发布一律绑 127.0.0.1（见
> deploy/docker-compose.yml 内注释），公网入口走 Nginx/Caddy 反代。

镜像由 GitHub Actions 多阶段交叉编译，只出两个目标：**arm64 对应 RK3318 生产盒子**、
**amd64 对应 115 开发机**（x86_64 / CentOS 7）；离线包 `docker load` 即用，不发布到镜像仓库、不部署其他服务器。

## 10. 与 v1 的差异

| 项 | v1（Go + Rust） | v2（Rust 单栈） |
|---|---|---|
| 运行时 | Go 1.27 + Rust | Rust 单进程 |
| 后端服务 | `douyin-server` + `pk-server` | 只有一个 `pk-server` |
| 镜像 | 2 个 | 1 个 |
| 写库 | Go 独占 | `pk-server` 内分账号（读 / 写分池） |
| 契约 | Go/Rust/TS 三端 | Rust / TS 两端 |
