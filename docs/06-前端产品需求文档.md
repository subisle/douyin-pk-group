# 06 · 前端产品需求文档（PRD）

> ⚠️ 2026-10-02 修订：后端已统一为 Rust 单技术栈（`pk-server`）。
> 「抖音数据管理」不再单独跑 Go 服务，其数据管理 / 机器人职责由同一个 `pk-server`
> 的 `admin.rs` / `bot/` 模块承载，前端调用路径不变（`/dy/*` 仍由 `pk-server` 转发）。
> 本 PRD 聚焦前端产品需求，接口实现见 `docs/07-后端需求文档.md`。

> 整合范围：**抖音数据管理**（原 Electron + Next.js 独立应用的职责，现并入本仓库由
> Rust `pk-server` 承载）× **PK 分组程序**（React Web + Rust，本仓库）。
> 两者融合为同一套 Web 后台：统一管理 SPA 落在 `apps/douyin-web`（见 docs/00 §2/§7），
> 不再保留桌面 App 形态。本文目标是先收敛出一份统一的前端产品需求，
> **本期不写代码**，只定范围、页面、模块与验收口径。

---

## 1. 目标用户

| 角色 | 谁在用 | 用什么页面 |
| --- | --- | --- |
| **运营管理员**（唯一管理角色，单团队内部使用） | 公会/传媒运营，负责录数据、分组、发公告 | 设置、数据、主播管理、导入数据、机器人配置 |
| **主播** | 参赛/在管主播，关心自己的每日音浪和分组 | 对外展示页（免登录） |
| **粉丝/观众** | 主播粉丝群成员 | 对外展示页（免登录，只看链接，不接触机器人） |

不需要多角色权限体系，一期只区分「后台（需口令）」和「对外展示（免登录）」两层。

## 2. 核心使用场景

1. **日常录数**：运营每天把采集到的音浪数据导入系统（Excel/粘贴/数据库同步），核对主播名单是否对齐。
2. **主播台账**：新签主播建档、别名映射、退赛排除，保证任何一次分组和榜单里名字都能匹配上。
3. **机器人导入导出**：机器人是**内部工具，只有管理员使用，没有粉丝侧命令**。运营在手机上直接把 Excel/数据文本发给 QQ 或微信机器人即可完成导入，也可以让机器人把指定日期的数据导出发回来——人不在电脑前也能录数、取数。
4. **赛前分组**：运营粘贴参赛名单 → 均衡分组 → 微调锁定 → 保存方案。
5. **对外公告**：把「每日音浪榜」和「PK 分组」发布到展示页，群里只发一个链接；运营可控制**每日数据展示不展示、分组展示不展示**。

> 对外粉丝侧只有展示页一条通路，机器人不承担粉丝查询职责。

## 4. 每个页面的模块结构

### 4.1 数据页 `/admin/data`

| 模块 | 需求说明 |
| --- | --- |
| 概况条（原「数据概况」） | 统计日期、当日总音浪、男团/女团、开播/在册 + 日报 SVG 入口——原来是独立导航项，现已并入本页 |
| 音浪 Top N | 当日音浪前 10：主播、团别、当日音浪、分钟 |
| 未播预警 | 连续 ≥2 天未播名单（窗口内从未开播单独标注） |
| 团别趋势 | 近 N 天男团 / 女团 / 合计音浪趋势表（窗口 7/14/30/90 可选） |
| 每日榜单 | **支持选择日期，默认最新日期**；每行：名次、主播、当日音浪、开播/未开播状态、距前一天增量 |
| 团别筛选 | **男团 / 女团 / 全部** 分段切换；音浪数据分男女团维护与排名，榜单默认按团分开 |
| 口径切换 | 总音浪 / 近 N 天（沿用现有 total / lastN） |
| 排序与检索 | 音浪高→低 / 低→高 / 名字；320ms 防抖检索 |
| CSV 导出 | 当前口径 + 当前日期的数据一键导出 |
| 强制刷新 | 绕过 10 分钟缓存重新拉数 |

### 4.2 主播管理 `/admin/streamers`

| 模块 | 需求说明 |
| --- | --- |
| 主播列表 | 名字、**抖音号（唯一，展示端「我的」身份验证凭据）**、别名、师傅/队长、**团别（男团/女团）**、分组状态（参赛/排除）、最近数据日期 |
| 新建/编辑主播 | 名字（必填）、**抖音号（必填、唯一，重复时行内红字提示）**、**团别（必填，男团/女团）**、别名映射（一对多，如 阿楠→南方楠）、师傅标注、备注 |
| 排除名单管理 | 维护不参赛名单（现有规则：默认排除「目」） |
| 别名冲突检查 | 保存时检测别名与既有主播名冲突，行内红字提示 |
| 批量操作 | 多选 → 批量排除 / 批量清别名 |
| 检索 | 按名字/别名模糊搜 |

### 4.3 导入数据 `/admin/import`

| 模块 | 需求说明 |
| --- | --- |
| 导入方式 | **只认文件，整页只有一个投放区**：把文件拖到投放区，或点投放区选文件（隐藏 `input[type=file]`，键盘 Enter / Space 也能打开）；拖入时投放区实线高亮、文案变「松手就开始解析」。**粘贴入口已下线**——运营一律用导出的数据文件，手抄文本容易错 |
| 预览弹窗 | 松手 / 选完文件**自动**解析并弹窗（不用再点一次「解析」）：逐行结果（名字 / 当日音浪 / 累计音浪 / 分钟 / 开播 / 抖音号）+ 团别、业务日期、模式；确认才入库，Esc 或点遮罩取消 |
| 文件名推断 | 文件名带日期和团别（`2026-10-07-男团.csv`）自动填好归属，不用手选；**日期取自文件名时弹窗标注「（取自文件名）」**，不带日期默认「收到日 − 1」 |
| 重复导入 | 同一天同一个文件再导一次：**音浪值与库里完全相同 → 一行都不覆盖**（报告显示「♻️ 另有 N 行音浪值与库里完全相同，未覆盖」）；**值变了才覆盖**，且只覆盖变化的那几行 |
| 校验报告 | 匹配不上的主播名与原因逐条列出；没数据的主播按「该团当天还有 N 人没有数据」提示 |
| 日期归属 | 每次导入必须归属到一个业务日期：**默认「收到日 − 1」**（数据半夜才更新，10 号收到的文件是 9 号的数据）；文件名里带了日期就按文件名走（补录旧数据），弹窗里会标出日期来源 |
| 团别归属 | 按**男团、女团分开导入**；与主播档案的团别冲突时报错 |
| 当日状态 | 选好日期 + 团别就查该日已有行数：无数据 = 新增，已有 = 「覆盖（幂等）」或「当日已有则拒绝」按模式提示；**入库后自动重查**，删除按钮立刻可用 |
| 导入历史 | 最近导入记录：时间、日期、条数、成功/失败数、备注 |
| 删除当天 | 按业务日期 + 团别删除已入库音浪与对应批次（导入错了先删再重导） |
| 失败重试 | 失败批次可整批重导或单条修正后重试 |

### 4.4 机器人配置 `/admin/bots`（QQ + 微信合一页，纯内部工具）

机器人定位：**只有管理员使用，用于数据的导入与导出；不做粉丝查询、不响应群友命令。**
两个渠道（QQ、微信）能力对齐，QQ 同样支持导入导出，不因渠道而异。

| 模块 | 需求说明 |
| --- | --- |
| 渠道总览 | 两张渠道卡：QQ 机器人 / 微信机器人，各自状态徽标（在线/掉线/未配置）+ 最近心跳时间 |
| QQ 机器人配置 | 账号接入方式、绑定管理员会话（只认管理员发的消息）、监听范围 |
| 微信机器人配置 | 登录状态（扫码/掉线重连入口）、绑定管理员会话、监听范围 |
| **统一命令面板** | 两渠道共用同一份管理员命令表（见下）：可改命令词、开关单条命令、配置确认/报错回复模板 |
| 导入规则 | 管理员发 Excel 或规定格式的文本 → 机器人走与 `/admin/import` 页相同的校验（解析/匹配/日期归属），失败时把校验报告作为消息回发 |
| 导出规则 | 管理员按命令导出指定日期/口径的数据，机器人回发 Excel 文件（列与 CSV 导出一致） |
| 推送规则 | 赛程公布、每日榜更新、分组变更时自动推送给管理员（每渠道独立开关） |
| 消息日志 | 最近 N 条机器人收发记录与处理结果（成功条数/失败原因），便于排查 |

**统一管理员命令（初版口径，QQ 与微信行为完全一致，仅管理员会话生效）：**

| 命令 | 功能 |
| --- | --- |
| 发送 Excel/数据文本 | 直接触发导入，回复导入结果（成功条数 / 标红名单 / 待绑定清单） |
| `导出 今日` / `导出 10-01` | 导出指定日期的每日数据，回发 Excel |
| `导出 总榜` | 导出当前口径的总音浪数据 |
| `导出 分组` | 导出当前方案的分组名单 |
| `状态` | 回数据新鲜度、最新采集日期、机器人连接状态 |
| `帮助` | 列出可用命令 |
| 非管理员会话的消息 | **一律静默忽略**（不回复、不刷屏），日志留痕 |

保持现有能力不变（名单解析、拖拽、锁定、撤销重做、均衡微调、自动修正、增补、全局找人、紧凑模式、导出长图、历史方案），本期只补两点：

- 方案卡片增加「**展示开关**」：控制该方案的分组是否出现在对外展示页（对应 4.6）。
- 解析名单时自动复用主播管理的别名库，无需重复维护。

### 4.6 对外展示 `/s/:planId`、`/st`

在现有三视图（每日音浪 / PK 分组 / 总音浪）基础上增强：

| 模块 | 需求说明 |
| --- | --- |
| **每日数据展示开关** | 后台可整体开关「每日音浪榜」；关闭后展示页不渲染该分页（后端同时不下发数字，不是前端藏） |
| **分组展示开关** | 每个方案独立的上架/下架（已有），另加「分组名单展示」开关：关掉后页面只显示赛程时段，不显示具体名单（用于赛前预热） |

## 5. 视觉风格关键词

沿用 PK 分组项目已落地的 design tokens（`apps/web/src/index.css`），两个项目合并后一套皮肤：

- **冷灰纸面**：#f7f8fa 画布 + 顶部轻渐晕，面板白卡、不发死白；
- **靛蓝品牌色**：#4f46e5 单一主色（导航、按钮、焦点环、选中文字），拒绝紫蓝/青色渐变「AI 味」；
- **发丝线表格**：淡分隔线 + 11px 大写字距表头 + 行 hover 整行点亮；
- **三档阴影**：raise（卡片）/ float（弹层）/ bar（吸顶），不随手加第四档；
- **语义色四件套**：绿=正常在线、橙=降级/超员/掉线预警、红=错误/匹配失败、蓝=提示；
- **数字等宽**：所有音浪数值 tabular-nums，重算不跳动；
- **展示端苹果风**：深色头部（顶光 ≤6% + 颗粒）、发丝分隔名单行、胶囊赛程条；
- **系统字体栈**，零外部字体请求。

## 6. 交互要点

- 导航：顶栏吸顶毛玻璃 + 品牌色 2px 指示条，**history 路由**（`/admin/*`）保证刷新/分享/前进后退不丢页；导航项是真链接，可复制、可中键新开标签。
- 表格通用：粘性表头、行 hover、列排序点击切换方向。
- 导入流：上传文件 → **弹窗预览**（逐行结果 + 日期/团别/模式）→ 确认入库 → 报告 + 批次列表；Esc / 点遮罩取消，入库前后都能一键删除当天数据重来。
- 机器人命令修改后**热生效**（worker 重载命令表），无需重启渠道进程；QQ / 微信两端同一套命令实现，改一处两边生效。
- 看板快捷键：`Cmd/Ctrl+Z` 撤销、`Cmd/Ctrl+Shift+Z` 重做，输入框聚焦时不劫持。
- 所有破坏性操作（删主播、删方案、下架）需二次确认弹层。
- 错误文案一律翻译成人话 + 下一步动作（沿用现有 `reasonOf` 翻译规则：401 指路重新登录、网络错误指路检查服务）。

## 7. 空状态

| 位置 | 表现 |
| --- | --- |
| 数据页无任何数据 | 「还没有采集到任何日期」+ 去导入按钮，不显示假进度 |
| 检索无结果 | 「没有匹配的主播，换个词试试」+ 清空按钮 |
| 主播列表为空 | 引导卡：先建主播或先跑一次导入 |
| 导入历史为空 | 「还没有导入记录」 |
| 机器人未配置 | 渠道卡显示「未配置」+ 配置引导，不显示报错红字 |
| 消息日志为空 | 「机器人还没有收发过消息」 |
| 展示页方案未上架/被关 | 明确的「暂未公布」占位页，不是 404 |
| 展示页分组被隐藏 | 只显示赛程时段，不出现空洞名单区 |

## 8. 加载状态

- 按钮级 loading（导入、导出、刷新转圈），不做全屏 spinner。
- 表格首屏行骨架；榜单切日期时旧行保持 + 轻微降透明度，不闪空白。
- 展示页每分钟静默刷新不动 UI；只有强制刷新才显式 loading。
- 机器人登录/重连过程显示进度态（等待扫码 → 已扫码 → 已连接）。
- 后端不可用：后台页给横幅提示「服务暂不可用」；展示页自动降级快照 + stale 徽标。
