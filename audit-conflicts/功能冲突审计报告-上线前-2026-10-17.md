## P1-1 · 头像同步「默认手动」了，但手动按钮根本没做 → 头像永远不更新

**位置**
- 承诺方：`docs/10-当前功能清单.md:94`、`docs/19-功能与页面文档.md:97`、`:212`、`:256`、`docs/25-展示端抖音头像.md:149`、`:373`
- 实现方：`rust/crates/pk-server/src/main.rs:235`（定时器开关）、`apps/douyin-web/src/StreamerPage.tsx`（主播管理页）

**冲突描述**
2026-10-16 二期把头像更新改成「默认手动」：定时器默认**关闭**
（`AVATAR_SYNC_ENABLED` 默认 0，`main.rs:235` 确认 `if config::avatar_sync_enabled()` 才 spawn），
手动路径文档写了两条：① 管理后台「主播管理」页同步按钮 `POST /api/admin/avatars/sync`；② CLI `sync-avatars`。

实际情况：
- 后端 `/api/admin/avatars/sync` **已注册**（`main.rs` 路由表确认存在）；
- 前端**完全没有调用它** —— 全量 grep `apps/douyin-web/src/` 无 `avatars/sync`，
  `StreamerPage.tsx` 里只有头像**显示**逻辑（`avatarHash` → `/api/public/avatars/{personId}?v={hash}`），
  没有任何同步按钮。

**上线后具体表现**：两条手动路径只剩 CLI 一条（还得登上服务器跑）。运营在后台**找不到任何刷新头像的入口**，
自动定时器又默认关 —— 新人入职登记了抖音号，头像**永远不会出现**，一直回落姓名首字色块。
运营会反馈「头像功能坏了」，实际是入口没做。

**严重度**：P1（功能凭空消失 + 文档与实现对不上；不涉及数据错误，但上线后运营一定来问）

**证据**
```rust
// rust/crates/pk-server/src/main.rs:235 —— 定时器默认关
if config::avatar_sync_enabled() {
    ... avatar_sync::spawn_scheduler(pool, days, every);
} else {
    tracing::info!("AVATAR_SYNC_ENABLED=0：主播头像自动刷新已关闭（默认纯手动…）");
}
```
```
$ grep -rn "avatars/sync" apps/douyin-web/src/
（无输出 —— 前端从未调用）
```

**建议**：二选一，别留空档 ——
(a) 「主播管理」页加一个同步按钮调 `POST /api/admin/avatars/sync`（文档已经这么承诺了，补上最省事）；
(b) 或者把 `AVATAR_SYNC_ENABLED` 默认改回 1（但要注意首次上线会有一波抖音请求）。
若暂时不动，请在 docs/10、19、25 里把「页内同步按钮」这句改掉，别让文档骗人。

## P1-2 · 一批后端接口存在但前端没有任何入口（能力在，运营够不着）

**位置**：`rust/crates/pk-server/src/main.rs:510/537/563/564/639` 等 vs `apps/douyin-web/src/`

**冲突描述**
机械比对「后端注册的 `/api/admin/*` 路由」与「前端实际调用」，以下接口后端有、前端**零调用**：

| 接口 | 作用 | 前端入口 |
|---|---|---|
| `POST /api/admin/avatars/sync` | 手动同步抖音头像 | ❌ 无（见 P1-1） |
| `GET /api/admin/push/jobs` | 推送任务队列查看 | ❌ 无 |
| `POST /api/admin/push/run` | **立即推送** | ❌ 无 |
| `GET /api/admin/collect/status` | 数据源采集状态 | ❌ 无 |
| `GET /api/admin/metrics/monthly` / `yearly` | 月/年指标 | ❌ 无 |
| `GET /api/admin/import/pending` | 导入暂存区 | ❌ 无 |

其中 `docs/10` 明确把「**立即推送**」「数据入库延迟推送队列」列为已上线功能（§2.6）。

**上线后具体表现**：运营想「立刻推一次今天的日报」或「看看推送队列卡在哪」时，后台**没有对应按钮**，
只能靠人登服务器 curl。特别是**推送出问题时排查不了** —— 队列里有几个 job、失败原因是什么，界面上一律看不到。

**严重度**：P1（可运维性差；上线后推送一旦出问题，排查路径只剩登服务器）

**证据**
```
$ comm -13 <前端调用> <后端注册>   # 后端有、前端没用
/api/admin/avatars/sync
/api/admin/push/jobs
/api/admin/push/run
/api/admin/collect/status
/api/admin/metrics/monthly
/api/admin/metrics/yearly
/api/admin/import/pending
```

**建议**：优先级排序 —— `push/jobs` + `push/run` 建议补进「机器人」页（上线后排查推送全靠它）；
`avatars/sync` 见 P1-1；其余可记为 backlog。
**或者**在 docs/10 里把这些改标为「后端已实现，无 UI」，别让清单继续宣称「已上线」。

## P2-1 · 机器人页三路刷新叠加（SSE + 20s 轮询 + 60s 轮询）

**位置**：`apps/douyin-web/src/BotPage.tsx:99`、`:126`、`:131`

**冲突描述**
`BotPage` 同时挂着：`useAutoRefresh(load, ['bot','import'])`（SSE 变更驱动）+
`setInterval(load, 20000)`（20 秒定时）+ `setInterval(loadLineageBind, 60000)`（60 秒定时），
另有一个扫码轮询 `setInterval`（`:222`）。三条路径都调同一个 `load`，互相不知道对方刚拉过。

**上线后具体表现**：机器人页保持打开时，后台每 20 秒必发一次请求，SSE 变更时再叠一次 ——
不是错误，属于请求冗余。管理端只有少数人用，影响可控。

**严重度**：P2

**建议**：留 SSE + 一个兜底轮询即可，或给 `load` 加最小间隔节流。

## P2-2 · QQ 渠道「无条件 Admin」与文档/环境变量口径不一致

**位置**：`rust/crates/pk-server/src/bot/mod.rs:823-828`

**冲突描述**
代码注释明确写着：QQ 是**无条件** Admin，**不看** `cfg.qq_admins`，
并特别说明「那个环境变量当前对 QQ 不生效，配了也不会生效」：

```rust
// QQ 是**无条件** Admin：不看 cfg.qq_admins。…
// BOT_QQ_ADMINS——那个环境变量当前对 QQ 不生效，配了也不会生效。
let role = if inbound.channel == "qq"
    || cfg.wechat_admins.contains(&inbound.conversation_id)
    || crate::store::session_is_admin(...).await
```

而 `config.rs` 里 `qq_admins: list("BOT_QQ_ADMINS")` 仍然在读这个环境变量，
`deploy/*.example` 里若配了 `BOT_QQ_ADMINS`，运营会以为配了就生效。

**上线后具体表现**：不产生错误（QQ 号由运营自持，实际就是全 Admin），
但**配置项是死的** —— 一旦将来有人往 QQ 群里放非管理员，或反过来指望配 `BOT_QQ_ADMINS` 收口，就会落空。

**严重度**：P2（现状安全，属于「配置骗人」，上线前建议至少在 `.env.example` 注明该变量对 QQ 无效）
