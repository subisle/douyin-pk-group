## 二、P0 修复（5 条）

### P0-1 · 师门日报「本月累计」没接整月音浪 → 与月榜差一截
- 位置：`lineage_report.rs`（`build()` 的 `month_sql`）
- 原状：裸 `SUM(daily_metric.wave)`；而月榜图/个人卡/推送 caption 早已改成整月优先
- 修法：复用 `report::month_wave_sql`（同一份 COALESCE 口径）+ `query_month_wave_fallback` 缺表降级
- 影响：导入整月音浪后，师傅收到的图里「本月累计」不再比其他地方少

### P0-2 · 「我的抖音号」分号卡月/年是纯日明细 → 与同页月卡自相矛盾
- 位置：`public_teams/minutes.rs::my_accounts_sql`、`push.rs::account_waves_sql`
- 原状：完全没有 `monthly_wave`；`/my` 月卡却走整月优先 → 同一台手机两卡数字不同
- 修法：主号那一支的月/年改整月优先（整月值是**人**粒度，只归主号，副号仍走 `wave_snapshot`），
  日明细侧排掉「该月已导整月值」的行 → 两处不双算
- 影响：「音浪对比」卡与「我的抖音号」卡月/年数字对齐

### P0-3 · 主播改名后三张表集体失联（改名是台账日常操作）
- 位置：`admin.rs::update_streamer`
- 原状：只 `UPDATE person SET name=?` 就返回 ok。`my_accounts` / `push_bindings` /
  `my_targets` / `wx_push_accounts` 四张表都以 **name** 关联 → 静默打断登录、微信推送、追分目标
- 修法：改名成功后同步改四张表的 name，并吊销旧 my token（与「改团别必吊销」的既有纪律一致）
- 注意：旧名必须在 UPDATE **之前**取，否则读到的已是新名

### P0-4 · `/wechat` 深链被鉴权拦成 401 JSON
- 位置：`auth.rs::OPEN_PREFIXES`
- 原状：`main.rs` 把 `/wechat` 注册成公开页路由，但白名单里漏了它 →
  主播点运营发来的链接看到一行 `{"error":"需要管理员口令"}`、页面空白。
  规范路径 `/my/wechat`（在 `/my/` 前缀内）一直是好的，只有这条短链挂了
- 修法：加精确路径 `"/wechat"`（不用 `starts_with`，避免 `/wechat-xxx` 被顺带放过）

### P0-5 · 出网闸门拦截被当成成功 → 消息永久丢失
- 位置：`push.rs::send_binding` / `send_binding_images`
- 原状：拦截后 `return Ok(())` → 调用方立刻推进去重标记
  （`last_report_date` / `last_lineage_date` / `last_notice_date`）并落终态 done。
  关闸期间本该发的消息被**永久吞掉**：标记已消耗，开闸当天也不重推，日志却全是 INFO「已推送」
- 修法：新增 `Blocked` 哨兵 + `is_blocked()`；拦截时不写去重标记、不记失败原因、
  图片被拦不再空跑退回文本重试
- 单测 `push::tests::blocked_is_distinguishable_from_success` 守住（含 anyhow 包一层也能认出）

## 四、P2 修复（15 条）

- 机器人帮助：管理员版标注「用户命令要本会话绑过推送才有效」
- 附件导入：团别按「消息文本 > 文件名 > auto」三级取（原先静默丢弃）
- 师门日报手动下发后写同日去重标记（避免定时+手动双发）
- 管理员下发/提权后广播 SSE（机器人页、消息下发页自动刷新）
- 限流文案带上实际生效上限（不再写死「10 条/分钟」）
- ip-allowlist：新增 `gateDisabled` / `mode`，前端不再把「表非空」渲染成白名单模式
- `gate_disabled` 布尔取值放宽（trim+小写，`TRUE` 生效）
- QQ 管理员：`BOT_QQ_ADMINS` 真正生效（配了按白名单收口，没配保持原行为）
- 展板配置写失败不再假成功（`config_set_result` 返回 Result）
- 策略白名单由 `pk_core::Strategy` 派生 + 单测钉死（三份手写清单 → 单一来源）
- `BREAK_AFTER_GROUP` / `REVIVAL_EVENTS` 两份拷贝 → 统一从 `rules.ts` 导出
- 管理端导入完成文案「75 小时29分」→ 复用 `push::fmt_minutes` 成「75时29分」（与展示端/机器人同口径）
- `seat-options` 的 period 补 `%` 通配（原先裸 period，年窗口会命中 0 行，与月榜分叉）
- 追分对手过滤：`MONTH_WAVE_MAP_SQL`（含 daily 版）补 `status <> 'left' AND hide_in_daily_report = 0`，
  与 `MONTH_RANK_SQL` 同口径（原先离团/隐藏的对手有音浪却查不到名次）
- 月榜末列表头「累计总音浪」→「本月累计（总）」（月榜该列其实是本月累计，同表头不同义）
- 师门日报「有徒弟」判定放宽为**只要求名下有徒弟**（原先还要本人是开山师傅，
  与推送侧/一键开启不一致 → 中间层师傅被开了却没开关可关）
- `push_stats.enabled` 补第三列 `lineage_report`，与推送引擎取人口径一致（原先统计偏低）
- 删除 `push_jobs::target_count` / `target_add` 两个旧口径死函数（无事务无判重无上限，
  留着会被误调用绕过分类上限）

   但 `docker-compose.prod.yml` 的默认值是 `${PUSH_OUT_ENABLED:-0}`（安全侧）——
   **上线前请确认 `.env.prod` 里到底写 1 还是 0**。

   sequential / sequential-last-n / random），但 docs/10、docs/11 都写了它。

3. **饭团这个账号在库里和种子名册里都不存在**（只在注释与推送白名单文案里出现）。
   她若要以「只看女团」身份登录，需管理员建 `is_admin=1` + `view_team=female` 的账号。
